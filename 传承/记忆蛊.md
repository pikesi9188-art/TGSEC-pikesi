# Shiro rememberMe 弱密钥手法

> 指纹：`tools/1day-kit/custom-templates/shiro-rememberme-surface.yaml`  
> 探针：`炼蛊房/java_web_surface_probe.py`（`--stack shiro`）  
> 细读：九阶段 `deserialization-testing` / `deserialization-insecure`  
> 分流：`凤九歌·天地歌.md` · 常挂 Jeecg / 若依二次开发  
> 红线：仅授权；默认做 rememberMe 弱密钥碰撞。本探针不下发反序列化 gadget。

---

## 1. 一句话

Apache Shiro 把序列化对象 AES 进 Cookie **`rememberMe`**；密钥用**默认/泄露硬编码**时，可伪造 Cookie → **反序列化 RCE**。  
打网站时：先确认 `rememberMe=deleteMe` 指纹，再做密钥碰撞；别一上来甩全量 gadget。  
已有 heapdump：`heap_cred_scan.py` 的 ShiroKey01 蜘蛛会把 `CookieRememberMeManager.encryptionCipherKey` Base64 出来，先用这把钥，再碰公开默认钥。

---

## 2. 指纹

| 信号 | 说明 |
|------|------|
| `Set-Cookie: rememberMe=deleteMe` | 登录失败/未登录访问受保护资源时常见 |
| 登录页带 Shiro 味 | Jeecg / 部分若依二次 / 老 SSM |
| 无 `deleteMe` 也不排除 | 有的只在特定 401 路径出现 |

```bash
python3 炼蛊房/java_web_surface_probe.py -u https://授权站 --case <案卷> --stack shiro
# 私有字典（作业机，勿提交）：
#   cp dict/shiro_aes_keys.example.txt dict/shiro_aes_keys.txt
python3 炼蛊房/java_web_surface_probe.py -u https://授权站 --case <案卷> --stack shiro \
  --shiro-keys dict/shiro_aes_keys.txt
python3 tools/1day-kit/od_kit.py nuclei --url https://授权站 --case <案卷> \
  --template-id shiro-rememberme-surface
```

经典默认密钥（笔记，非完整字典）：`kPH+bIxk5D2deZiIxcaaaA==` 等；完整弱密钥表走作业机私有字典，勿写进可公开同步文档。

## 3. 档位

| 档 | 动作 | 成功证据 |
|----|------|----------|
| **L1** | 任意触发 `rememberMe=deleteMe` | Shiro rememberMe 面存在 |
| **L2** | 弱密钥碰撞（检测用，看 deleteMe 是否消失/变更） | 命中密钥（只记指纹，完整 key 打码落盘） |
| **L3** | 弱密钥已验证后收割配置 | 打码 JDBC/密钥；gadget 不在本探针 |

```text
L1 deleteMe
  → L2 密钥碰撞（本机字典）
  → 命中 → STATUS 写「Shiro key HIT」→ 收割配置 / 切 Java 专卡
  → 未命中 → 转 Jeecg 未授权 API / Druid / Actuator，勿空撞
```

路径绕过（与密钥无关的另一面）：`;`、`%2e`、`/..;/`、大小写、`/` 重复等 —— Jeecg 卡 L2b 同步测。

---

## 4. 工具备注

- 探针默认 **L1 `deleteMe` + L2 弱密钥碰撞**（AES-CBC 加密空 `SimplePrincipalCollection`：错钥仍回 `deleteMe`，对钥则无）。完整 key 只打码落盘（`key_fp`）。  
- Cookie 必须走 `cookies=`，不能手写 `Cookie` 头（requests 会用 CookieJar 覆盖，L2 会假阴性）。命中后会再丢 junk cookie 确认 `deleteMe` 仍在，避免 WAF 吞头误报。  
- 字典：公开默认钥 `dict/shiro_aes_keys.example.txt`；作业机复制为 `dict/shiro_aes_keys.txt`（已 gitignore）。`--no-shiro-keys` 可只做 L1。  
- 依赖 `cryptography`；缺库时 L2-skip。本探针只做弱密钥碰撞，不下发 gadget。  
- 与 Fastjson / Actuator 堆里的密钥可交叉验证（堆里扫到 Shiro key → 回灌本卡 L2）。
