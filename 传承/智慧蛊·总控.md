## 3. 六门验证闸（进报告前全过）

| 闸 | 问 | 过闸证据 |
|----|----|----------|
| G1 可复现 | 同一条件能再打出？ | 命令 + 参数 + 时间 |
| G2 有包 | HTTP/WS/日志留下了？ | 请求/响应或 `aks_oob.log` 一类原件 |
| G3 影响实锤 | 读到/写到/执行到，不是「可能」 | 回显、对象、文件、会话 |
| G4 在范围内 | host 在 `scope*.json`？ | `--grant` 记录或 in_scope |
| G5 真洞 | 不是版本号碰 CVE、不是 banner | sink 可达或鉴权失效 |
| G6 可独立复现 | 换人按 STATUS 能复做？ | 案卷路径写死 |

全过 → `VALIDATED` 进 `案卷/findings.md`。缺一门 → `NEEDS-WORK`。G4/G5 失败 → `REJECTED`。

**负对照**：注入/延时至少跑一次无 payload。对照失败，不报阳性。

**版本 ≠ 漏洞**：nuclei/组件版本只是线索。没证明入口到 sink，写「嫌疑」不写洞。

## 4. 先问 vs 直接做

| 直接做（授权内本库已有命令） | 先问 |
|------------------------------|------|
| 弱口、信任头、未授权读、假支付验签、heapdump、GVA 伪造票只读、目录猎杀、RCE、写马、反弹 | 耗余额下单 |
| strike / sqlmap / Redis 读 captcha / PMA 短字典 | 删站 / 清数据 |
| 主站链发现的支付中转域 `scope_expand` | 改原超管密码 / 覆盖生产配置 |

Skill 里写「不落马 / 反弹先问」与本表冲突时，以本表为准。

## 5. 断点续跑

每个阶段写盘后再切下一阶段。重开对话先读 `STATUS.md`，已完成的阶段不重打。

| 阶段 | 落盘 |
|------|------|
| 授权/定级 | `STATUS.md` 头部 |
| 指纹/栈 | `案卷/tech-stack.md` |
| 身份 | `案卷/object_matrix.md` |
| 发现 | `案卷/findings.md`（只写过闸项） |
| 覆盖 | `案卷/coverage.md`（已测未发现也写） |
| 接管/支付 | `接管/` · `支付/` |

专卡阴性 **必须回矩阵换格子**，禁止直接写复工结案。

## 7. 失败处理

| 现象 | 不要 | 要 |
|------|------|----|
| 专卡全阴 | 结案 | `object_matrix.py next` 换对象/他人/写 |
| 工具缺依赖 | 当阴性 | 记 `coverage.md`「未测：缺工具」 |
| WAF 拦 | 只报有 WAF | `evasion-kit` / 换出口 `proxy-nodes.txt` |
| 本机 IP 被封 | SSH 用户主机当跳板 | `狼烟.md` |
| 范围歧义 | 猜着打 | 停，问用户或 `--grant` |
