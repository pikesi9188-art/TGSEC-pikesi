# Zimbra SNMP 命令注入手法（CVE-2026-73570）

> Skill：`杀招/信巢`  
> 情报：`od_kit.py cvebase lookup --cve CVE-2026-73570 --docs`  
> 指纹：`tools/1day-kit/custom-templates/zimbra-snmp-cve-2026-73570.yaml`  
> 总览：`CVE日报-2026-08-22.md`  
> 红线：仅授权目标；默认只 HTTP 指纹+版本；无公开 PoC 禁止自造 SMTP payload

---

## 0. 画像

Zimbra Collaboration（ZCS）在装了可选 **`zimbra-snmp`**、开启 **SNMP 通知**、且 **`swatchdog` 在跑** 时，未认证 SMTP 输入进通知处理，可命令注入，以 **`zimbra` 用户**执行（非自动 root）。  
KEV 2026-08-21 · CERT Polska 08-17 报在野 · 无公开 PoC。修：`10.1.20+`。

成功口径：确认 Zimbra 且版本 `< 10.1.20`。不要把「可能装了 snmp」写成已 RCE。

---

## 1. 指纹（L1）

```bash
python3 炼蛊房/nday_route.py -u https://授权站 --case <案卷>
python3 tools/1day-kit/od_kit.py nuclei --url https://授权站 --case <案卷> \
  -t tools/1day-kit/custom-templates/zimbra-snmp-cve-2026-73570.yaml
```

常见：`/zimbra/`、`/zimbraadmin/`、标题/体 `ZimbraWebClient` / `Zimbra Collaboration`。  
版本从 `ZmSettings.js` 的 `clientVersion` / `zimbraVersion` 抠，**不要把 `cacheVersion`（缓存戳）当 ZCS 版本**。

---

## 2. L2 / L3

| 档 | 动作 | 默认 |
|----|------|------|
| L1 | HTTP 指纹 + 抠版本 | **做** |
| L2 | 版本落在 `< 10.1.20` 记「条件满足才可打」 | **做** |
| L3 | SMTP 命令注入 | **先问**；无公开 PoC **不做** |

HTTP 看不到 `zimbra-snmp` / `swatchdog`。未证实这三条件时，STATUS 写「版本可疑，SNMP 条件未知」。

---

## 3. 不要做

- 自造 SMTP 注入包 / 对未授权邮件网关狂轰  
- 只报 CVE 号结案  
- 把 Zimbra Cloud / 已修 `10.1.20+` 当受影响
