## 1. GeoServer jsonArrayContains（P0，在野、无补丁）

8/12 `@q1uf3ng` 公开：`jsonArrayContains` 过滤函数对用户参数未正确编码进 SQL。  
8/14 Hadrian 写完链；watchTowr 称公开后数小时已有**成百次探测**。  
**尚无 CVE、尚无 OSGeo 补丁。** 影响约 `GeoServer >= 2.25.3` + 受影响 GeoTools；需 PostGIS/Oracle 图层。RCE 另需库账号超管 / `pg_execute_server_program`（或 MSSQL SA）。

完整步骤 → **`地图府·吞库.md`**  
指纹 → `tools/1day-kit/custom-templates/geoserver-jsonarraycontains-sqli.yaml`

```bash
python3 炼蛊房/nday_route.py -u https://授权站 --case <案卷>
python3 tools/1day-kit/od_kit.py nuclei --url https://授权站 --case <案卷> \
  -t tools/1day-kit/custom-templates/geoserver-jsonarraycontains-sqli.yaml
```

临时缓解（防御笔记）：关公网 WFS/WMS、禁用 `jsonArrayContains`、PostGIS 关 encode functions / 开 prepared statements。默认 **不做** `COPY … TO PROGRAM`。

## 4. NextAuth / Auth.js（P1）

- **CVE-2026-73421**：`auth()` 在服务器配置错误时解析出真值 error 对象；只写 `if (req.auth)` / `!!auth` 的中间件 **fail-open**。修 `next-auth` **5.0.0-beta.32**。  
- **CVE-2026-73420**：magic-link 先校验再 Unicode 正规化，全角 `＠`（U+FF20）可把链投到攻击者邮箱。修 `@auth/core` **0.41.3**、`next-auth` **4.24.15** / **5.0.0-beta.32**。

作业口径（授权站）：

1. 指纹：`/_next/`、`next-auth`、`/api/auth/`。  
2. 73421：看中间件是否只判断 session 存在；配置残缺（缺 `AUTH_SECRET` / issuer）时未登录是否仍 200 进保护路由。  
3. 73420：仅当用内置 email normalizer + 下游会 NFKC 时测；勿对未授权邮箱狂发。

无专用 Skill：记 STATUS「NextAuth + 73421/73420」，源码案并行 DeepAudit。
