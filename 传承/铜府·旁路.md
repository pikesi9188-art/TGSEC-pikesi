# Tomcat 集群加密旁路手法（CVE-2026-34486）

> 情报：`od_kit.py cvebase lookup --cve CVE-2026-34486`  
> 配套指纹：`tools/1day-kit/custom-templates/tomcat-encrypt-bypass-cve-2026-34486.yaml`  
> 总览：`新伤·在野.md`  
> 红线：仅 `授权范围`；对集群口发反序列化/RCE payload **先问**

---

## 1. 一句话

开了 **Tribes 集群 + EncryptInterceptor** 的 Tomcat，解密失败仍把原始报文交给后续处理（fail-open）→ 未加密恶意集群消息可被接收 → 常落到 **反序列化 / RCE**。  
KEV · 在野 · EPSS≈0.83 · 有公开 Nuclei。

修 **CVE-2026-29146**（同组件 padding oracle）时把 `super.messageReceived()` 挪出 try，引入本回归。

---

## 2. 成立条件（比「有 Tomcat」窄）

必须同时接近：

1. 启用集群复制（Tribes）  
2. 配置了 `EncryptInterceptor`（以为加密=门禁）  
3. **集群接收口可达**（常见 **TCP 4000**，不一定是 8080）  
4. 版本落在未修点：`9.0.116` / `10.1.53` / `11.0.20`  
5. 类路径上有可用反序列化 gadget（决定 L3 能否打成 RCE）

**没开 EncryptInterceptor 的集群不受本 CVE 约束**（别的集群面另论）。  
只扫到 HTTP Tomcat 不等于本洞成立。

修复：`9.0.117` / `10.1.54` / `11.0.21`。

---

## 3. 指纹与作业档位

| 档 | 动作 | 成功证据 |
|----|------|----------|
| **L1 产品** | HTTP 版号 / `Server: Apache-Coyote` / 错误页 | Tomcat 且版本命中窄线 |
| **L2 集群面** | 授权内探集群口（常见 4000）是否开 | 端口开 + 与版本组合高置信 |
| **L3 利用** | 外置 nuclei / 授权 PoC 打未加密集群报文 | 命令执行或受控反序列化成功；**先问** |
