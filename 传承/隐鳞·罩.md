# WAF 检测与绕过

> 识别授权目标前的 WAF/CDN，再选绕过或旁路。  
> 工具入口：`炼蛊房/waf_detect.py`  
> 知识全文：`tools/vendor/09-aux/waf-detector/SKILL.full.md`

## 何时开打

- 响应头出现 `cf-ray` / `x-amz-cf-id` / `aliyun_lb` / `sl-session` / `x-sucuri-id` 等
- 探针统一 403/406/429 / JS challenge，需要先定厂商
- Triage 卡在「进不去」，怀疑边缘防护

## 流程

```text
授权确认
  → waf_detect.py detect（被动头/体 + 轻主动探针）
  → 置信度 + CDN 消歧（CDN ≠ 一定有 WAF 规则）
  → 分流：
        SQLi 拦签名     → waf_sqli_bypass（Unicode / %0a）
        CF 挑战 / 会员  → session_pipeline
        只要源站        → origin_recon / space_search cert-origin
        需协议层绕过    → SKILL.full.md（HTTP/2、h2c、chunked…）
  → 证据落 案卷/waf/ + STATUS 一句结论
```

## 命令

```bash
python3 炼蛊房/waf_detect.py stats

python3 炼蛊房/waf_detect.py detect \
  --url 'https://授权站' --case <案卷> --insecure

python3 炼蛊房/waf_detect.py full \
  --url 'https://授权站' --case <案卷> --attack sqli

python3 炼蛊房/waf_detect.py bypass --waf cloudflare --attack sqli --case <案卷>
```

证据：`案卷/<案卷>/案卷/waf/{detect,full,meta}.json`

## 与邻近手法

## 踩坑

- **CDN 误报**：Fastly/CloudFront 可能只缓存，未必开 WAF；看 challenge / block body，勿只凭 `via`。
- **指纹库**：可执行库 **253**（v2.2，已从表灌缺失项）；细节仍可读 `SKILL.full.md`。
- **噪声**：`full`/`bypass` 带攻击型探针，生产授权站控制频率。
- **性能**：短 body 词（`cdn`/`waf`）与全库 generic 403 已收紧；主动探测限 Top-8，行为探针全局一次。若仍慢，检查目标本身延迟。
- **结案标准**：写出「哪家 WAF + 下一步打法」，不是只报 `waf_detected: true`。
