## 一、真假分离侦察

先找**矛盾点与诱饵面**，再锁定**真实总后台/资金入口**。不在假壳上耗 80% 算力。

### 步骤

1. 枚举入口：www / app / admin / api / m / platform / static
2. 标「诱饵」：纯静态、文档站、过期 demo、无真实 API 的 SPA
3. 找矛盾：
   - 文档路径 vs JS bundle 真实 path
   - 登录成功域 vs 业务 API 域
   - 有 CSRF 面 vs 无 token 的 JSON API
   - GET 严校验 vs POST/export/upload 松
4. 锁定真总后台 / Crown 面：支付 settings、TRC20/ABA、结算 QR、租户管理、export
5. 再开正逻辑或 Anti-Logic

### 矛盾速查

| 矛盾 | 含义 |
|------|------|
| 页面有 admin，API 在另一 host | 真入口在 API 域 |
| init_data 文档严，register 可空 | 状态机旁路 |
| Bearer 文档必备，form/cookie 也能进 | 多鉴权不一致 |
| /admin 403，/admin/reports/export 200 | 路径级漏控 |
| 改地址字符串失败，QR 图能换 | 展示层与账务层分离 |

## 二、身份层 ROI 决策（业务系统 ≠ CMS 注入）

核心：把**需要身份的业务系统**当成**存在单点注入的 CMS** 来打 = 浪费 80% 算力。

真实防线是**密码学身份层**（bcrypt + HMAC + JWT HS256 / 签名 Cookie），不是 WAF。

### ROI 决策树

```
目标是 CMS/老 PHP/明显注入面？
  ├─ 是 → SQLi/上传/RCE 仍高 ROI
  └─ 否 → 业务系统 + 登录/Bot/JWT？
        ├─ 身份层优先：密钥泄露 · 伪造 · 注册状态机 · 无 auth 写接口
        └─ 仍要 RCE？→ 仅当存在回调 URL / 模板 / 反序列化 / 文件解析
```

### 错误算力（避免）

| 错误 | 为何低 ROI |
|------|------------|
| 对强身份业务无脑 sqlmap | 无注入面或 ORM 参数化 |
| 死磕 WAF 当主线 | 真防线在 HMAC/JWT |
| 未拿 session 就喷 RCE | 无入口 |
| 只爆 admin，忽略 user 链 | 旁路在 A2/A4 |

### 正确优先

1. 密钥与配置泄露 → session/JWT 伪造
2. 无 auth 写接口（settings / payment-methods / setup）
3. 注册/状态机旁路（无 init、phone-only）
4. IDOR / 角色混淆
5. 再考虑 SSRF/回调/模板

## 三、Anti-Logic 六轴（A1–A6）

> **完整 Playbook**：`传承/武遗海·反逻辑.md`（含对手心理模型矩阵、每轴打法示例、优先序、三张图片手法提炼）。  
> 本节为摘要指引，详细打法、SAN 拓线、RCE 可行性分级、IDOR 深挖后台定位见完整 Playbook。

对手按「你会怎么走」布防；你专走「他不会想你会走」的缝。

| 轴 | 名称 | 做法 |
|----|------|------|
| **A1** | 反目标 | 不夺权，先碰钱/配置。无 token 测 TRC20/ABA/settings |
| **A2** | 反路径 | 不打正门。register / setup / install / admin-users / reports / export |
| **A3** | 反协议 | 非标准 init_data。空 init / phone-only / 内网 persona |
| **A4** | 反顺序 | 先 user 链。register → recharge/merchant → 再测 admin 越权 |
| **A5** | 反身份 | 扮客服/运维/cron。device_id、UA、频次像 support |
| **A6** | 反入口 | 非主 API 前缀。chat / socket.io / telegram-test 回调面 |

### 优先序

1. **A4** user 链 + 异常 init_data
2. **A1** QR upload / 支付展示
3. **A6** telegram-test / 回调 SSRF
4. **A5** decoy + support persona
5. **A2** setup/install 窗口期

### 与正逻辑 Kill Chain

```
正逻辑: 身份 → 权限 → Crown（等人/口令/token）
反逻辑: 旁门 → 业务链 → QR/SSRF/export → 可回 Crown
```
**并行，不是二选一**。汇合点：任一轴拿到 token 或有效写权限。

## 四、支付/收款配置面（Crown Surface）

「改收款地址/支付方式/结算QR」= **真实资金影响面**，比拿 shell 更贴近交付目标。

### 检查清单

- [ ] `PUT/PATCH` payment-methods/settings/settle-address 是否鉴权
- [ ] user 角色能否写 admin 支付配置（BFLA）
- [ ] QR 图片上传与地址字符串校验是否不一致
- [ ] 回调/通知是否在改密后告警
- [ ] 无 auth 或 setup 阶段可否写支付配置
- [ ] 前端展示地址与服务端结算地址是否双源

## 八、进站课（脱敏）

### 8.1 settings/Bot Token 泄露（Nuxt/PHP 内容站）

| 接口 | 问题 |
|------|------|
| `GET /api/v1/site/settings` | 未授权返回 Bot Token、客服 chat_id、USDT 地址 |
| `GET /posts/{id}` 详情 | 未登录返回 download.url + 解压密码 |
| login/register | captcha 全关 → 可爆破/批量注册 |

**检查**：settings 是否鉴权；Token 是否永远不下发前端；付费字段是否服务端校验。

### 8.2 TG 云控 export BOLA

```
开放注册 → JWT → JS 挖 API → POST .../export {ids:[...], format: session_json}
→ 无 owner 校验 → ZIP 内 .session + .json 批量出库
```

信号：`GET /accounts/{id}` 403，但 `POST /accounts/export` 200 = **读严导出松**。
次生风险：导出含明文 2FA/两步密码、session 含 auth_key（等同接管）。
**检查**：所有 export/download/batch 是否按 owner 过滤；ids 数组可否越权扫。

### 8.3 发卡站支付回调伪造 → 未授权读卡密

```
创建订单 → 泄露 pid/sign 结构 → 反推/复用 merchant_key
→ ksort+md5 构造 notify → 订单变已支付 → 卡密页无鉴权
```

根因：回调签名密钥弱/复用/泄露 + 不校验金额 + 详情未授权。
**检查**：notify 验签密钥独立随机？金额校验？卡密页强制登录态？

### 8.4 RuoYi/多租户 DataScope 遗漏

信号：某个 biz 列表 total 极大（跨租户），其它同角色 total=0。
= 单点遗漏 `@DataScope` 注解 → 水平越权。
并行面：`/common/upload` 白名单含 html（存储 XSS）、`configKey` 泄露 `initPassword`。
**口径**：数据层打穿 ≠ 管理后台/RCE 打穿，报告诚实区分。

### 8.5 EdgeOne WAF + 开放注册 + 上传链

```
多子域指纹 → EdgeOne JS Challenge → 拿 EO cookie
→ 开放 /register → 角色菜单过多 → 产品/定价/thirdSource 泄露
→ /common/upload 弱类型 → Druid 等监控暴露
```

**检查**：WAF cookie 可否脚本化重放？Host 直连绕过？注册默认角色最小化？

## 九、自主威胁建模工作流

按业务面建模，不套固定漏洞清单。

### 三阶段

| 阶段 | 名称 | 要点 |
|------|------|------|
| 1 | Discovery | JS 深度分析 + 全量接口发现 + 会话池 + 权限矩阵 |
| 2 | Attack | feature 级流水线 + 动态发现子模块 + 跨角色验证 |
| 3 | Audit | schema 校验 + 完整性审计 + 报告（md + docx 双格式） |

### 关键理念

- **先读懂 JS**：签名机制、前端可控参数、业务逻辑 → 再测接口（不盲喷）
- **200 ≠ 漏洞**：验证数据库层/数据访问/状态变更真实发生
- **权限矩阵**：Discovery 生成矩阵，Attack 内联做越权验证，victim ID 不硬编码
- **三问 coverage_note**：输入面 / 行为面 / 深度面
- **未排除面**：`not_vulnerable` 附 `unruled_out`（诚实标注哪些没排除）
- **多项目隔离**：`--resume` 断点续测、`--list` 列项目状态

### 七硬门（G1-G7 摘要）

- G1 账号门槛：≥2 账号正常进入；0-1 不阻塞降级放行
- 高危利用先汇报再继续
- `pentest-data/` 含明文凭据，测完清理或加密
- 报告配置类低危归附录，主报告聚焦核心发现
