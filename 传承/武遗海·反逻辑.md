# Anti-Logic 六轴反逻辑攻击面手法

> **定位**：与正逻辑 Kill Chain 并行的攻击思维框架。不是二选一，是并行：正逻辑等人/口令；反逻辑扫旁门与业务缝。  
> **真源**：大爱仙尊 Anti-Logic 六轴 Playbook。摘要见 `幻道辨真.md` §三。  
> **适用**：授权渗透/SRC 猎洞全场景——尤其在正逻辑卡死（admin 密码强、MFA、WAF 严）时，反逻辑提供平行突破面。

---

## 一、核心思想

对手按「你会怎么走」布防；反逻辑专走「他不会想你会走」的缝。

### 对手心理模型 vs 反逻辑刀矩阵

| 他认为你会… | 反逻辑刀 | 轴 |
|-------------|---------|-----|
| 死磕 admin/auth/login 爆破 | 打 user/login 同口令 · setup/install 无 auth 建站 | A2/A4 |
| 先拿 admin 再改 TRC20 | 无 auth 直接 PUT payment-methods / settings | A1 |
| 伪造 init_data HMAC | telegram/register 无 init · phone-only 状态机 | A3 |
| 正面 Crown PUT | 先 QR upload 换图（用户扫 QR 不读地址）· ABA 旁路 | A1 |
| 外部黑客 JSON Bearer | 内网 persona · cron UA · form/500 错误面 | A5 |
| 从 /admin 进 | /admin/reports/* export · /chat/* · Socket.io | A6 |
| 继续大规模喷洒 | 慢速 support/kefu 单发 + decoy（不像攻击） | A5 |

## 二、六轴定义与打法

### A1 反目标 — 不夺权先改钱

**核心**：不追 admin token，先碰钱/配置/展示层。无 token 测 TRC20/ABA/settings。

| 打法 | 说明 |
|------|------|
| `PUT/PATCH` payment-methods / settings 无鉴权 | 直接改收款地址，不需要管理员身份 |
| QR upload 换图 | 用户扫 QR 看图不看地址字符串，改图比改字符串更隐蔽 |
| ABA 旁路 | 不碰 admin 钱包字段，改 ABA routing number / 结算配置 |
| Crown 展示层 | 改充值页面展示的地址（展示层 vs 后端验证层不一致） |

**何时用**：有 admin 面板或 upload 未授权时优先；即使无法登录也能直接影响资金流。

### A2 反路径 — 不打正门

**核心**：避开 `/admin/login`，走 register / setup / install / admin-users / reports / export。

| 打法 | 说明 |
|------|------|
| `/setup` / `/install` 无 auth | 新部署/重装窗口期偶发无鉴权建站 |
| `/admin/reports/*` export | 报表导出接口常漏鉴权或降级鉴权 |
| `/register` → admin 路径 | 注册后直接访问 admin 路由（注册 ≠ 需要已有管理员） |
| `/admin-users` 枚举 | 管理员列表接口与登录接口分离，前者可能无 auth |

**何时用**：setup/install 在新部署期、reports 在业务系统常见；正门挡死时侧面突破。

### A3 反协议 — 非标准认证路径

**核心**：不走标准 init_data/HMAC 验证流，走空 init / phone-only / 内部 XFF。

| 打法 | 说明 |
|------|------|
| 空 init_data | Telegram Mini App 场景下 init 为空仍可注册/操作 |
| phone-only 状态机 | 绕过完整认证链，只用手机号进入部分业务流 |
| 内网 XFF / 信任头 | `X-Forwarded-For: 127.0.0.1` 走内部认证路径 |
| form 提交 vs JSON API | 切换 Content-Type，某些鉴权只检查 JSON 路径 |

**何时用**：TMA/Bot 场景或内部网关暴露时。

### A4 反顺序 — 先 user 链再 admin

**核心**：先注册普通用户，走 recharge/merchant 路径，再测 admin 越权。

| 打法 | 说明 |
|------|------|
| register → recharge | 注册用户 → 充值/提现流 → 发现商户/代理 API |
| merchant 自批 | 商户身份若存在即越权（充值审核自己通过） |
| user 链发现 admin API | 通过用户 JS/路由暴露管理接口 |
| 低权票测高权接口 | 有用户 session 后直接请求 admin 端点 |

**何时用**：优先级最高。真实 init_data + user 链 = 商户/充值自批若存在即越权。

### A5 反身份 — 扮客服/运维/cron

**核心**：device_id 像 support 不像 hacker。慢速单发 + decoy 不触发安全告警。

| 打法 | 说明 |
|------|------|
| support persona | UA/device_id/频次模拟客服终端 |
| cron UA | 模拟定时任务请求 `User-Agent: CronJob/1.0` |
| 内部 form/500 错误面 | 通过错误页面暴露的内部表单提交 |
| 慢速 kefu 单发 | 单发请求 + 间隔，不像扫描器喷洒 |

**何时用**：需要绕过 WAF/行为检测时；社工辅助（非纯技术突破）。

### A6 反入口 — 非主 API 前缀

**核心**：不走 `/api/hm`，走 chat / socket.io / telegram-test / 回调面。

| 打法 | 说明 |
|------|------|
| `/chat/*` WebSocket | 聊天接口常有不同鉴权策略 |
| `socket.io` 事件 | WebSocket 事件处理逻辑独立于 REST API |
| `telegram-test` SSRF | 测试回调端点可用于内网探测 |
| `/admin/reports/*` export | 导出接口与主 API 鉴权分离 |

**何时用**：需 admin token 打内网时（二次武器化）；主 API 全锁但辅助接口暴露。

## 三、优先序

| 优先级 | 轴 | 打法 | 理由 |
|--------|-----|------|------|
| 1 | **A4** | user 链 + 真实 init_data | 商户/充值自批若存在即越权 |
| 2 | **A1** | QR upload / 支付展示 | 有 admin 或 upload 未授权时改 QR 比改字符串更隐蔽 |
| 3 | **A6** | telegram-test SSRF | 需 admin token 打内网（二次武器化） |
| 4 | **A5** | decoy + support persona | 不像红队的慢速社工 |
| 5 | **A2** | setup/install | 新部署/重装窗口期偶发无 auth |

## 四、与正逻辑 Kill Chain 的并行关系

```
正逻辑: 身份 → 权限 → Crown（等人/口令/token）
反逻辑: 旁门 → 业务链 → QR/SSRF/export → 可回 Crown
```

**并行，不是二选一。** 正逻辑等人/口令；反逻辑扫旁门与业务缝。

**汇合点**：任一轴拿到 token/写权限 → `admin-takeover --crown-trc20 TN9GuM...`

### 实操节奏

1. 进站后正逻辑（弱口/凭证/提权）和反逻辑（A1–A6）**同时展开**
2. 正逻辑卡在 admin 密码/MFA 时，反逻辑已在 user 链/setup/chat 面推进
3. 任一面突破 → 立刻汇合到 Crown（支付配置/管理员接管）
4. 反逻辑阴性 → 回正逻辑继续；正逻辑阴性 → 反逻辑加码

## 五、三张图片手法提炼

### 5.1 证书 SAN 拓线（A2 反路径延伸：侦察面）

**手法**：TLS 证书 SAN 字段发现报告外的隐藏资产。

**实战案例**：
- 证书 SAN 挖出 `cs-go-viewer.dev.cookies.games` → dev 子域暴露开发环境
- RunCloud 面板 IP → 托管面板未设防，直接管理服务器

**打法**：
1. `crt.sh` / `certspotter` 查目标域所有证书
2. 提取 SAN 字段全部域名，含 dev/staging/internal 子域
3. 非 CDN IP 证书 → 溯源到源站或管理面板
4. 新资产回灌种子队列（自由跳模式 §1.1.1）

**融入 Skill**：`cdn-origin-tracing`（证书溯源）+ `information-gathering`（SAN 拓线）。

### 5.2 RCE 攻击面可行性分级矩阵（strike-probe / case-triage）

**手法**：多面盘点后按可行性（零认证 → 需前置）排序，直接开测最可行的。

**五面矩阵实例**：

| # | 面 | 手法 | 可行性 |
|---|------|------|--------|
| 1 | Poker `/Cheat/request` (JsonNode body) | Json.NET `$type` 反序列化 gadget | 🟢最高：零认证+裸弃 |
| 2 | Memcoin Next.js | CVE-2025-29927 middleware 绕过 | 🟢版本一查便知 |
| 3 | VIRUS/Trade Go 服务 | `/api/metrics` 220KB + `/debug/pprof/` 栈泄露 | 🟡中等 |
| 4 | GitLab 16.6-16.7 | 7028 端口 CI/CD runner → shell | 🟠需前置：控邮箱 |
| 5 | Release Admin K8s ingress | 假证书=运维裸奔，kubelet 10250/API 6443 匿名面 | 🔴顺手扫 |

**节奏**：零认证面先测 → 版本确认面次之 → 需前置条件的后排。只读试探、零资金操作优先。

**融入 Skill**：`strike-probe`（S1–S8）/ `attack-router`（面排序）/ `case-triage`（定级）。

### 5.3 IDOR 深挖 → 后台定位（dotnet-ashx-fintech-idor 延伸）

**手法**：从 IDOR 响应字段反推运营后台位置。

**实战案例**：
- `getuserinfo.ashx` 响应中 `hasOrder=1` → `wsq(userid=2132)` 的 `fundAccount.hasOrder=1`
- `getorder.ashx` 裸路径 404、WAF 双斜杠绕过无效
- `nlpquant` 裸 IP 直连正常 → 真正存"谁买了哪个投顾产品(最高16.8万)"的库
- 运营后台 = `nlpquant`（Vol.Core 框架）

**深挖链路**：
1. IDOR 枚举 → 发现业务字段（hasOrder/fundAccount/证券产品）
2. 响应里的内部标识 → 定位真实后台 IP / 域名
3. WAF 绕过无效 → 换裸 IP 直连
4. 新主攻方向：后台 API 匿名访问 + 框架默认凭据/已知漏洞

**融入 Skill**：`dotnet-ashx-fintech-idor`（IDOR 枚举 + 后台定位）。
