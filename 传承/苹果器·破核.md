## 3. AKS / 65343 可验证链

```bash
python3 ios-research/tools/aks-oob/bin/aks_oob_lab.py doctor
python3 ios-research/tools/aks-oob/bin/aks_oob_lab.py build --team <10位TeamID> --udid <设备>
# 真机 App 点 Run，取出 aks_oob.log
python3 ios-research/tools/aks-oob/bin/aks_oob_lab.py classify --log <aks_oob.log> --build 23G71
```

| classify 结论 | 含义 |
|---------------|------|
| `CONFIRMED_KASLR` | 真机打出 slide |
| `CONFIRMED_INFOLK` | kptr / OOB CONFIRMED |
| `PATCHED` | 23G83+ 且无 kptr |
| `PHASE1_BLOCKED` | 没抓到 ACM handle（常见 secd XPC），换机构建再测 |
| `NOT_RUN` | 没有日志 = 未验证 |

证据写 `案卷/<案>/案卷/ios/65343/`。没有 `aks_oob.log` 禁止写「漏洞成立」。

对照构建：未打补丁 `23G71`，已打 `23G83`。模拟器无 SEP，不要用。

## 5. 成功口径

- 应用面：Keychain / Scheme / ATS / 明文库，写入 `案卷/ios/`
- 内核 infoleak：仅 `classify` 阳性
- 资产面：对**指定导出**跑出 `CONFIRMED_SECRET` / `CONFIRMED_ADDR`
- 转 USDT / 真耗余额：先问

## 不要做

- 把「官方写了 UAF」当成结案
- 用模拟器复测 SEP/AKS
- 把网页诱饵页写成已破核
- 编成功率表或不存在的 exploit 文件名
