# MLflow Webhook SSRF 手法（CVE-2026-64849）

> Skill：`杀招/流实验`  
> 情报：`od_kit.py cvebase lookup --cve CVE-2026-64849 --docs`  
> 指纹：`tools/1day-kit/custom-templates/mlflow-ssrf-cve-2026-64849.yaml`  
> 总览：`CVE日报-2026-08-22.md`  
> 红线：仅授权目标；先协作域名，禁止扫无关公网 / 默认打云元数据  
> API 真源：OSS `GET/POST /api/2.0/mlflow/webhooks`（GHSA-7gwp-5pfp-969j）。**不要**写成 `/webhooks/list`，也不要跟 Databricks `registry-webhooks/list` 混。

---

## 0. 画像

默认 `mlflow server` **无鉴权**。未认证 `POST /api/2.0/mlflow/webhooks/{id}/test` 只校验原始 URL，delivery 跟随 302 且不钉解析 IP → **全回读 SSRF**（`response_status` + `response_body`）。  
KEV 2026-08-19 · 在野 · 有公开利用。GHSA 在 `3.13.0` 复现。修：`3.15.0`。

| 动作 | 方法 | 路径 |
|------|------|------|
| 列 webhook（L2） | GET | `/api/2.0/mlflow/webhooks` |
| 建 webhook | POST | `/api/2.0/mlflow/webhooks` |
| 测试（SSRF 面） | POST | `/api/2.0/mlflow/webhooks/{id}/test` |
| 实验列表（指纹） | POST | `/api/2.0/mlflow/experiments/search` |

成功口径：未授权 GET 出 `webhooks` JSON **或** 协作 URL 被 Tracking Server 回读。不要只报 CVE 号。

## 2. L2 验证（授权内）

1. 未带票 `GET /api/2.0/mlflow/webhooks`。`{"webhooks":[...]}`（含空数组）即未鉴权。  
2. 要证明出网：对**你控制的协作 HTTPS URL** `POST /api/2.0/mlflow/webhooks` 再建，再 `POST .../{id}/test`。events 必须大写 proto 名（如 `REGISTERED_MODEL` / `CREATED`）。默认 scheme 只允许 https。  
3. **不要**把 `/test` 指到 `169.254.169.254`、未授权内网或无关公网。  
4. 证据：`案卷/1day/mlflow_ssrf.*` + STATUS 写版本与是否未鉴权。

影响：`< 3.15.0`。修：`3.15.0+`。

---

## 3. 不要做

- 用 SSRF 扫未授权网段 / 默认打 IMDS  
- 走错路径 `/webhooks/list` 或 Databricks `registry-webhooks` 然后报阴性结案  
- 无协作或 list 证明就报「可打云凭据」  
- 只扫 CVE 结案；命中后若同机还有业务面，切对应专链
