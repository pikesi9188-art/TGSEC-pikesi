# SmartConsole 认证绕过手法（CVE-2026-16232）

> 情报：`od_kit.py cvebase lookup --cve CVE-2026-16232`  
> 指纹：`tools/1day-kit/custom-templates/smartconsole-auth-bypass-cve-2026-16232.yaml`  
> 总览：`新伤·在野.md`  
> 红线：仅 `授权范围`；改防火墙策略/下发规则 **先问**

---

## 1. 一句话

Check Point **Security Management / MDS** 上 SmartConsole 登录链信任边界坏掉：未授权可读管理端 **SIC DN**，伪造 application bind → 拿到 **application token** → 换 **SmartConsole SSO 超管票**。  
KEV · 在野 · CVSS≈9.8 · 有公开 Nuclei/分析。

远程利用前提（厂商）：

1. 能访问 **Management Server** 管理地址  
2. **Trusted Clients（GUI clients）未收紧**（常见默认 `Any`）

---

## 2. 战场价值

管策略的大脑：VPN、访问控制、网关配置。超管票 = 改策略/扩信任/为横向铺路，不是普通 Webshell 可比。

审计线索（防御/复盘）：SmartConsole 日志搜  
`Authentication method: application token`

---

## 3. 修复与缓解

| 项 | 内容 |
|----|------|
| Jumbo | R82.10 **Take 36+**；R82 **Take 118+**；R81.20 **Take 158+** |
| 缓解 | Trusted Clients **禁止 Any**，只放可信管理 IP；管理口勿对公网裸奔 |
| SK | https://support.checkpoint.com/results/sk/sk185169/ |
| 分析 | https://www.rapid7.com/blog/post/ra-check-point-smartconsole-authentication-bypass-technical-analysis-cve-2026-16232/ |

根因备忘：信任调用方自报的 SIC DN，未绑定对端证书 DN（`getCertificateDnName()`）。

## 4. 档位与成功口径

| 档 | 动作 | 成功证据 |
|----|------|----------|
| **L1 指纹** | 管理口/Gaia/CP 产品特征、19009 等管理面 | 确认 Security Management 暴露 |
| **L2 条件** | Trusted Clients 是否 Any；是否达管理 IP | 满足远程利用前置 |
| **L3 绕过** | 授权内用公开 Nuclei/PoC 换票 | 超管级会话/可改策略证据；**改策略先问** |
