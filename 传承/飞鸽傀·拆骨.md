## 0. 为什么 TG Bot 是高价值目标

Telegram Bot API = 免费、TLS、全球可达、免基础设施的消息总线。

- **Token 即全部权限**——无密码、无 2FA、无 IP 白名单
- **token + chat_id 常硬编码**在恶意产物里（HTML/JS/二进制/配置文件）
- **Webhook 是 HTTP 端点**，bot 后端常见签名缺失/反代配置错误
- **黑产 bot 后端**往往就是普通 Web 应用，可套 web 渗透方法论

## 1. A 面：Token 泄露 → 全接管

### 1.1 Token 格式

```
格式：<bot_id>:<35位secret>     例: 1234567890:AAFizzpeo2...YaB0d78
正则：[0-9]{10}:[A-Za-z0-9_-]{35}
```

### 1.2 核心 API 命令

| 命令 | 用途 | 注意 |
|------|------|------|
| `GET /bot<T>/getMe` | 验证 token 有效性 | 无副作用 |
| `GET /bot<T>/getUpdates?offset=-1000` | 回放历史消息 | 有 webhook 时不可用 |
| `GET /bot<T>/getWebhookInfo` | 查看 webhook 配置 | 评估动静 |
| `POST /bot<T>/sendMessage` | 冒充 bot 发消息 | ⚠️ 先问 |
| `POST /bot<T>/setWebhook` | 截流到攻击者 URL | ⚠️ 先问 |
| `POST /bot<T>/deleteWebhook` | 清除 webhook | ⚠️ 中断通知 |
| `POST /bot<T>/forwardMessages` | 批量前转消息 | ≤100 条/次 |

### 1.3 泄露途径

1. **客户端 JS 硬编码**：`curl -s https://target/_nuxt/*.js | grep -oE '[0-9]{10}:[A-Za-z0-9_-]{35}'`
2. **表单请求透传**：Contact us 表单提交请求体/URL 带 token
3. **GitHub 仓库/git history**：`gitleaks detect` / `trufflehog git`
4. **.env / docker-compose 泄露**：`BOT_TOKEN=` / `TELEGRAM_TOKEN=`
5. **恶意样本硬编码**：PyInstaller 解包 / JS 反混淆 / APK 反编译
6. **钓鱼 kit 泄露**：open dir 挖 `sign/*.html` 变体内 token
7. **kit 开发者后门**：JQ.js 后门偷运营者 token
8. **日志泄露**：`laravel.log`、`app.log`、`debug.log`

### 1.4 批量发现（测绘）

```bash
# FOFA body 搜
python3 tools/space-search/fofa_query.py 'body="api.telegram.org"'

# Netlas 分层搜（getUpdates 最有价值）
# http.body="api.telegram.org" AND http.body="getUpdates"

# VirusTotal：contacted_urls:api.telegram.org → 提取 token
```

### 1.5 操作纪律

- 拿到 token 先 `getWebhookInfo` 评估
- 有 webhook → bot 在跑，动静大
- 优先 `forwardMessage` 特定消息而非 `getUpdates` 全拉
- 不立刻 `setWebhook` 截流（先问）

## 2. B 面：Webhook/后端攻击

### 2.1 secret_token 签名校验

Telegram 机制：`setWebhook(url, secret_token=...)` → 回调带 `X-Telegram-Bot-Api-Secret-Token` header。
**后端不校验 = 任何人都能 POST 伪造 Update JSON。**

框架默认都**不校验**，需显式配置：
- python-telegram-bot：`Application.run_webhook(secret_token=...)`
- aiogram：`run_webhook(secret_token=...)`
- telegraf：`bot.launch({webhook:{secretToken:...}})`
- grammY：`webhookCallback(bot, {secretToken:...})`

### 2.2 CVE 与案例

**CVE-2026-28454 (OpenClaw, CVSS 9.1)**
- webhook 模式未配置 secret → 接受任意 POST → 伪造 `from.id`/`chat.id` → 绕过 sender 白名单执行特权命令

**F-2026-0005 (zealynx)**
- 控制器不验签，且用攻击者可控的 `update_id` 当反重放键 → 完全绕过 anti-replay → 伪造带 auth code 的 `/start` → 把受害者钱包绑到自己 TG 账号

### 2.3 常见 webhook 端点探测

```
/webhook  /bot  /telegram/webhook  /api/webhook  /api/telegram
/bot/webhook  /.well-known/telegram  /tg  /hook  /callback
```

### 2.4 伪造 Update 骨架

```json
{
  "update_id": 999999,
  "message": {
    "message_id": 1,
    "from": {"id": 67890, "is_bot": false, "first_name": "Attacker"},
    "chat": {"id": 67890, "type": "private"},
    "date": 1700000000,
    "text": "/start VALID_AUTH_CODE_HERE"
  }
}
```

### 2.5 反代坑点

- nginx 吞掉 `X-Telegram-Bot-Api-Secret-Token` → 应用层校验永不生效
- webhook 路径可预测 + Swagger 暴露
- `setWebhook` 指向内网地址 → SSRF

## 4. D 面：恶意生态情报利用

### 4.1 ANY.RUN 拦截方法论

```
① 沙箱抓样本 → 拿 token + chat_id
② getWebhookInfo → 保存配置 → deleteWebhook（避免抢先消费）
③ 建匿名群 → 拉 bot 进群
④ getUpdates?offset=-1 重置
⑤ getUpdates?offset=<last+1> 清空
⑥ forwardMessages 批量前转（≤100条/次）
⑦ 完事恢复原 webhook
```

### 4.2 Drainer 逆向要点

- token/chat_id/钱包地址写在 JS 头部变量
- 区域检查过滤 CIS（ipapi.co / cf trace）→ 伪装 IP 绕过
- 搜 `api.telegram.org` / `bot` / `chat_id` 锚点 → 沿调用回推

### 4.3 Stealer/RAT 逆向链

```
PyInstaller 解包 → 反编译 .pyc → grep token → getMe 验证 → 情报采集
```

### 4.4 聚类

同 token / 同 webhook / 同 description → 同一运营者

### 5.3 YARA 规则

```yara
rule HUNT_Telegram_Bot_API {
  strings:
    $api = "api.telegram.org" ascii wide
    $token = /[0-9]{10}:[A-Za-z0-9_-]{35}/ ascii
    $gm = "getMe" ascii
    $gu = "getUpdates" ascii
  condition:
    $api and ($token or 2 of ($gm, $gu))
}
```

## 6. 防御速查（报告用）

1. token 只放 env/secret manager，**轮换 = BotFather /revoke**
2. 前端只用 bot_id，secret 绝不进客户端
3. webhook：强制 `secret_token` + constant-time 校验 + 反代原样转发 header + 路径随机化 + 仅 Telegram IP 段可达
4. 支付：服务端二次验证 successful_payment（charge id）
5. 权限：from.id + 角色白名单；不信任 update 内可伪造字段
6. 依赖：锁版本、定期审计、警惕冒牌包
7. Mini App：initData 服务端 HMAC 校验，恒时比较
