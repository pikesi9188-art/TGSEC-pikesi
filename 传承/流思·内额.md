# Flowise 内部头密钥泄露 → NodeVM 逃逸（CVE-2025-58434 / CVE-2026-46442）

> 学习样本：SAE-20260827-822f5b-A005-PUB（公开版，2026-08-31）  
> 探针：`炼蛊房/flowise_probe.py`  
> 指纹：`tools/1day-kit/custom-templates/flowise-apikey-internal-header.yaml`  
> 杀招：`流思`  
> 同族：`流语·开天.md` · `大灵.md` · `cloud-metadata-harvesting`  
> 红线：仅 `授权范围`。L2 只测内部头密钥泄露。NodeVM 沙箱逃逸 payload **不默认发**。挖矿/持久化先问。

---

## 1. 一句话

公开部署的 **Flowise**（低代码 LLM 工作流，Node）常见两步链：

1. `GET /api/v1/apikey` + 伪造内部头 `x-request-from: internal` → **未认证吐 API Key/Secret**（CVE-2025-58434 变体）
2. 持钥打 `POST /api/v1/node-custom-function` → **NodeVM 沙箱逃逸 → 容器 root RCE**（CVE-2026-46442）

样本版本 **2.2.7-patch.1**；受影响区间 **≤3.1.2**。修复：**3.1.2 以上**。  
GKE/K8s 上若未开 **metadata concealment**，容器 RCE 会直接升级成云账号令牌 + 公开桶。

---

## 2. 为什么值钱

Flowise 控制面常挂 LLM Key、向量库、下游回调。内部头当「来源信任」且不做网络校验 = 零凭据进控制面。  
容器默认 root + 云元数据未隐藏 = 应用 RCE 变成项目级云横向。

---

## 3. 档位与成功口径

| 档 | 动作 | 成功证据 |
|----|------|----------|
| **L1 指纹** | `/api/v1/version` / `/api/v1/ping` / 首页 Flowise | 产品 + 版本 |
| **L2 密钥** | 无头 vs `x-request-from: internal` 打 `/api/v1/apikey` | 带内部头 200 且 JSON 含 Key/Secret（**值打码**）；无头 401/403 |
| **L3 RCE** | 持钥打 `node-custom-function`（沙箱逃逸） | **先问**。本库探针不发逃逸 payload。得 shell 后走云元数据卡 |
| **L3 云** | 容器内 IMDS / 公开桶 | 先问；禁止默认打 `169.254.169.254`；公开桶只列不拖全量 |

根因（概念）：平台用请求头标识「内部调用」，未校验来源；自定义 JS 函数进 NodeVM，沙箱有已知逃逸面且执行端点鉴权可被 L2 密钥绕过。

## 4. 利用链（概念级，学习样本）

```
伪造 x-request-from: internal
  → 未认证 GET /api/v1/apikey 拿 Key/Secret
  → 持钥 POST /api/v1/node-custom-function（NodeVM）
  → 容器 uid=0
  → 云元数据默认 SA 令牌（concealment 未开）
  → 生产对象存储桶匿名可读
```

RCE 后横向（与 Langflow 样本同构，走已有卡，不新写）：

1. 环境变量 / 应用超管 / DB / API Key
2. Skill `盗天·云骨`（GKE 须 `Metadata-Flavor: Google`）
3. 公开桶 → `bucket_probe.py`（只列）
4. 得 shell → `linux-post-exploit`；容器 SA → `群瓮·特权.md`

**禁止**默认挖矿、删站、改原超管密。授权内反弹/写马直接做。
