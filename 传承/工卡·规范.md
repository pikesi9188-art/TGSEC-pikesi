# 工卡·规范

> 通用技能已 **收编为本库卡**（`owned: true` / `pack: survey-skill`），不是外挂。

## 1. 两层技能

| 层 | 路径 | 用途 |
|----|------|------|
| 打站专卡 | `杀招/` 无 `pack: survey-skill` | 授权作业、杀伤链、探针 |
| 通用技能 | `杀招/` 带 `pack: survey-skill` | Word/PPT/官方文档/ToB 等，已是本库的 |
| 全文仓 | `智道藏书/skill-store/skills/<slug>/` | 已收编全文；目录名 = 技能名 |

收编命令：

```bash
python3 炼蛊房/skill_store_sync.py   # 增量拉全文（写入 slug 目录）
python3 炼蛊房/skill_own.py          # 写成大爱仙尊自己的卡（不覆盖打站专卡）
python3 炼蛊房/skill_store_adopt.py  # 旧外仓目录名 → slug
```

## 2. 本库一张作业卡的最低完成度

三件套缺一不可（重定向 stub 除外）：

| 件 | 路径 | 作用 |
|----|------|------|
| Playbook | `传承/*.md` | 手法真源（先读再打） |
| Skill | `杀招/<name>/SKILL.md` | 触发词 + 交接，禁止只堆 payload |
| 探针/工具 | `炼蛊房/*_probe.py` 或卡内 `scripts/` | 授权内能跑出 JSON 证据 |

新卡按此规范写：

1. YAML frontmatter：`name`（小写连字符）+ `description`（含触发词，10–500 字）
2. **何时用 / 任务目标**
3. **输入 / 输出**（参数表 + 产物路径）
4. **核心逻辑**（步骤，禁止文字墙）
5. **失败处理**（服务挂了不能默默当阴性结案）
6. **示例**（至少 1 条真实命令）
7. 可选：`scripts/`、`references/`（长文从 SKILL.md 拆出去）

同族重复（融合百科 / 旧入口名）**并进已有专卡**：Cursor 卡改成 stub「已并入 \`canonical\`」，长文留在 `智道藏书/`。禁止用百科覆盖专卡正文。再 fuse 时把旧名写入 `shizhan_pack_route.TO_OURS`。

## 3. 命令

```bash
# 整库蒸馏（张数 / 路由覆盖 / 未挂入口）
python3 炼蛊房/engine_distill.py snapshot
python3 炼蛊房/engine_distill.py orphans

# 盘点：有无 Playbook / 探针 / 卡内脚本
python3 炼蛊房/skill_catalog.py list

# 校验器 + 本库作业闸检查
python3 炼蛊房/skill_catalog.py validate
python3 炼蛊房/skill_catalog.py doctor --fix   # 清商店孤儿目录、补缺 frontmatter

# 导出打站卡目录
python3 炼蛊房/skill_catalog.py export --json /tmp/skills.json --md /tmp/技能目录.md

# 检索已灌入的第三方全文库
python3 炼蛊房/skill_catalog.py store --search pptx
```

等级：

| grade | 含义 |
|-------|------|
| `stub` | 重定向卡，正文指向另一张 |
| `thin` | 只有 SKILL.md，未点到 Playbook 也未点到工具 |
| `kit` | 点到 Playbook **或** 工具 |
| `full` | Playbook + 可跑入口都有 |

`thin` 不能进交货包当「完整技能」。补三件套或标 stub。

## 4. 收编纪律

- 打站专卡目录名冲突时 **专卡赢**，不覆盖。
- 同名多源：按质量优先去重，打站专卡赢。
- 溯源只写在卡内一行，对外算大爱仙尊技能。
- 只爬目录、不落正文，不算收编完成。
