# Spring Cloud Gateway / Actuator 杀伤链 Playbook

> 参考真源：（开源包不收个案摘记）（Telegram 审计报告全文）  
> 工具目录：`tools/spring-gateway-killchain/`  
> 授权：已写入 `授权范围` → `allowed_operations`（业务 AF）  
> **仅在授权 targets 内使用。**

---

## 0. 何时启用

目标出现以下任一指纹时，**必须**按本 Playbook 全链复测（勿只扫 `/actuator/health`）：

| 指纹 | 含义 |
|------|------|
| `/actuator`、`/actuator/env`、`/actuator/gateway/routes` | Spring Boot / SCG 控制面 |
| `/v3/api-docs`、`/open/v2/api-docs` 未授权 | OpenAPI 放大攻击面 |
| ShowDoc / 对接文档 `?t=` 公开令牌 | 文档/密钥泄露 |
| `User-Target` / `/prod-api` + 商户后台 | 支付中台 / 微服务网关 |
| `security.ignore.whites` 含 `refreshInRule` 等 | 白名单路径旁路候选 |
| Nacos `dev/dev`、Jasypt `ENC(...)` | 配置中心/密文链 |

```bash
# 快速入口（授权 scope 内）
python tools/spring-gateway-killchain/bin/sgc_probe.py --base https://目标 --out 案卷/.../sgc/
```

**大爱仙尊顺序（禁止跳步）**：白名单旁路 → Range heapdump 分桶 → 双编码 LFI → 开放平台签名 → SpEL stale route → `/agg-c` → Nacos。  
见 Nacos 先版本：`GET /nacos/v3/auth/user/list` 无 token 出 `pageItems` → `nacos_authscope_poc.py --check-only`，禁止直接 Jasypt。  
下堆立刻 `heap_cred_scan.py`。测完临时路由 `DELETE`+`refresh`。

## 1. 手法总表（必须掌握）

### A. 侦察与文档面

| ID | 手法 | 要点 |
|----|------|------|
| A1 | 凭据/TOTP/回调 IP 清单化 | 目标信息文件、对接文档、回调 IP 当作**不同入口/节点视图** |
| A2 | ShowDoc `t=` 直链 | 索引失效时仍可能直连文档 API；提取 merchant_id / DSA 私钥 / 验签规则 |
| A3 | OpenAPI 还原 | `/v3/api-docs`、`/open/v2/api-docs` 可脱离 ShowDoc 还原签名参数 |
| A4 | 前端 chunk 隐接口 | 下载业务 JS，补出隐藏路径与请求头（如 `User-Target: client`） |
| A5 | 验证码绕过 | `captchaEnabled:false` 或任意非空 `vCode` 可登录时，扩展撞库/会话面 |

### B. Actuator 控制面

| ID | 手法 | 要点 |
|----|------|------|
| B1 | 全端点枚举 | `health/env/beans/mappings/configprops/metrics/loggers/conditions/threaddump/heapdump/nacosdiscovery/nacosconfig/serviceregistry/logfile/httptrace` |
| B2 | 未授权写 | `POST gateway/routes/{id}`、`POST gateway/refresh`、`POST loggers/*`、`POST refresh`、`POST serviceregistry` |
| B3 | 路由三层分裂 | **definition**（routedefinitions）≠ **active**（gateway/routes）≠ **trigger**；LB 多节点内存态导致漂移 |
| B4 | SpEL / RCE 原语 | 路由 filters 写入 `#{...}` / `T(java.lang.Runtime).getRuntime().exec(...)` / `@systemProperties`；先验证求值再追 shell |
| B4b | **CVE-2025-41243** Gateway SpEL 属性篡改 | WebFlux + 暴露 `gateway` + 未鉴权 → 改 env / 读 `@environment`（CVSS 10）；详见 `春府·新伤.md` |
| B4c | **CVE-2026-40976** Boot4 默认链失效 | Boot 4.0.0–4.0.5：actuator-autoconfigure 且无 health、无自定义 Security → 可能整站匿名；手法 §2 |
| B4d | **CVE-2026-22733** CF Actuator 路径绕过 | 业务挂在 `/cloudfoundryapplication/**` 下可鉴权绕过（条件窄）；手法 §3 |
| B5 | stale route | 历史危险 definition 残留；按 **pinned IP** 分线触发，勿混节点 |
| B6 | local-view | 不同入口路径倾向不同 HOSTNAME；用矩阵记录「入口→节点」 |

### C. 路径规范化 / 白名单旁路（核心）

| ID | 手法 | 示例 |
|----|------|------|
| C1 | 点段编码旁路 | `/auth/..%2Factuator/env`、`/auth/%2e%2e/actuator/...` |
| C2 | 白名单后缀穿越 | `/system/gateway/route_range_conf/refreshInRule/../../../../actuator/*` |
| C3 | refreshInRule 特化 | 白名单仅精确匹配 `refreshInRule`（无 `/**`）仍可 `../` 规范化到 actuator |
| C4 | 多前缀交叉 | `/server/`、`/test/`、`/auth/`、`/open/` 前缀 + `..%2F` 对比节点命中率 |
| C5 | Range 分块 heapdump | `Range: bytes=a-b` → `206` + `Content-Range`；**按 IP+HOSTNAME+total 分桶**，禁止混 dump |

### D. 内部代理 / SSRF 候选

| ID | 手法 | 要点 |
|----|------|------|
| D1 | `/agg-c` | 未授权内部路径聚合（常为 GET 型）；先证业务路由转发，再测任意 URL |
| D2 | `/test*` vs `/server*` | metrics 命中 `WebClientRequestException` 的更像真代理；`/server/uri` 可能仅回显 |
| D3 | notify_url / byGateway / 回调注入 | 开放平台回调字段作 SSRF/选路 |
| D4 | 调试控制器 | mappings/metrics 定位后逐个边界测试，勿当已通 SSRF |

### E. 开放平台签名与业务面

| ID | 手法 | 要点 |
|----|------|------|
| E1 | 泄露私钥重签 | DSA/RSA 本地签名 → `getBalance` / 查单 |
| E2 | 签名预言机 | 匿名接口接受 `pri_key` 返回签名 → 闭环读余额 |
| E3 | 签名串还原 | 如 `DSA(merchant_id)`、`merchant_id+merchant_order_no` |
| E4 | 弱校验 mock | 如 `repayin/mock` 仅要求 `sign` 非空 |
| E5 | 可信头伪造 | `X-Forwarded-For` / `X-Real-IP` / `Forwarded` 伪造白名单 IP，改变验签/业务分支 |
| E6 | 推进到状态变更 | `paid` / `re` / `findByNoList`；从读余额→查单→改状态 |

### F. 配置 / 内存 / 文件读

| ID | 手法 | 要点 |
|----|------|------|
| F1 | env/configprops 挖矿 | Redis/Nacos/Jasypt/日志路径/运行用户 root |
| F2 | heapdump 离线 | **必须** `heap_cred_scan.py`（正则 + 蓝鸟对象图）。`heapdump_strings.py` 只是粗扫，不算拆完 |
| F3 | Jasypt 解密 | 算法常见 `PBEWITHSHA1ANDRC2_40` + `NoIvGenerator`；口令恢复后批量解 `ENC(...)` |
| F4 | 双编码读文件 | `/file/statics/**`：raw `../` / `%2F` / **`%252F`** 分层；目标 jar、gc.log、nacos logs、jvmdump |
| F5 | 日志体采样 | `logging.request.body-enabled=true` 时优先追 logfile / 物理日志路径 |
| F6 | Redis 协议指纹 | 先 TCP/RESP/HELLO/TLS 指纹，再 AUTH；「可达≠可 redis-cli」 |

### G. 作业流（报告级）

| ID | 手法 | 要点 |
|----|------|------|
| G1 | 多子代理并行 | 控制面 / 开放平台 / 离线 dump 分线，主线程统一裁定 |
| G2 | 临时路由清理 | 测完 `DELETE` + `refresh`，恢复默认路由 |
| G3 | 证据分桶 | `evidence/roundN/` + IP/HOSTNAME/Content-Range 元数据 |
| G4 | 优先级漂移 | route 不稳时切 dump/日志/文件读；拿到明文后回打 Redis/Nacos/下游 |

## 2. 推荐攻击面排序（通用）

1. **白名单旁路 → actuator 读写**（refreshInRule / `..%2F`）  
2. **Range heapdump 分桶 + Jasypt/Redis 明文**  
3. **双编码文件读**（jar / 日志 / jvmdump）  
4. **开放平台：文档私钥 / 签名 oracle / 可信头**  
5. **gateway SpEL stale route**（pinned IP local-view）  
6. **agg-c / test 代理边界**  
7. **Nacos / 下游配置 → DB**

依赖安装（首次）：

```bash
# vendor 由安装脚本拉取；无 brew 时用 Adoptium tarball

pip3 install --user requests pycryptodome  # 可选：纯 Python 解密辅助
```
