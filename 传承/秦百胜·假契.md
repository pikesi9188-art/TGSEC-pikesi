# 秦百胜·假契（Playbook）

配套 Skill：`杀招/秦百胜·回响/SKILL.md`  
授权：仅 `授权范围` 内目标。

## 1. 手法定义

伪造支付异步通知（notify/callback），使业务系统在**未收到真实资金**的情况下将订单置为已支付，从而完成发卡、加余额或开通权益。

高价值形态：**业务站不直接验支付签，只信中转站的 success** → 伪造打穿中转/插件即可驱动上游入账。

旁路形态（PHP autopay）：`checkGatewayIP` 误信 **`CF-Connecting-IP`** → 直连**源站 IP** 伪造成网关 → `CreateTransaction` 伪成功回调 / `CreateUpdateUser` 开 ADMIN。详见 `血路·雾墙.md`（先摸 `selfAPI`）。

```text
业务下单 → [支付中转] → 支付插件(VPay/vmqphp/Epay/…)
                ↑ 伪造回调（验签弱）
                └─ 中转回 success → 业务 COMPLETED → 余额/卡密
```

参考确认口径（学习样例）：

`Ocenza/sub2api 下单 → p…支付中转 → VPay/vmqphp 回调签名伪造 → p 中转返回 success → Ocenza 订单变 COMPLETED → 余额到账`

## 2. 七步执行清单

- [ ] ① 授权 + 探针单（`out_trade_no`、金额）
- [ ] ② 发现 `notify_url` / callback 路由 / 通道名
- [ ] ③ 画链：直连 or 中转
- [ ] ④ 验签矩阵（空/true/错签/改金额/合法签）
- [ ] ⑤ 中转优先（若有 VPay/vmqphp/p）
- [ ] ⑥ 验证入账（卡密/余额/COMPLETED）
- [ ] ⑦ STATUS + `forge_repro` 固化

## 3. 验签矩阵表（复制到 STATUS）

| # | 变体 | Content-Type | 期望若弱 | 本站实绩 | 订单状态 |
|---|------|--------------|----------|----------|----------|
| 1 | 无 sign | form/json | 接受或明确缺参 | | |
| 2 | sign=（空） | form | 同左 | | |
| 3 | sign=true | form | 松散比较绕过 | | |
| 4 | "sign": true | json | 类型混淆绕过 | | |
| 5 | sign=1 | form | 宽松解析 | | |
| 6 | 随机 MD5 | form | 应失败（对照） | | |
| 7 | money±0.01 + 通签手法 | 同成功变体 | 应金额校验失败 | | |
| 8 | 合法 MD5(key) | form | 有 KEY 时必测 | | |

## 4. 通道速查

### 4.1 异次元 / Epay（直连）

```text
POST /user/api/order/callback.Epay
Content-Type: application/json
{"pid":"1","trade_no":"t","out_trade_no":"<oid>","type":"alipay",
 "name":"x","money":"<money>","trade_status":"TRADE_SUCCESS",
 "sign": true, "sign_type":"MD5"}
```

- 成功：body 含 success + 查单已付  
- 硬化：`非法签名` / `is_string($sign)` → **先支付栈取钥**（`宝黄天·回灌.md`），再源码 KEY；不要停假付结案

### 4.1b 彩虹易支付 · submit 参数原样回放（免 KEY）

指纹：`/pay/rainbow/return` · `/pay/rainbow/notify` · 充值 302→彩虹 `submit.php`。  
手法：建充值单 → 从 submit URL 抽出 `pid/type/out_trade_no/notify_url/return_url/name/money/sign/sign_type` → **原样**打业务 return + notify → **余额增值**（硬条件）。  
不依赖爆破商户 KEY；与松散 `sign:true` 并行测。详卡：`酒虫·回放.md` · 参考 （开源包不收个案摘记）。  
勿与 `易付·回响.md`（打网关 `/pay/notify/{payId}/`）混淆。

### 4.1c′ 硬编码系统令牌 + CF-Connecting-IP 加款（非 notify）

源站直连 + 伪 `CF-Connecting-IP` + 源码 `ARSYSTEMTOKEN`/`accessToken` + `module=manualAngPao`（或同类加款）→ 任意用户资金写入。详卡：`和稀泥·加款.md` · 同族见 `血路·雾墙.md`。

### 4.1c USDT 共享收款 · 付款地址归属劫持（非 HTTP 验签）

若平台用链上 `from` 匹配用户绑定钱包入账（共享收款址），假回调硬化（如 `1002`）后仍可能被 **同址多绑 / 无所有权证明** 抢走充值。详卡：`马鸿运·归属.md` · Skill `马鸿运·稳币` · `炼蛊房/usdt_attr_hijack.py`。与本章假支付 **互补并行**，勿因 notify 阴结案。

### 4.2 TokenPay

```text
Header: Signature: true
POST <notify_url>   # 常带订单 UUID
```

前台可能隐藏 TokenPay，需 `payCheck` / 强制 payway。

### 4.3 VPay / vmqphp + 中转（本手法补完重点）

1. 下单后记录中转域、支付单号、回调路径  
2. 读 vmqphp/VPay 验签实现（多为 MD5 拼接 + key）  
3. 对 **插件 notify** 投伪造包，直到中转日志/响应为 success  
4. 查业务订单；若业务另有二次 notify，对二次再跑矩阵  
5. 以「余额到账 / COMPLETED」为成功，不以中转 HTML 为准

### 4.4 合法签（有 KEY）

```text
params 去 sign → 按键名排序 → 拼 k=v&…&key=SECRET → md5 小写
POST 回 notify，字段集与通道文档一致
```

KEY 来源（按便宜顺序，**禁止爆破**）：

| 序 | 面 | 说明 |
|----|----|------|
| 1 | **应用日志** | PHP/Laravel 发卡：`/storage/logs/`、`laravel.log`、`/runtime/logs/`、`/debug/`。异常栈常把 `merchant_pem` / epay `key` / `pid` 打进日志。`composer.json` 只认栈，不是钥。 |
| 2 | `.env` / `Config.php` / 备份 | `sensitive-dir-dump` L2 只摘片段 |
| 3 | 支付栈 admin | `宝黄天·回灌.md` |
| 4 | 源码 / DeepAudit | `da_pipeline.py pay-hint` |

**F-01 形态（2026-08 审计）**：严签矩阵全阴 ≠ 结案。日志里已有商户钥时，直接走本节合法签 → 未付单标已付 + 自动发货。成功口径仍是出卡，不是 notify 回 `success`。  
并行：游客查单若对**已付单**回 `secret`/`info`，走 `faka-card-shop-pentest`（F-02），与假付互补。

## 6. 停止条件

| 条件 | 动作 |
|------|------|
| RSA2/严字符串比较 + 无 KEY | **先**支付栈取钥；仍无 KEY 再 STATUS 写「验签硬化」，换主机/后台/上游 |
| 假付成功但手动发货无卡 | 标明无卡，转后台导卡 |
| 无 Web notify（纯链上/TG） | 本手法不适用 |
| 未授权 | **禁止执行** |

## 7. 与其它手法衔接

| 前置/后置 | 说明 |
|-----------|------|
| 客户端改价 | 先改 `price` 再假付（需服务端未重算） |
| 弱口令后台 | 直接改余额/发货，可跳过假付 |
| **日志/composer 泄钥** | PHP 发卡先 `sensitive-dir-dump`；日志出 `merchant_pem`/epay key → 本节合法签（先于支付栈） |
| **支付栈旁站取钥** | 主站严签且日志无钥 → 聚合支付 admin → 商户 key → 合法签回灌（`宝黄天·回灌.md`） |
| CSRF 挡下单 | 先破 TOKEN/会话，再进入本链（如 hyzwfw） |
