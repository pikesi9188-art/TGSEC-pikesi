## 🔥 一、React2Shell (CVE-2025-55182 / CVE-2025-66478) — CVSS 10.0

### 根因
React **Flight协议** (RSC传输格式) 的不安全反序列化 + 属性所有权校验不足。

### 攻击原理 (JavaScript thenable + 原型链污染)
1. **Fake Chunk (入口)**: 构造恶意RSC payload(JSON), 伪造一个带 `then` 属性的对象
2. **thenable gadget**: JS的 `await` 会对待 `then` 的对象执行其 `then()` 方法, 利用这个行为劫持控制流
3. **原型链污染 → RCE sink**: 通过继承链劫持, 把恶意逻辑注入到服务端执行

### 受影响版本
- `react-server-dom-webpack/turbopack/parcel` (19.0.0, 19.1.0, 19.1.1, 19.2.0)
- Next.js 15.x (全部), 16.0.0-16.0.6, 14.3.0-canary.77+

### 高危场景 (与加密网赌直接相关)
- 启用 **App Router** 的Next.js应用(默认配置即可打)
- 加密网赌/加密交易所/Web3前端 (几乎全用Next.js+React)

### 实战情报
- 披露后**数小时内**出现野外利用, 800+攻击IP
- 已被用于**渗透区块链基础设施** + 服务器**挖矿木马**投放
- 默认认证绕过: 无需登录, 一个构造的HTTP请求直接RCE

## 🔥 二、CVE-2026-75604 / GHSA-p293-qw3h-jr36 (React2Shell2) — CVSS 9.0

### 影响
Next.js `>=13.4 <15.5.24` 或 `>=16.0 <16.3.3`
**仅Windows原生宿主**, 同时用 Pages Router + App Router(无Cache Components)
默认文件系统缓存 + 动态ISR路由 + 兼容closure-bound Server Action

### 攻击链 (POC已验证, 见 poc.py)
1. **`%5C`路径穿越**: App Router对URL编码反斜杠处理缺陷, `..%5C`穿越读文件系统
2. **读Server Action密钥**: 穿越读取 `server-reference-manifest` 文件, 拿到 `encryptionKey`
3. **伪造加密payload**: 用泄漏密钥 AES-GCM 加密恶意 Server Action bound 参数 (`$1:constructor:constructor` 原型链)
4. **触发RCE**: 提交伪造action, 执行 `cmd.exe /c 任意命令`, 结果回调攻击者

### 修复版本
- **15.5.24** (Maintenance LTS)
- **16.3.3** (Active LTS)

## 🔥 三、Image Optimization API AVIF RCE (GHSA-2xp9-vwfh-vxw4)

### 根因
底层 `libheif` 库被 `sharp` 引用, 优化攻击者控制的 **AVIF 图片**时触发RCE。

### 利用方式
上传恶意AVIF图片到 Next.js Image Optimization API → 服务端优化时RCE。
**未认证**, 任何能触发图片优化的Next.js站点都中招(头像上传/图片代理等常见功能)。

### 修复
补丁版本**禁用AVIF优化**直到上游修复。(与CVE-2026-75604同批次8月发布)

## 🎯 与加密货币网赌平台攻防的关系

### 为什么是"打加密网赌平台"的王牌
1. 加密货币网赌/交易所/Web3博彩前端**99%用 Next.js** (Sportbet等均为Next.js)
2. React2Shell (CVSS10) 打**默认配置**, 无需登录, 最通用
3. 已被证实攻击者在**区块链基础设施**上利用React2Shell挖矿
4. 拿下前端 → 可下一步渗透后端API/钱包/私钥

### 利用前提判断 (FOFA指纹)
- 找 Next.js 特征: `X-Powered-By: Next.js`, `/_next/static`, `__NEXT_DATA__`
- 确认RSC: 响应含 `application/rsc` / `flight` 编码特征
- CVE-2026-75604还需确认 **Windows** (平台/ServerHeader/端口特征)

### 检测思路
- 版本指纹: 检查 `/_next/` chunk资源路径版本号
- RSC端点: `?_rsc=` 参数 / `text/x-component` content-type
- 打点验证: 无害payload只触发反序列化, 不执行命令

## 🛡️ 防御建议 (知识留存)
1. Next.js升级到 **15.5.24** 或 **16.3.3+**
2. 若无法升级: 禁用AVIF优化、限流图片API、WAF拦截RSC异常请求
3. 监控Flight协议端点异常反序列化payload
4. Windows部署注意路径穿越面, 避免Pages+App Router混用

## 🔥 四、Next.js 中间件认证绕过 (CVE-2025-29927) — 打后台神器

### 影响
Next.js `<12.3.5, <13.5.9, <14.2.25, <15.2.3`
CVSS **9.1** | EPSS **92.56%**
自托管 + `next start` + `output: standalone` 场景

### 核心原理
Next.js 用 `x-middleware-subrequest` 内部头防止中间件无限循环(用于SSR内部请求)。
**框架盲信该头不验证来源** → 攻击者伪造该头, 服务端跳过整个中间件层 → **绕过所有认证/授权逻辑**。

### 利用 (一行打穿)
```
GET /admin HTTP/1.1
x-middleware-subrequest: middleware
```
直接访问受保护的管理路由, 无需登录。

### 对加密网赌平台的意义
很多加密网赌/交易后台用 Next.js middleware 做权限控制(管理路由保护)。
**一个伪造头直接进后台**, 是打管理后台最廉价高效的手段。

## 🔥 五、Next.js 2026年7月安全发布 (9个CVE, 修复于15.5.21/16.2.11)

Next.js历史上最大单批发布(9个CVE), 4个高危。首个预公告安全发布模型。

### 完整清单
| CVE | 类型 | 严重性 | 描述 |
|-----|------|--------|------|
| CVE-2026-64641 | DoS | High | App Router + Server Actions, 构造请求CPU耗尽, 阻断进程后续请求 |
| CVE-2026-64642 | **中间件/代理绕过** | High | Turbopack + 单locale, 绕过middleware/proxy认证 |
| CVE-2026-64645 | **SSRF** | High | rewrites/redirects用请求可控的外部hostname → SSRF |
| CVE-2026-64649 | **SSRF** | High | Server Action相关SSRF |
| CVE-2026-64643/64644/64646/64647/64648 | DoS/缓存/标识泄露等 | 中危 | 需查看各GHSA详情 |

> 编号范围 CVE-2026-64641 ~ CVE-2026-64649 (分批披露)

### 组合利用思路 (打加密网赌)
- **CVE-2026-64642** = CVE-2025-29927的"续作", 又一个中间件绕过, 继续打后台
- **CVE-2026-64645/64649(SSRF)** = 探测内网/打云元数据(169.254.169.254)/读后端API
- SSRF + 中间件绕过组合 = 加密网赌后台 + 云环境双收割

## 🔥 六、打加密网赌平台的完整武器栈 (汇总)

### 优先级排序 (从肥到易)
1. **CVE-2025-29927 / CVE-2026-64642**: 一个伪造头绕过后台认证 (最廉价)
2. **CVE-2025-55182 (React2Shell)**: 默认配置RCE (最通用, CVSS10)
3. **CVE-2026-64645/64649 (SSRF)**: 打云元数据/内网 (要配合)
4. **GHSA-2xp9-vwfh-vxw4 (AVIF RCE)**: 上传图即RCE (Image API通用)
5. **CVE-2026-75604 (React2Shell2)**: Windows路径穿越RCE (仅Windows)

### 指纹判断 (FOFA/手工)
- Next.js: `X-Powered-By: Next.js`, `/_next/static`, `__NEXT_DATA__`
- RSC: `_rsc=` 参数, `text/x-component` content-type
- 中间件: 首字判定响应头中有无 `x-middleware`
- Turbopack: 构建资源特征

### 版本判断
- 检查 /_next/ chunk 路径版本号
- HTTP响应头 Server 字段
