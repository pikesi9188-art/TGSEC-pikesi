# 案卷 Triage（A/B/C）与攻击手法索引

> 目的：开案 30～60 分钟内定级，避免所有站同时半吊子空转。  
> 模板：`案卷/_templates/TRIAGE.md`  
> 脚本：`python3 炼蛊房/case_triage.py`  
> Skill：`杀招/春秋蝉/SKILL.md`
> 复盘：`案卷/_templates/RETROSPECTIVE.md` + `retrospective.json`

---

## 1. 分级标准

| 级 | 含义 | 典型特征 | 默认动作 |
|----|------|----------|----------|
| **A** | 本周主攻 | 弱签支付 / 未锁 PocketBase / Spring Actuator 全链 / 明文密钥 / 可匿名高价值 API | 按专用 Playbook 打穿到可验证结论 |
| **B** | 有苗头、缺条件 | 能下单/注册；回调严签；缺会话；缺中转授权；后台路径未找到 | 写清 **唯一复工条件** 后可挂起 |
| **C** | 冷冻 | 全程 CF+Turnstile 且无会话；严签+无 KEY+无源码；无源站；第三方中转未授权 | **停进攻**，只保留复工条件 |

规则：

1. 一案一卷只标一个主级；可附「旁路级」（如支付 B、主机 C）。  
2. **挂起 = 进度**：C/B 写好复工条件即算本轮完成。  
3. 同时 ACTIVE 的 A 级建议 ≤ 2。  
4. 用户说「暂停」→ 全案进攻面停，Triage 可继续改文档。

---

## 2. 复工条件（写死、可勾选）

每条必须 **可验证、单点**，例如：

- [ ] 浏览器导出完整 `USER_SESSION`（JWT 含 **两个** `.`）并经 `session_import` 校验通过  
- [ ] （若跳转中转尚未进 scope）跑 `scope_expand` / `pay_matrix --pay-url` 静默并入后继续  

- [ ] 拿到源码/Git/备份 → 跑 DeepAudit SAST  
- [ ] FOFA/历史解析出现非 CF 源站 IP  
- [ ] （黑洞/敲门面板）持有 SPAKE/HMAC 敲门材料，或发现未走 nftables DROP 的入口  
- [ ] （autopay/CF 头链）源站 IP 可达且网关白名单 IP 已知  
- [ ] （彩虹/号铺）充值 submit 捕获完整 sign 参数集，return+notify 回放后余额增值  
- [ ] （USDT 共享收款）双账号同绑自控地址无去重，且最小额入账到非预期 uid  
- [ ] （GVA）注册 `authorityId=888` 可登录，或 jwt-key 可伪造 admin JWT（**未**改原 admin 密）+ 脱敏 notify  
- [ ] （FastAdmin 代付）`part/index` 已拖树且真结算写口已钉，或已写清 journal-only + 缺 google_key 的复工条件  
- [ ] （芋道代付 / ruoyi-vue-pro）`mock-enable` 已用 `test1` 等读到超管 profile，或已写清 mock 关 + 任意身份打 file-config 的复工条件  
- [ ] （硬编码 Token+CF-IP）源站可达 + 伪头放行 + 自控用户余额增值  
- [ ] （TG bot 越权）USER 写 admin/telegram/bot 成功；webhook 劫持须另确认  
- [ ] （TG NEXTAUTH / 技能沙箱）文档凭据或 `admin_session` 已拿；沙箱 RCE / secret 横移另记  
- [ ] 挖到随机后台路径且弱口令字典就绪  
- [ ] 支付 KEY / `app_secret` 从配置或白盒命中  
- [ ] （网狐/TP5 登录盲注）本站 oracle 三码已标定 + 四库 SELECT 1 地图；Manager GRANT 拒后已换 Web/GM/WS  

禁止写空话：「继续挖」「再试试」。

## 6. 复盘知识库与自动推荐

每个已结束、部分成功或暂停的案卷都应建立**脱敏**复盘条目，记录：
技术与业务标签、前置条件、有效/无效信号、停止条件、修复建议，以及仅含相对
路径或哈希的证据引用。严禁把 token、Cookie、密钥、原始请求响应或数据库内容写入
`retrospective.json`。

```bash
# 为已存在案卷初始化复盘（默认 PAUSED）
python3 炼蛊房/case_triage.py retrospect init --case <站_日期> --outcome PAUSED

# 追加可复用、脱敏的判断
python3 炼蛊房/case_triage.py retrospect set --case <站_日期> \
  --tag payment-callback-forgery \
  --effective-signal "支付回调与订单状态存在可验证差异" \
  --stop-condition "同一验签矩阵无差异结果后停止复试" \
  --remediation "服务端严格校验订单金额、商户与签名"

# 新案 init 会自动显示匹配复盘；也可主动查询
python3 炼蛊房/case_triage.py recommend --case <站_日期>
```

推荐只读取历史 `retrospective.json` 中的脱敏摘要，按当前 Triage 的
`techniques` 与附加 `--tag` 匹配；它只用于选择 Playbook 和停止条件，
不能替代授权校验或人工结论。
