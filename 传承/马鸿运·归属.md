# USDT 充值归属劫持 + 隐藏 paytype/deposit — 手法

> 笔记原图：（开源包不收个案摘记）  
> 挂靠：`秦百胜·假契.md` · `杀招/马鸿运·稳币` · `杀招/秦百胜·回响`  
> 工具：`炼蛊房/usdt_attr_hijack.py`  
> **仅授权 targets**；真链充值只用**自控测试地址/自有小额**；禁止对无关第三方地址批量「收割」。

---

## 0. 一句话

平台若用「链上**付款方地址** ↔ 用户绑定钱包」做 USDT 入账归属，且 **同一地址可绑多账号、无所有权证明、入账免人工**，则攻击者可把他人常用付款地址绑到己号 → 受害人打款到平台收款地址时 **余额进攻击者口袋**。  
并行面：服务端对 `paytype`/`deposit` **无白名单**，前端隐藏的通道仍可建单，作攻击面放大器（ alone 未必立刻加余额）。

与假支付分工：假支付打 **HTTP notify 验签**；本卡打 **链上入账归属逻辑**（常无 notify，或 notify 已硬化仍可通）。  
与展示层分工：受害人屏幕上的收款址被换成攻击者址 → `血神子·账.md`（`fund-edge-ops`）。两卡都打，一张阴不算资金面结案。

---

## 1. 适用指纹

| 层 | 指纹 |
|----|------|
| 充值模型 | 共享平台收款地址（TRC20/ERC20）；按 `from` / `payer` / `sender` 匹配用户 |
| 绑定 API | `bindUsdt` / `usdtCreate` / `wallet/bind` / `setDefaultAddress` / `rechargeAddress` |
| 注册门槛 | guest / 手机邮箱随意注册、无 KYC、可批量开号 |
| 去重缺失 | 同一地址可绑多账号；或「后绑覆盖 / 默认激活优先」可被抢 |
| 隐藏通道 | 前端只展示部分 `paytype`，API 仍接受 `3/5/6/7` 等；`deposit` 手工建单 |
| 对照阴性 | 假回调全局 `1002` / 严签 → **仍要测本卡**，勿因假付不通结案 |

同时满足「共享收款地址 + 按付款地址归属 + 可自助绑定」再套本卡。

## 2. 攻击链（标准形态）

```text
① 注册攻击者账号 A（低门槛）
② 绑定「目标付款地址」W → 设为默认/激活
③（对照）账号 B 再绑同一 W —— 若也成功 → 无去重（高危确认）
④ 受害人（或自控钱包）从 W 向平台收款地址打 USDT
⑤ 监听/入账任务按 from=W 查绑定 → 入账到 A（非受害人真实会员）
⑥ 立刻提现/转出（自动流常无人工拦截）

组合（中危放大器）：
  枚举隐藏 paytype → 建 deposit 单 → 收款信息绑定攻击者侧资料
  → 诱导/误导受害者按单转账（与 ①–⑤ 叠加）
```

笔记口径（脱敏）：曾见按绑定自动入账约 **1336** 元量级到攻击者侧——证明「自动归属」已闭环，不是理论推演。

---

## 3. 原理（学什么）

```text
合法意图：用户先绑定自己的付款钱包 → 链上扫到 from=该钱包 → 记入该用户

缺陷组合：
  1. 绑定无所有权证明（无小额挑战 / 无签名 message / 无链上验证）
  2. 地址全局唯一约束缺失（或多账号可同时「默认激活」）
  3. 入账权威源 = 「绑定表 + from」，不核「订单用户」或「收款备注/金额订单」
  4. 无人工阈值；入账后可秒提
```

| 设计 | 安全 | 危险 |
|------|------|------|
| 专属收款地址（每用户一址） | 归属天然隔离 | — |
| 共享收款 + 订单金额/备注匹配 | 需防撞单 | 比纯 from 好 |
| 共享收款 + **仅 from 绑表** | — | **本卡主杀伤面** |
| 绑定前签 `Login`/`Bind` 消息 | 证明控钥 | 仅前端展示地址不够 |

隐藏 `paytype`：前端隐藏 ≠ 服务端禁用；建单扩大「可诱导收款信息」与未来通道复活面；假回调已修时单独未必造成直接加余额。

## 4. 复现步骤（授权作业清单）

**硬约束**：只用你控制的两把测试钱包 `W_test` / `W_ctrl`；小额自充自证；不扫链批量绑陌生人热地址。

```text
① scope 确认；充值/钱包 API 异 host → scope_expand 静默并入
② 开账号 A、B（或 guest）；记初始余额
③ A 绑定 W_test，设默认；落 bind 请求/响应
④ B 绑定同一 W_test：
     - 成功 → 无去重（L1）
     - 拒绝「已占用」但 A 仍可改绑/抢默认 → 记竞争窗口
⑤（可选）枚举 paytype=0..16 / deposit 类建单；对照前端可见集合差分
⑥ 自控：从 W_test 向平台收款地址打最小额（授权额度内）
⑦ 查 A/B/受害人对照号余额与流水：谁入账 = 归属裁决
⑧ 固化：STATUS + 案卷/usdt_attr/；提现面若测须先问成本
```

### 成功口径

| 级 | 标准 |
|----|------|
| L0 | 指纹：共享收款 + 绑定 API + 低门槛注册 |
| L1 | 同址可绑多账号 **或** 可抢默认激活 |
| L2 | 自控小额从绑定址打入 → **入账到非预期账号**（硬条件） |
| L3 | 入账后可提现/转出/消费（资金出逃面） |
| P1 | 隐藏 paytype/deposit 可建单（攻击面； alone 不算资金洞） |
| P2 | 隐藏通道建单信息可诱导到攻击者可控收款要素（组合） |

仅「能绑定」不算完成；**L2 余额错归属**才是主洞成立。

### 失败对照

| 结果 | 含义 | 下一步 |
|------|------|--------|
| 同址绑第二账号被拒且全局唯一 | 去重在 | 测「解绑竞争 / 默认覆盖 / 大小写·链前缀混淆」 |
| 专属收款地址 per user | 本卡主链不适用 | 转假支付 / 金额撞单 / 备注注入 |
| 绑定要签名挑战且服务端验 | 所有权在 | 转其它面 |
| 入账按订单号/唯一金额窗口 | 归属模型不同 | 测撞金额窗口、过期单复用 |
| 假回调 1002 但本卡 L2 通 | 预期 | STATUS 写「假付硬化、归属逻辑未修」 |

## 5. 探针命令

```bash
# 同址双账号绑定差分（需两枚 Token + 绑定路径）
python3 炼蛊房/usdt_attr_hijack.py bind-dup \
  --base https://授权站 --case <案卷> \
  --token-a "$TOKEN_A" --token-b "$TOKEN_B" \
  --address TTest...YourControlled... \
  --bind-path /api/wallet/usdt/bind --bind-field address

# 隐藏 paytype 枚举（对照前端可见集合）
python3 炼蛊房/usdt_attr_hijack.py paytype-enum \
  --base https://授权站 --case <案卷> --token "$TOKEN" \
  --create-path /api/deposit/create --paytype-field paytype \
  --visible 1,2,4 --probe 0-16
```

产出：`案卷/<案卷>/案卷/usdt_attr/`。

## 6. 与其它手法对照

| 手法 | 打点 | 本卡关系 |
|------|------|----------|
| 假支付 `sign:true` / 合法签 | HTTP notify | **互补**；假付通了仍建议扫归属 |
| 彩虹 submit 回放 | return/notify 预签名 | 法币/网关面；USDT 共享收款另测本卡 |
| autopay + CF 头 | 源站可信头 | 网关白名单面 |
| Epusdt/TokenPay | 中间件订单 | 若中间件按 from 绑商户用户 → **同源逻辑** |
| 免费领取礼包 | claim-free | 无链上；别混 |

分流口诀：

```text
有 notify/callback → 先 pay_matrix
有 USDT 共享收款 + 绑定钱包 → 并行本卡
假付全阴 + 绑定无去重 → 本卡升 A
```

## 7. Triage

| 现象 | 级 | 复工条件 |
|------|----|----------|
| 共享收款 + 可绑付款址 + 低门槛注册 | **A** | 自控双账号 bind-dup + 最小额 L2 |
| 仅能绑、同址第二号被拒、专属收款 | 本卡 **C** | 换假付/主机；或出现「可抢默认」再复工 |
| 假付 1002 硬化但绑定无去重 | **A**（本卡） | L2 自证错归属 |
| 隐藏 paytype 可建、入账未通 | **B**（面） | 通道复活 / 与归属组合复测 |

复工条件示例：

- [ ] `bind-dup`：同址两账号均 2xx 或可抢默认  
- [ ] 自控 `W_test` 最小额入账到非预期 uid  
- [ ]（组合）隐藏 paytype 建单回包含攻击者侧收款要素

## 8. STATUS 一句模板

> USDT 归属：共享收款 + 按 from 绑表；账号 A/B 同绑 `W_test`（无去重）。自控小额从 W_test 打入 → 入账 uid=A（预期应 B/受害人）。隐藏 paytype={…} 可建单；假回调 1002。证据：`案卷/usdt_attr/`。

---

## 9. 加固对照（识读 / 修复建议）

1. **地址全局唯一**：一址一用户；冲突拒绝并告警。  
2. **绑定所有权**：EIP-191 / TRON 等价签名挑战，或绑定前小额打标。  
3. **入账模型**：优先「专属收款址」或「订单金额+时间窗+用户确认」；禁止仅 from→绑表自动入账到可自助改绑账号。  
4. **paytype 服务端白名单** = 前端可见集合；禁用通道硬拒。  
5. **入账/提现风控**：新绑地址冷却、首笔人工、异常同址多号告警。
