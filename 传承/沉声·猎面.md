# gRPC 猎面手法

> 杀招：`沉声`  
> 探针：`炼蛊房/grpc_surface_probe.py`  
> 大爱仙尊专卡。参数/文档面仍走 `api-recon-and-docs`。  
> **禁止** HTTP/2 Rapid Reset（CVE-2023-44487）及任何 DoS。

---

## 1. 一句话

授权目标暴露 h2 / `:50051` / grpc-gateway 时：确认 `grpc-status` 传输 → 健康检查/反射是否匿名 → 网关 REST 转码是否把内部方法摊到 HTTP。

```bash
python3 炼蛊房/grpc_surface_probe.py --base https://授权站 --case <案卷>
# 明确是 gRPC 微服务、要探默认端口时：
python3 炼蛊房/grpc_surface_probe.py --base https://授权站 --case <案卷> --extra-ports
# 有 grpcurl（Qzino 类微服务）再列服务：
python3 炼蛊房/grpc_probe.py detect --target 授权站:443 --case <案卷>
python3 炼蛊房/grpc_probe.py list --target 授权站:443 --case <案卷>
```

落盘：`案卷/grpc/surface.json`

## 2. 档位

| 面 | L1 | L2 | 不要做 |
|----|----|----|--------|
| 传输 | POST `application/grpc` 出现 `grpc-status`（含 12 Unimplemented） | 仅 `--extra-ports` 才探同主机 `:50051`/`:9090` | 全端口扫；默认不打旁端口 |
| Health | `grpc.health.v1.Health/Check` 回 0 | — | — |
| 反射 | 正文/头出现 `ServerReflection` | 能 `list` 出业务 service 名 | 把反射当洞（只是枚举器） |
| 网关 | `/v1/` JSON、swagger、`.proto` 200 | 无票调用 `admin`/`internal` 得业务 JSON | Rapid Reset |
| 信任头 | — | 手测 `x-user-id` 等是否穿到后端（有身份回矩阵） | 对无关服务打 |

`Unauthenticated(16)` / `PermissionDenied(7)` = 鉴权在。  
`OK` + 业务字段无票 = L2。  
`InvalidArgument(3)` = 方法可达，改 payload 再测，不是阴性结案。

---

## 3. 成功口径

| 级别 | 口径 |
|------|------|
| L1 | `grpc-status` 或 grpc-web / 网关指纹 |
| L2 | 无票 Health/业务方法成功 **或** 反射列出内部 service **或** HTTP 转码打到 admin JSON |

---

## 4. 不要做

- Rapid Reset / 并发 RST 打满
- 未装 grpcurl 就报「无法检测」——探针用 HTTP/grpc-web 即可
- 反射开启当成 RCE
