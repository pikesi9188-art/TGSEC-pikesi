# RBAC 权限绕过手法

> 对象矩阵问 **对谁**（自己 vs 他人）。  
> 本卡问 **低权身份能不能做高权功能**（BFLA / 垂直越权 / 角色继承 / 方法覆盖 / 字段提权）。  
> 工具：`炼蛊房/rbac_bypass_probe.py`  
> Skill：`杀招/无极·职分`  
> 水平越权（换 uid 读他人）仍走 `万我.md` / `万我·信门.md`  
> 溯源改编：[Auth9 M-AUTHZ-02](https://github.com/c9r-io/auth9/blob/main/docs/security/authorization/02-rbac-bypass.md)（已泛化，不是只打 Auth9）  
> 红线：目标在 `授权范围`；默认不删已有用户、不改原超管密、不耗余额。

---

## 1. 一句话

已有**普通用户票**时，按五场景压管理 API：直接打管理端点 → 角色/权限注入 → HTTP 方法覆盖 → 批量/敏感字段 → JWT 权限过期判定。  
`authz-probe` 只覆盖「匿名 / 低权 GET 管理页」；本卡补管理读差分、方法矩阵、Mass Assignment 和 JWT 误报闸。  
**默认只 GET。** Override DELETE、空 POST 集合、批量 DELETE 他人都已从默认路径拿掉——旧版探针会误伤数据。

| 信号 | 例子 |
|------|------|

## 4. 五场景（大爱仙尊口径）

改编自 Auth9 的 5 个回归场景，端点按目标栈替换，不要死抄 `/api/v1/users`。

### 场景 1 — 直接权限绕过（BFLA）

低权票直接打管理功能。优先 **读**（列表/详情），写操作默认只打自控标记账号。

| 常见管理面 | 动作 |
|------------|------|
| `GET /api/admin/users` · `/admin-api/system/user/page` · `/prod-api/system/user/list` | 列用户 |
| `POST` 创建用户 / `DELETE` 删用户 | 仅 `--write`，且只用探针标记邮箱 |
| `PUT` 改租户 / 改角色 / 创建服务 | 配置格；成功后收云钥，不要改原超管密 |

**L2 成立**：低权票 200 + JSON 含他人列表 / 角色 / 权限（不是空 `{}`、不是登录页 HTML）。  
**不算**：401/403；200 但业务码「无权限」且无数据。

### 场景 2 — 角色继承 / 参数提权

JWT 或 `/me/permissions` 只声明 `viewer` / 普通用户时：

1. 解码票里的 `role` / `roles` / `permissions` / `authority`（只读 claims，默认不伪造超管票）
2. 请求体或 query 塞 `role=admin`、`roles[]=admin`、`authorityId=888`、`role_in_tenant=owner`
3. 再打场景 1 的管理读

**L2 成立**：参数注入后权限集变大，或管理读从 403 变 200。  
循环继承、缓存旧权限：以**实际接口差分**为准，不要只看文档角色树。

GVA 味（开放注册 + `authorityId`）立刻切静默提权卡，不要在本卡发明第三条链。

### 场景 3 — HTTP 方法绕过

同一路径分别打：

| 手法 | 预期安全行为 |
|------|----------------|
| `GET` 打本该 `DELETE`/`PUT` 的管理资源 | GET 也要鉴权，且不回敏感行 |
| `X-HTTP-Method-Override: DELETE`（以及 `X-Method-Override` / `X-HTTP-Method` / `?_method=DELETE`） | 不执行 DELETE |
| `PATCH` vs `PUT` | 权限检查一致 |
| `OPTIONS` | 只回允许方法，不执行业务、不泄完整用户 |

**L2 成立**：假 id 上 Override 与 POST 差分且打出管理 JSON，或 GET 打出管理数据。  
默认**不**发 Override DELETE。`--method-probe` 只打 `__se_rbac_noexist__`。`--write` 只删本轮标记号。

### 场景 4 — 参数级权限（批量 + 字段白名单）

| 打法 | 成功口径 |
|------|----------|
| 批量 `ids: [自己, 他人]` 删/改 | 他人那条也被改（他人 × 写） |
| 更新自己资料时带 `role` / `is_admin` / `authorityId` / `created_at` | `/me` 回读角色已升，或只读字段被改 |
| 嵌套资源 `/users/{id}/roles`、`/orders/{id}/refund` | 子资源单独过权 |

**L3 成立**：角色字段写进去且后续管理读成功；或批量里他人对象被改。  
给自己加款失败仍按对象矩阵去打他人 uid，不要停在本场景。

### 场景 5 — Token 权限与库不一致（误报闸）

JWT 把角色嵌在票里是常态：

| 现象 | 判定 |
|------|------|
| 撤权后，旧票在 `exp` 内仍能打管理面（未改 claim） | **PASS（预期）**，不是洞。记下剩余 TTL |
| 撤权后枚举 `ver`/`version`/`v`/`token_version`/`jti`（1..5）并重签，五次内复活 | **FAIL**（吊销逻辑可预测；与 TTL 误报不是一回事）。需已撞开 HS256 |
| 票已过期仍 200 | **FAIL** → 切 JWT 卡（弱签 / 不验 exp） |
| 重新登录/换票后新票仍带旧角色 | **FAIL**（签发源没读库） |
| 有 session 黑名单但 Redis 挂了全放行 | **FAIL**（fail-open） |
| 测试脚本直接签发非成员票能进租户 | 只说明签发钥匙在测试侧；**生产 Token Exchange 另测**，禁止当「未授权签发」结案 |

Auth9 原文 TTL=15 分钟。作业时以**目标票的 `exp-iat`** 为准，不要套 15 分钟。

## 5. 档位

| 档 | 动作 | 成功证据 |
|----|------|----------|
| **L1** | 低权票 + 管理 path 清单（OpenAPI/JS/默认表） | `案卷/rbac/surface.json` 有 endpoints |
| **L2** | 场景 1/3 读成功，或 Override/GET 打出管理 JSON | 低权 200 + 他人列表/角色字段 |
| **L3** | 场景 2/4 写成：角色字段生效或批量改到他人 | `/me` 角色升高，或他人对象被改 |
| **L3 禁** | 删已有用户、改原超管密、耗余额下单 | 先问 |

两轮同态 403 → 回对象矩阵换他人/换对象，或切专卡（GVA / 芋道 mock / Shop GT）。

## 6. 默认命令

```bash
# 有低权票就跑（默认只 GET 管理面 + /me；PATCH 角色字段；不删用户）
python3 炼蛊房/rbac_bypass_probe.py \
  --base https://授权站 \
  --token "$LOW_TOKEN" \
  --case <案卷>

# 若依/芋道前缀 + 自定义头 + 假 id 方法矩阵（--base 也可写成 https://站/prod-api）
python3 炼蛊房/rbac_bypass_probe.py \
  --base https://授权站 \
  --prefix /prod-api \
  --token "$LOW_TOKEN" \
  --header 'X-Token:…' \
  --admin-path /system/user/list \
  --profile-path /getInfo \
  --method-probe \
  --case <案卷>

# 批量只 POST 探测体，绝不 DELETE 他人
python3 炼蛊房/rbac_bypass_probe.py \
  --base https://授权站 \
  --token "$LOW_TOKEN" \
  --self-id 12 --other-id 13 \
  --case <案卷>

# 自控标记号：POST 创建并 DELETE 该标记（仍禁止删已有用户）
python3 炼蛊房/rbac_bypass_probe.py \
  --base https://授权站 \
  --token "$LOW_TOKEN" \
  --write --case <案卷>
```

落盘：`案卷/<案卷>/案卷/rbac/surface.json`（Token 已打码）。

并行（不要互相替代）：

```bash
python3 main.py authz-probe -u https://授权站 --scope 授权范围
python3 炼蛊房/js_secret_hunter.py hunt --base https://授权站 --case <案卷>
python3 炼蛊房/jwt_gql_probe.py -u https://授权站 --token "$LOW_TOKEN" --case <案卷>
python3 炼蛊房/object_matrix.py check --case <案卷> --strict
```
