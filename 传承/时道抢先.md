# 大爱仙尊竞态作业手法

> 杀招：`时道抢先`  
> 通用：`python3 炼蛊房/race_probe.py`  
> 博彩充提扫面：`logic_vuln_probe.py concurrent`  
> 发卡共享货：`acg-faka`

目标须在 scope。**耗余额下单先问。** `success_n>1` 只是候选，必须对照余额/库存/券次数。

---

## 1. 立刻跑

```bash
python3 炼蛊房/race_probe.py --self-test
python3 炼蛊房/race_probe.py --url https://授权/api/coupon/claim \
  --body '{"code":"A"}' --n 20 --header 'Authorization: Bearer <票>' --case <案>
# 博彩提现窗口
python3 炼蛊房/logic_vuln_probe.py concurrent \
  --url https://授权/api/withdraw/apply --amount 1 --token <票> --threads 20 --case <案>
```

产物：`案卷/race/race.json`。

---

## 2. 四刀

1. **认限次** — 领券 / 首充 / 提现 / 投票 / 库存 1；无限次接口不要打竞态  
2. **单发对照** — 先 1 次，再 barrier 并发 N 次  
3. **看次数** — 多笔 2xx 且业务成功标记相同；再查余额/库存是不是真加了  
4. **收窗口** — 普通并发阴，再 HTTP/2 单包或更短间隔。上传落盘窗口走上传卡

不要用 `core_web_surface_probe` 结竞态。它不会发并发。

---

## 3. 档位

| 档 | 成立 |
|----|------|
| L1 | 接口吃请求（单发或并发有成功） |
| L2 | 并发成功 ≥2，且对照证明多领/多扣/多提 |
| L3 | 资金/库存被放大（耗余额先问） |
