# LiteLLM BadHost 鉴权绕过（Playbook）

工具：`炼蛊房/litellm_badhost.py`  
CVE / 顾问：`CVE-2026-49468`（亦见披露文 `CVE-2026-48710`）· `GHSA-4xpc-pv4p-pm3w`  
修复：`litellm >= 1.84.0`（建议跟到含硬加固的最新 patch）  
授权：仅 `授权范围`；本机 `127.0.0.1` 代理环回除外。

## 1. 心智

LiteLLM Proxy 旧版在鉴权层用 `request.url.path` 取路由，而 Starlette 会按 **Host** 拼 URL。  
构造畸形 Host（如 `target:8080/?`）可让：

- **鉴权门**以为自己在走「内部/公开」路由 → **不校验** `Authorization: Bearer …`
- **FastAPI** 仍按真实 path 分发 → `/chat/completions`、`/spend/keys`、`/settings` 照常执行

```text
正常:  Host: target:8080          + Bearer sk-xxx  → 校验 Key
绕过:  Host: target:8080/?        + Bearer 任意    → 当内部请求放行
```

成功口径：

1. **探针**：`Host` 变异 + 假 Key 对 `/v1/models`（或管理 path）得 **200 且非鉴权错误**，而正常 Host + 假 Key 为 401/403  
2. **Loot**：`/spend/keys`、`/settings`、`/key/list` 等可读（证据默认打码）  
3. **Proxy**：本机 `127.0.0.1:8800` 可被前端当 OpenAI 兼容入口用（CORS / SSE）

## 2. 指纹

| 信号 | 说明 |
|------|------|
| `/health`、`/health/liveliness` | 代理存活 |
| `/v1/models` / `/models` | OpenAI 兼容 |
| 响应/错误文案含 `litellm` / `virtual key` / `master_key` | 强指纹 |
| 常见端口 | `4000` / `8080` / `8000`；反代后也可能是 443 |

前置条件（官方）：跑的是 **Proxy**（不是纯 SDK）、版本 **&lt; 1.84.0**、监听面对不可信客户端，且上游未严格规范化 Host。

## 3. 自动化

```bash
# ① BadHost 探针（对比 normal vs host/? 等）
python3 炼蛊房/litellm_badhost.py probe \
  --base http://授权主机:4000 --case <案卷>

# ② 绕过后捞管理面（默认密钥打码）
python3 炼蛊房/litellm_badhost.py loot \
  --base http://授权主机:4000 --case <案卷>
# 需要完整 token 再加 --raw（勿同步公开仓）

# ③ 本机兼容代理：BadHost + 剥 Anthropic 字段 + CORS + SSE
python3 炼蛊房/litellm_badhost.py proxy \
  --upstream http://授权主机:4000 \
  --listen 127.0.0.1:8800
```

代理行为（对齐你给的技术细节）：

| 本地 | 上游 |
|------|------|
| `GET /v1/models` | 转发 `/v1/models`（Host 注入 BadHost） |
| `POST /v1/chat/completions` | 转发同 path；自动剥 `thinking` / `cache_control` 等 |
| streaming | 透传 `text/event-stream` |
| CORS | `*` |

产物：`案卷/<案卷>/案卷/litellm_badhost/{probe,loot}.json`

|------|------|

## 5. 与现有基础的结合

| 组件 | 怎么接 |
|------|--------|
| DeepAudit / 本地 LLM | 授权测通后可用 `proxy --listen 127.0.0.1:8800` 当 OpenAI base_url |
| FOFA / 测绘 | `title="litellm"` / `body="LiteLLM"` / 端口 4000 — **命中后先写 scope** |
| `http-host-header-attacks`（九阶段） | 通用 Host 手法；**本漏洞专用链走本 Playbook** |
| 案卷 STATUS | 记版本猜测、BYPASS Host、open_paths；完整 Key 只放 `loot_raw.json` |

## 6. 边界

- 未进 scope 的公网 LiteLLM **禁止** probe/loot  
- `--raw` 与未授权推理（烧额度）属高成本 → 先确认  
- CDN/WAF 规范化 Host 时常失效；记「不可达/已修复」勿空转  
- 修复后复测：应恢复 401 + 无管理面泄露
