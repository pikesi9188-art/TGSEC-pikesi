## 一、本次学到了什么

### 1. Mac 微信 wxapkg 使用独有的 V1MMWX 加密

Mac 版微信的小程序包不是明文 wxapkg，而是使用 **V1MMWX** 格式加密。这与 Windows/Android 完全不同：

| 平台 | 格式 | 加密 |
|------|------|------|
| Android | `.wxapkg` | 无加密（直接解包） |
| Windows | `.wxapkg` | 无加密或简单 XOR |
| **Mac** | `.wxapkg`（头部 `V1MMWX`） | **PBKDF2 + AES-256-CBC + XOR** |

**解密密钥**不是用户的 wxid，而是**目标小程序的 AppID**。这个认知错误浪费了大量时间。

### 2. 政务小程序的鉴权模型有固定模式

政务小程序（公安/民政/社保类）的代码中存在一种固定的鉴权设计模式：

```javascript
// 请求拦截器中的鉴权判断
var p = void 0 === o.tokenRequired || o.tokenRequired
// tokenRequired 未设置 → 默认 true（需要 JWT）
// tokenRequired: !1 → false（不需要 JWT）→ 攻击面！
```

**审计方法**：搜索所有 `tokenRequired:!1` 或 `tokenRequired: false` 的端点，这些是**客户端开发者明确标记不需要鉴权**的接口。

### 3. SM2 国密加密选择性覆盖是普遍现象

政务小程序通常使用 SM2（国密）加密敏感请求，但**只覆盖认证类端点**（登录/注册/改密），而 PII 查询接口（地址/照片/个人信息）完全不加密。

这意味着：即使加密了登录流程，获取 JWT 后的所有 PII 查询都是明文 JSON，没有传输层保护。

### 4. 政务 API 后端常用非标端口做网络隔离

政务后端常使用 `:9000`、`:8443` 等非标端口，且只允许微信框架内的 `wx.request` 调用，外网完全拒连。这是一种「安全通过不可达」的思路，但：

- 任何微信用户都可以打开小程序 → 网络隔离名存实亡
- 通过 Proxifier / mitmproxy / Frida 可绕过
- MMKV 本地存储可能缓存了 JWT

### 5. specialRequestPaths 是认证链的薄弱点

`specialRequestPaths` 数组中的端点会自动注入微信 `jsCode`。如果这些端点同时标记 `tokenRequired:!1`，意味着仅凭微信 jsCode（任何微信用户都能生成）即可获取有效的后端 JWT。

## 二、提取到了什么

### 技术产出

| 产物 | 说明 |
|------|------|
| V1MMWX 解密算法 | 完整的 Python 实现（PBKDF2+AES-CBC+XOR） |
| wxapkg 解包器 | struct 解析 Big-Endian 文件索引 |
| tokenRequired 审计方法论 | 系统化的政务小程序鉴权猎杀流程 |
| SM2 加密面分析框架 | crypto-list 提取 + 覆盖范围评估 |
| MMKV JWT 提取路径 | Mac 微信本地存储中的 token 定位 |
| 政务认证流图谱 | WePolice / 粤信签 / 微信授权三条路径 |

### 漏洞模式（可复用到下一次）

| # | 模式 | 复用场景 |
|---|------|----------|
| 1 | `tokenRequired:!1` + 敏感操作（OCR/上传/写入） | 所有使用该拦截器模式的小程序 |
| 2 | `specialRequestPaths` + 无鉴权 → jsCode 换 JWT | 政务/企业小程序 |
| 3 | SM2 只加密认证流，PII 查询明文 | 使用国密的政务系统 |
| 4 | `rkbm` / 人口编码 IDOR | 任何使用人口编码做唯一标识的系统 |
| 5 | `photoSave` / `authSave` 无鉴权写入 | 微警集成的政务小程序 |
| 6 | 非标端口网络隔离 ≠ 真安全 | 所有仅依赖网络层防护的小程序后端 |
| 7 | Mac MMKV 缓存 JWT | 任何 Mac 微信小程序（用户登录过） |

## 三、V1MMWX 解密核心参数速查

```
文件头:     V1MMWX (6 字节)
KDF:        PBKDF2-HMAC-SHA1(password=AppID, salt="saltiest", iter=1000, dklen=32)
AES:        AES-256-CBC(key=上述, iv="the iv: 16 bytes")
AES 范围:   byte[6:1030]   → 1024 字节密文
跳过:       byte[1030]     → 1 字节分隔符
XOR 范围:   byte[1031:EOF] → 与 ord(AppID[-2]) 异或
拼接:       aes_plaintext + xor_plaintext
验证:       首字节 == 0xBE
```
