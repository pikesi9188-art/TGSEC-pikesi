# 余烬·固化

恢复成功不等于闭环。目标是撤销旧入口、轮换机密、保存可恢复备份，并让下一次不再依赖公网漏洞。

## 执行顺序

1. 保存恢复前证据和只读快照。
2. 确认当前会话稳定、备用恢复渠道可用。
3. 轮换账号与机密。
4. 撤销旧会话、旧密钥和异常权限。
5. 导出数据、配置和恢复卡。
6. 更新 Scope、STATUS 和报告。

不要在没有快照或备用登录方式时一次性撤销全部凭据。

## 通用账号

- [ ] 修改管理员密码，使用唯一随机密码
- [ ] 开启 2FA，并离线保存恢复码
- [ ] 更新恢复邮箱和手机号
- [ ] 检查最近登录、活跃会话和可信设备
- [ ] 撤销不认识的会话、应用密码和 OAuth 授权
- [ ] 为日常操作建立低权限账号，避免长期使用主账号

## Web / 支付 / 数据库

- [ ] 轮换后台管理员、数据库和缓存密码
- [ ] 轮换支付 KEY、回调密钥和 webhook secret
- [ ] 检查回调域名、收款账号和订单状态任务
- [ ] 导出数据库、卡密、上传文件和关键配置
- [ ] 修复匿名读写、BOLA、文件上传和 CORS 规则
- [ ] 删除测试记录、临时账号和探针文件
- [ ] 在测试环境验证新密钥后再切换生产

## PocketBase / Horizons

- [ ] 导出 `pb_data` 或使用受支持的备份功能
- [ ] 轮换 `_superusers` 密码并核对超管列表
- [ ] 逐集合检查 list/view/create/update/delete 规则
- [ ] 检查 SMTP、OAuth、文件存储和备份配置
- [ ] 移除前端硬编码后台口令
- [ ] 验证普通用户票不能访问超管接口

## OSS / 对象存储

- [ ] 导出对象清单和关键对象本地镜像
- [ ] 轮换主账号、RAM AK/SK 和临时凭证策略
- [ ] 改为最小权限 RAM，禁止应用使用主账号 AK
- [ ] 关闭无业务需要的匿名 List / Put / Delete
- [ ] 核对 Bucket Policy、ACL、CORS、生命周期和日志
- [ ] 对外分发 Bucket 启用版本控制或不可变备份
- [ ] 删除恢复控制标记和临时测试对象

## Telegram Bot / TG 账号

- [ ] BotFather 轮换 Token 并更新部署环境
- [ ] 执行 `recovery-init`，登记主号与备用号
- [ ] 执行 `recovery-export`，恢复卡保存两处
- [ ] TG 账号开启两步验证并保存恢复邮箱
- [ ] 满平台安全等待期后撤销旧设备
- [ ] 核对 Bot 管理员 ID、Webhook 和部署机权限

## VPS / 部署主机

- [ ] 创建恢复后磁盘快照
- [ ] 轮换 SSH 密钥并清理未知 `authorized_keys`
- [ ] 检查面板账号、计划任务、启动项和部署密钥
- [ ] 收紧安全组，只开放必要端口
- [ ] 备份环境变量、服务配置和恢复文档
- [ ] 验证备份可恢复，而非只验证“文件存在”

## 证据与敏感文件

- [ ] 原始响应、截图和日志使用相对路径写入证据索引
- [ ] Token、密码、卡密、个人信息保存为受限文件
- [ ] 敏感文件建议命名为 `*.RESTRICTED.json`
- [ ] 正式报告只引用脱敏摘要，不复制完整机密
- [ ] 对备份生成校验值并记录生成时间

## 最低验收

只有同时满足以下条件才标记 `SUCCESS`：

- [ ] 目标产物已实际验证可用
- [ ] 至少一种备用恢复渠道已验证
- [ ] 旧机密和异常会话已撤销
- [ ] 数据与配置备份可读取
- [ ] `STATUS.md` / `VERDICT.json` 已更新

若只拿到数据、旁路权限或业务层控制，真超管 / 主账号仍未恢复，应标记 `PARTIAL`。
