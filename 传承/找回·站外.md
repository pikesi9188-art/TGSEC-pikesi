# 找回·站外 Playbook

适用于站内技术面已经熔断，但自有资产仍可通过官方账号、邮箱、云控制台或部署主机恢复的场景。

## 总原则

1. 先确认目标属于 `授权范围`，并记录资产 Owner。
2. 只走官方登录、找回密码、工单和实名认证渠道。
3. 同一技术向量两轮同态失败后停止，转入本 Playbook。
4. 不猜测他人身份、不伪造证明、不扩展到未授权关联资产。
5. 找回前先整理材料，避免在验证码和客服会话中临时翻找。

## 统一材料包

- 注册或购买时使用的邮箱、手机号
- 实名主体、公司名称和证件信息
- 历史账单、订单号、支付方式及后四位
- 域名、Bucket、项目、服务器实例等资源名称
- 已知创建时间、区域、旧 IP、旧账号名
- 能证明持续控制或使用的历史配置、截图、备份

材料只保存于受限目录；报告中不得明文复制证件、Token 或完整支付信息。

## Telegram Bot

### 前置

- 还能登录创建 Bot 的 Telegram 账号；或
- 仍有 VPS/部署机权限；或
- 已预登记恢复口令、备用号和 PIN。

### 官方与本地恢复顺序

1. 恢复口令：向 Bot 发送 `/recover <长口令>`。
2. 备用号：发送 `/recoverpin <PIN>`。
3. 部署机：通过 SSH 修改自有 Bot 的管理员配置并重启。
4. BotFather：重新取得或轮换 Bot Token，再重新部署。
5. 成功后立即执行 `recovery-init` 和 `recovery-export`。

完整决策树见 `docs/遗忘资产合法恢复.md`。

### 禁止

- 在代码中添加隐藏管理员入口。
- 将 Token 写入 Git、公开报告或聊天记录。
- 通过公网弱口令代替已有的 BotFather / SSH 恢复渠道。

## 邮箱与 2FA

### 前置材料

- 注册邮箱或绑定手机号
- 恢复邮箱、恢复码、可信设备
- 最近一次成功登录的大致时间和常用地区

### 操作

1. 使用常用设备、常用网络和单一浏览器会话。
2. 只请求最新一枚验证码，旧码立即作废。
3. 优先使用恢复码或可信设备确认。
4. 失败后记录错误类型和冷却时间，不并发重复提交。
5. 无法自助恢复时，通过官方客服提交材料包。

### 停止条件

- 进入频率限制或账号保护冷却期。
- 缺少能证明所有权的材料。
- 候选邮箱已被证实不是该资产的注册账号。

## Hostinger hPanel / Horizons / PocketBase

### 适用

Horizons 托管站、`/hcgi/platform`、PocketBase `/_/` 真超管无法从站内恢复。

### 所需材料

- Hostinger 注册邮箱或手机
- 订单、账单和支付信息
- 域名、Horizons 项目名及 dev 域名
- 项目创建时间、历史 DNS 或部署截图

### 操作

1. 通过 Hostinger 官方账号恢复入口找回 hPanel。
2. 自助失败时，向官方支持提交材料包并指定资源名称。
3. 进入 Horizons 项目后，先导出项目和 PocketBase 数据。
4. 再恢复或重置 PocketBase `_superusers`，不要把前端 `/admin` 密码当作真超管。
5. 登录 `/_/` 后轮换超管密码、检查 SMTP、备份和集合规则。

### 停止条件

- PocketBase installer 返回 `Only superusers`：安装面已锁，不再尝试外网重装。
- JWT、mass assignment、403 绕过两轮同态失败：站内提权熔断。
- 无确凿超管邮箱：不做邮箱枚举或弱口令海喷。

## 阿里云 OSS / RAM

### 所需材料

- 阿里云登录名、绑定手机或邮箱
- 实名认证主体和历史账单
- Bucket 名、地域、历史 Endpoint
- 已知 RAM 用户名、旧 AK 标识或客户端配置

### 操作

1. 通过阿里云官方账号找回或工单恢复主账号。
2. 进入控制台后确认 Bucket 所属账号、地域、ACL 和 Bucket Policy。
3. 新建最小权限 RAM 身份，轮换旧 AK/SK 和 STS 策略。
4. 先导出对象清单和关键对象，再修复匿名读写策略。
5. 对同名或相邻 Bucket 逐 Key 对比；不得把旁路桶写权误报为主桶恢复。

### 停止条件

- 主桶 PUT / ACL / Multipart 两轮均为同态 403，且没有新凭据。
- 客户端静态分析无凭据且存在 VMProtect 等保护：停止重复 strings。
- 发现第三方裸写桶：只记录，不写入，不自动扩入授权。

## VPS / SSH / 主机面板

### 操作

1. 优先走云厂商控制台重置 SSH 密钥或系统密码。
2. 使用救援模式或快照挂载前先创建磁盘快照。
3. 恢复后检查 `authorized_keys`、面板账号、计划任务和部署密钥。
4. 轮换数据库、对象存储、支付和 Bot Token。

### 禁止

- 没有主机授权时扫描 SSH、宝塔、cPanel 或数据库。
- 为方便下次恢复而保留公网未授权接口或弱口令。

## 域名商 / GoDaddy / cPanel

1. 先恢复注册商账号，锁定域名并检查联系人邮箱。
2. 导出 DNS 区域，核对 NS、MX、A/AAAA、CAA。
3. cPanel 与域名账号分开恢复，不能用域名控制权推定主机控制权。
4. 发现 DNS 被改后，先保存现状证据，再恢复解析并轮换相关密码。

## 结案标准

在案例 `STATUS.md` 中至少写明：

- 站内技术面为何熔断
- 官方恢复渠道及材料 Owner
- 已提交的工单或待办状态
- 成功后的固化清单
- 未授权关联资产和明确禁止动作
