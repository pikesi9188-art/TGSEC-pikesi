# 万我

> 专卡（假支付 / Actuator / 芋道 / 发卡）是锤子，不是想法。  
> 本卡回答：**已经有一个身份之后，先问什么、禁止在哪结案。**  
> 工具：`main.py authz-probe` · `agent_probe.py` · `hardcoded_token_cfip.py` · `bucket_probe.py` · `js_secret_hunter.py`  
> Skill：`杀招/万我`  
> 红线：目标在 `授权范围`；大规模拖库 / 耗余额先问。

---

## 0. 为什么会「手法限制想法」

默认回路是：

```text
认栈 → 命中一张专卡 → 专卡阴性 → 写复工 / 换下一张专卡
```

三张实战链教的不是三个洞，是三种**结案禁令**：

| 禁令 | 错的结案 | 对的下一问 |
|------|----------|------------|
| **超管不是终点** | 进了 admin 就找 RCE / 改密 | 配置 / 文件 / COS·OSS 接口把云钥读出来没有 |
| **IDOR 奖品是哈希** | `/api/user/info` 当「查自己资料」跳过 | `userId` 换他人是否吐 bcrypt / 资金密码 hash |
| **禁自己 ≠ 禁他人** | 给自己加款 403 就停 | 用 A 的票给 B 加，再用 B 的票查余额 |

先填矩阵，再回专卡。专卡阴性只说明**那条锤子不行**，不说明对象面没洞。

## 0.1 怎么解决「专卡变成唯一想法」

加第 91 张手法卡解决不了。要改的是**开打顺序和结案条件**：

| 层 | 做什么 | 不做什么 |
|----|--------|----------|
| 闸 | 开案落 `案卷/object_matrix.md`；有身份先填自己 vs 他人 | 把矩阵当成又一张可勾选专卡 |
| 细链 | 假支付 / Actuator / 芋道 **只填某一格** | 专卡阴性就写复工结案 |
| 回表 | 阴性后换对象或换「他人」 | 换一张同类锤子再空转 |

命令：

```bash
python3 炼蛊房/case_triage.py init --case <案卷> --url https://目标 --grade A
# init 会同时写入 案卷/object_matrix.md
python3 炼蛊房/object_matrix.py next --case <案卷>
python3 炼蛊房/object_matrix.py check --case <案卷> --strict
```

`--strict`：空格子 **或** 三禁未勾 → exit 1，不准 PAUSED 结案。空单元格也算未测（删掉「未测」两个字混不过去）。`next` 只打下一格。

## 1. 开案 15 分钟：对象矩阵

对**每一个已拿到的身份**（游客 / 刚注册 / OAuth token / 代理 / 后台）填四列。空格必须实测，禁止用「应该不行」填。

| 身份 | 对象 | 动词 | 自己 | 他人 |
|------|------|------|------|------|
| 注册用户 | `/api/user/info` | 读 | | 换 `userId`/`uid`/`id` |
| 同上 | 钱包 / 收款址 / 流水 | 读 | | 换 `wallet_id`/`fundsn`（uid 阴不准停） |
| 同上 | 余额 / 加款 / 调账 | 写 | 给自己 | 给任意 uid |
| 同上 | 订单 / 下载 / 卡密 | 读 | | 换 `orderNo`；列表锁死再打消息/工单 |
| 同上 | 玩家票 config | 读 | init/自己 | `turnWaterInit` / `task-center` / 异租户 |
| OAuth / 默认账 | 角色 | 升 | 普通 | `super_admin` / `authorityId` |
| 任意已登录 | 配置 / 文件 / OSS | 读 | settings | `/config` `/file` `/oss` `/cos` `/storage` |
| 超管或云钥 | 桶内对象 | 列/读 | 业务图 | `session` / `tdata` / `whatsapp` / `2fa` |

成功口径：

- **读**：他人字段出现（hash / 手机 / 余额 / AK），不是 200 空 JSON。
- **写加款**：自控号 B 用**自己的票**查余额增值。提现记录里的 `balance` 常是历史快照，**不算入账**。
- **云钥**：`sts:GetCallerIdentity` / COS 列桶成功，不是配置页截图。

## 2. 链 A — 进门到云库存（OAuth2 password + 默认账）

指纹：`POST /auth/token`、`grant_type=password`、图形码挡登录、开放注册、`super_admin`。

```text
验证码旁路或打码
  → OAuth2 password grant（必须 form-urlencoded，JSON 会假阴性）
  → 默认账 / 开放注册写角色
  → super_admin
  → 文件配置接口（不是 RCE）
  → 腾讯云 COS / 阿里云 OSS 账号级密钥
  → 全桶读写
  → TG 养号库（手机号 + session 目录 + 2FA）/ WhatsApp 媒体
```

并行面（同一环境常一起在）：未授权上传、开放注册、配置大面积泄露。

**本库交接**：

| 段 | 走 |
|----|-----|
| OAuth2 password + 重置/改邮 | Skill `托印·口令` |
| 注册写角色 | GVA `authorityId` 专卡；其它后台看 Mass Assignment |
| 进超管后收钥 | `js_secret_hunter` + 配置 API；`云府·临钥.md` |
| 桶 | `bucket_probe.py`；Electron/ASAR 硬编码对照 `uukeji` |
| TG session 库 | Skill `太白云生·云台` · `tg-account-library` |
| FastAdmin Shop `shop_id` | Skill `快府·横夺`（EQ 改租户阴性必须再打 GT/IN） |

禁止：拿到 `super_admin` 只截后台首页就结案。

## 3. 链 B — 用户信息 IDOR 拖哈希

指纹：`/api/user/info`、`/user/detail`、`refreshUserInfo`、参数 `userId` / `uid` / `loginUid`。

```text
任意合法会话（开放注册最佳）
  → 改 userId
  → 完整用户行：bcrypt + 资金密码 hash + 账号字段
  → 区间扫描（低速，去重回放）
  → hashcat 短字典（资金密码往往更弱）
```

本库已有：Skill `报名·横夺`（`refreshUserInfo` 范式）。  
增量：**info 类接口默认当 IDOR 测**，不要因为名字叫 info 就当只读自己。

L2 证据：两个不同 `userId` 的 hash 不同且都能打出。大规模拖全表先问。

## 4. 链 C — 给他人加款 + 自证链

指纹：加款 / 调账 / `manualAngPao` / `addBalance` / `changeBalance`；文案或接口写「不能给自己操作」。

```text
A 给 A 加款 → 失败（这是诱饵，不是结案）
A 给 B 加款 → 200
B 用自己的 token 查余额 → 增值（这才算入账）
```

自证链（提现记录不可信时强制用）：

1. 注册新号 B（无验证码则直接做）  
2. 记下 B 加款前余额  
3. 用 A 的 token 对 B 的 uid 加最小额  
4. **登录 B**（或用 B 的 token 调余额接口）看差额  

本库交接：Skill `和稀泥·死契`（命门仍是源站 + 站内 Token）；`agent_probe.py level`（代理改等级）。  
增量：探针必须带 `--target-uid` 他人号，禁止只打 self。

大额加款先问。L3 口径=B 的余额差，不是 A 的 200。

## 5. 15 分钟命令（有会话就跑）

```bash
# 通用未授权 + 水平越权（无专卡时）
python3 main.py authz-probe -u https://授权站 --scope 授权范围

# JS 里把 userId / addBalance / oss / cos / config 路由捞出来
python3 炼蛊房/js_secret_hunter.py hunt --base https://授权站 --case <案卷>

# 代理体系：注册代理后枚举 API，再改等级
python3 炼蛊房/agent_probe.py api-enum --base https://授权站 --token "$TOKEN" --case <案卷>

# 加款类：先他人 uid，再自证
python3 炼蛊房/hardcoded_token_cfip.py probe \
  --origin-ip <源站> --host api.授权域 --token "$TOKEN" \
  --module '<加款路径>' --case <案卷> \
  --extra-json '{"userId":<B的uid>,"amount":1}'
```

OpenAPI / 前端出现这些名字，**默认进矩阵，不准跳过**：

`user/info` `userId` `uid` `addBalance` `changeBalance` `adjust` `manual`  
`config` `file` `upload` `oss` `cos` `secretId` `SecretKey` `sts`  
`grant_type=password` `/oauth/token` `super_admin`

## 7. 与专卡的关系

本卡**不替代**假支付 / Actuator / 芋道。顺序是：

```text
Triage → 对象矩阵（15 分钟，有身份就做）
       → 仍按指纹走专卡
       → 专卡阴性：回到矩阵换对象/换「他人」，不要换一张同类锤子
```

分流总卡：`凤九歌·天地歌.md`。越权细档：`万我·信门.md`。  
低权票打管理功能 / 角色字段 / Method-Override：`无极·职分.md`（填 **自己 × 配置/角色**；批量混他人 id 再填他人写）。  
资金对象键 / 展示层地址 / 双路径 / 提款 saga：`血神子·账.md`（`fund-edge-ops`）。四账户：同租户 A/B + 代理 C + 异租户 D，不要停在两号。
