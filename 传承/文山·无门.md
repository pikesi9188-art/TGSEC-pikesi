# GitLab GraphQL 未授权改删手法（CVE-2026-19478）

> Skill：`杀招/文山`  
> 指纹：`tools/1day-kit/custom-templates/gitlab-graphql-cve-2026-19478.yaml`  
> 情报：`od_kit.py cvebase lookup --cve CVE-2026-19478`  
> 日报：`CVE日报-2026-08-18.md`  
> 红线：仅 `授权范围`。默认 **不发改/删 mutation**（那是破坏业务）。

---

## 1. 一句话

自托管 GitLab CE/EE 的 GraphQL 在 **18.2–19.2.3 窗** 存在未认证代码注入面：恶意 GraphQL **directive** 可改/删公开项目和用户数据（CVE-2026-19478，CVSS 9.4）。  
同补丁还有 CSRF：未认证可用 **GET** 跑 multiplex mutation（CVE-2026-19650，需用户点击）。

厂商工作项 90 天后才公开细节。本卡默认：**认产品、抠版本、证明 GraphQL 未鉴权可读**。不自造 directive，不删项目。

修：**18.11.11 / 19.0.8 / 19.1.6 / 19.2.4**。GitLab.com / Dedicated 已打，不要扩进 scope。

## 3. 档位

| 档 | 动作 | 成功证据 |
|----|------|----------|
| **L1** | 首页 / 登录页 / `/api/v4/version` | 确认 GitLab 与版本号 |
| **L2** | 未带票 `POST /api/graphql` 只读 `metadata`；可选列公开项目 | GraphQL 未鉴权可读；版本落在影响窗则记「可能受影响」 |
| **L3** | 用 directive / GET mutation 改或删项目 | **先问**；默认不做。无公开 PoC 时禁止现编 payload |

```text
L1 确认产品与版本
  → L2 证明 /api/graphql 未鉴权只读 + 是否有公开项目（本卡默认停在这里）
  → L3 写/删 = 破坏业务，先问
```

版本窗（CE/EE 相同）：

| 分支 | 受影响 | 已修 |
|------|--------|------|
| 18.x | `≥18.2` 且 `<18.11.11` | `18.11.11` |
| 19.0 | `<19.0.8` | `19.0.8` |
| 19.1 | `<19.1.6` | `19.1.6` |
| 19.2 | `<19.2.4` | `19.2.4` |
| `<18.2` | 不在本 CVE 声明窗 | — |

L2 只读查询（官方公开字段，不是 exploit）：

```http
POST /api/graphql
Content-Type: application/json

{"query":"{metadata{version revision}}"}
```

公开项目列表（评估影响面，不是利用）：

```http
GET /api/v4/projects?visibility=public&per_page=5
```

STATUS 记：版本、GraphQL 是否未鉴权、公开项目是否存在。不要只写 CVE 号。

---

## 4. 不要做

- 未授权扫公网 GitLab / 把 gitlab.com 当目标  
- 默认发 `projectDestroy` / 改可见性 / 改用户（删数据先问）  
- 对目标发 CVE-2026-19650 的 GET mutation（要用户点的 CSRF，且会改数据）  
- 在 90 天解禁前自造 GraphQL directive payload  
- 只报 CVE 编号不核对版本
