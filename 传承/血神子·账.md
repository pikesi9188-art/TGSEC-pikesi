# 血神子·账

> Skill：`杀招/血神子·锋`  
> 探针：`炼蛊房/fund_edge_ops_probe.py`  
> 实证来源：2026-08 授权会员资金盘口全链（脱敏；不写站名/账户/域名）  
> **仅 `授权范围`**。默认只读；真提现 / 耗余额 / 改他人收款址 **先问**。

---

## 0. 一句话

会员票打资金面时，**对象键往往不是 `user_id`**。  
`wallet_id` / 双路径 / 展示层地址 / 客服消息 / 提款流水号，任意一层鉴权不一致，就能读到他人资金对象，甚至把受害人付款打到攻击者地址。

假支付打 HTTP notify；USDT 归属打「from 绑表入账」；**本卡打资金对象键 + 状态机 + 展示层**。三张并行，一张阴性不准结案。

## 2. 何时启用

命中任意两条就开本卡（有会员票之后，与对象矩阵同时填）：

- 请求/响应出现 `wallet_id` / `walletId` / `fundId` / `fundsn` / `recvAddress`
- 同一资金动作有两条 path（`/wallet/*` 与 `/fund/*`、`/pay/*` 与 `/finance/*`）
- 充值页展示地址来自 init / config / 消息 / 工单，而不是唯一建单接口
- 客服消息 / 站内信 / 工单回显订单号或地址
- 提现多步：申请 → 审核 → 打款 → 完成，带流水号
- 玩家票能打到 `init2` / `turnWaterInit` / `task-center` / `tenant` / `site` config

**不要走本卡**：无会话（先注册/弱口）；只换 uid 读 `/me`（回对象矩阵）；只测 notify 验签（回假支付）。

## 3. 六层身份审计（先问对象键，再打专卡）

有任意会员票，按层填，禁止跳层结案。

| 层 | 问 | 对象键 | 成功信号 |
|----|----|--------|----------|
| L1 会话 | 这张票是谁 | JWT `sub` / `uid` / `siteId` | 票能打业务 API |
| L2 资金身份 | 钱挂在哪个钱包 | `wallet_id` ≠ `user_id` | 同一用户多钱包；换 wallet 响应变 |
| L3 支付对象 | 单/流水是谁的 | `order_id` / `fundsn` / `payId` | 换键 200 且字段属他人 |
| L4 路径身份 | 同一资源是否两条路 | path-A 鉴权、path-B 弱鉴权 | 双路径 status/body 不一致 |
| L5 消息神谕 | 主列表锁死后来信 | message / notice / ticket | 信里有他人单号/地址 |
| L6 配置收割 | 玩家票当侦察 | init / turnWater / task-center / tenant | 异租户域、隐藏后台、站点表 |

四账户（不要停在 A/B）：

| 号 | 角色 | 用来测 |
|----|------|--------|
| A | 同租户会员 | 自己的基线 |
| B | 同租户另一会员 | 水平 `wallet_id` / 地址 / 流水 |
| C | 代理 / 推广 | 代理读会员资金 |
| D | 另一 `siteId` / 租户 | 跨租户 config / CORS |

回写 `案卷/object_matrix.md`：自己 vs 他人 × 读钱包 / 读地址 / 读流水 / 读消息。专卡阴性必须回表。

## 4. wallet_id 旁路

```text
A 的票 + B 的 wallet_id
  → GET/POST 充值地址 / 余额 / 提现绑定 / 流水
  → 若 200 且地址/余额/绑卡属 B = L2 水平资金 IDOR
```

要点：

1. JS/建单响应里同时抓 `user_id` **和** `wallet_id`，当两把键。  
2. 参数位置都试：query、JSON body、`X-Wallet-Id` / `X-Fund-Id`。探针默认三处都打。  
3. 网关前缀用 `--prefix /prod-api`（或 `/api/v1`），Cookie 票用 `--cookie`。  
4. `user_id` 校验通过但 `wallet_id` 不校验 = 典型洞（只测 uid 会假阴性）。  
5. 只取 A/B 自控号证明；禁止枚举真实用户钱包。

---

## 5. 展示层充值地址劫持（≠ USDT 归属）

```text
USDT 归属：共享收款址 + 按 from 绑表 → 钱进错账号
展示层劫持：受害人屏幕上的收款址被换成攻击者址 → 受害人把钱打错
```

常见向量：

1. **wallet_id 换地址**：A 票 + B `wallet_id` → 接口把 B 的专属收款址回给 A（或反过来让 B 的前端渲染 A 的址）。  
2. **双路径不一致**：建单接口返回平台分配址；init / config / task-center 另一条路返回可注入址；前端优先展示后者。  
3. **消息/工单注入**：客服或站内信里的地址被前端直接渲染，无二次核验。  
4. **展示 ≠ 入账权威**：页面显示址 A，链上/FPS 实际应打址 B——以**用户会按屏幕转账**为攻击面。

| 档 | 成立 | 不算 |
|----|------|------|
| L1 | 两条路返回的地址字段不一致，或换 `wallet_id` 地址变了 | 仅前端文案 |
| L2 | A 票能读出 B 的收款址，**或** 能让 B 的展示变成 A 的址 | 只能绑自己的址（那是归属卡） |
| L3 | 自控小额按展示址打入后，入账到非预期账号 | 先问；禁止诱导真人付款 |

链上 from 绑表仍走 `usdt-deposit-attribution-hijack`，两卡都打。

## 6. 双路径 bypass

同一资金资源两条 path，鉴权不对称：

```text
path-A  /api/wallet/address     → 校验 wallet 归属 → 403
path-B  /api/fund/address      → 只校验登录       → 200 + 他人址
path-C  /api/task-center/wallet → 玩家票当内部调用 → 200
```

作业：

1. 从 JS chunk 抽成对：`wallet`/`fund`/`pay`/`finance`/`capital` 同名词。  
2. 同一 token、同一对象键，打两条路，比 status + 地址/余额/流水字段。  
3. 写操作只打自控对象；读他人只取一条证明。

`status` 不同或 body 关键字段不同 = L1；读到他人资金字段 = L2。

## 7. 幽灵单 / 消息神谕

主订单列表按登录态过滤，但消息 / 站内信 / 工单 / IM 历史仍回订单切片。

```text
官方 /orders 只见自己
/message /notice /ticket /inbox 换 order_id 或 wallet_id
  → 回显他人单号、金额、地址、fundsn
= 幽灵单：信里有、列表里没有
```

用途：当主 API 锁死，用消息当 IDOR oracle，再拿单号回灌建单/查单/提现查询。  
禁止批量拖真实工单；A/B 自控互证即可。

---

## 8. 提款 saga / fundsn 状态机

提现常是多步状态机，不是单次 POST。

```text
apply → pending → reviewing → paying → done
         ↘ rejected / canceled
```

查：

| 手法 | 怎么打 | 默认 |
|------|--------|------|
| 状态跳步 | 对自控单 PUT `status=paid` / `step=done` | 只打自己的单 |
| 双路径取消/完成 | path-A 取消、path-B 仍能完成 | 只读对照优先 |
| `fundsn` 复用 | 旧流水号当幂等键重放 | GET 枚举；POST 先问 |
| 审核前改址 | pending 单改 `address`/`wallet_id` | 只改自控单 |
| 并发 saga | 同单同时 apply/cancel | 小额自控 |

`logic_vuln_probe.py concurrent` 打单接口竞态；**本卡打跨状态、跨路径、跨流水号**。  
默认探针 `saga-read` 只 GET。对他人单做完成/打款 = 禁止。

## 9. 玩家票配置收割

玩家 JWT 不是只能打 `/me`。先打这组（只 GET）：

| 指纹 | 常见 path | 要的东西 |
|------|-----------|----------|
| 二次初始化 | `/init` `/init2` | `siteId`、域名表、开关 |
| 反水/流水 | `turnWaterInit` | 租户规则、隐藏通道 |
| 任务中心 | `/task-center` `/task/center` | 内部 wallet/活动 API |
| 租户配置 | `/tenant/config` `/site/config` | 异租户域、客服域 |
| 公开配置 | `/public/config` `/app-config` | 假后台域 vs 真隐藏 path |

假后台域名 403 ≠ 没有管理面。对照 init 里的隐藏 path / 非标端口再打。  
CORS 对租户 Origin 反射 + 带 Cookie = 跨租户读资金面（回 `core-web-vuln-kit` 做 CORS，证据挂本卡）。

```bash
python3 炼蛊房/fund_edge_ops_probe.py cors \
  --base https://授权站 --case <案卷> --token "$TOKEN_A" \
  --origin https://另一租户域 --path /api/wallet/address
```

## 10. 客服 / FPS 干预面

人工通道（FPS / 银行转账 / 上传凭证）里，客服常能改展示地址或点「已到账」。

- 只打**授权测试号自己的工单 API**（读字段、看是否回显他人单）。  
- 禁止对真人客服做诱导转账脚本。  
- 工单能改地址 = 展示层 L2 的人工版，记进矩阵「他人 × 写地址」。

## 11. 成功口径

| 档 | 成立 | 不算 |
|----|------|------|
| L1 | 双路径差分 / 换 `wallet_id` 响应变 / 消息回单号 / 玩家票打到 config | 只扫到 health；只发现字段名 |
| L2 | 读到**另一自控号**的地址、余额、绑卡、流水或展示址被换 | 200 空 JSON；只读自己 |
| L3 | 自控小额按错误展示址入账，或 saga 跳步改了自控单状态 | 耗他人余额；真提现到外部 |

入账以 **B 自己的票查余额** 为准。提现记录里的 `balance` 快照不算。

## 13. 复工 / 结案禁令

- `user_id` IDOR 阴性 → 换 `wallet_id` / 双路径 / 消息，禁止写「无越权」。  
- 展示层阴性 → 仍打 USDT 归属；归属阴性 → 仍打展示层。  
- 假后台 403 → 用 harvest 里的隐藏 path，禁止只扫 `/admin`。  
- 提现 apply 403 → 打 saga-read + 双路径，禁止当资金面结案。  
- 专卡阴性必须 `object_matrix.py check --strict`。
