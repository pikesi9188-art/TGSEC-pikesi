# Go 后端零信任敲门与黑洞模式 — 手法

> 原图：（开源包不收个案摘记）  
> 专卡：`杀招/行器·敲门` · 探针：`炼蛊房/c2_zt_probe.py`  
> 挂靠：`云帷·源溯.md` · `隐鳞·罩.md` · `空间眼.md`  
> 分界：**打授权目标上的 C2 控制台面**。自己的 Sliver 落地回连走 `host-c2-verify`。  
> 立场：目标须在 `授权范围`。改原超管密 / 持久化清日志仍先问。

---

## 0. 一句话

一套 **Go 后端 + Vue 控制台** 的对外姿态：默认 **nftables 黑洞（Global DROP）**；合法操作员走 **Cloudflare 上的两步敲门（SPAKE2 + HMAC）** → 动态白名单短暂开洞 → 再连非标 SSH / Web 控制台；控制台资源 **内存加载、无痕执行**，桌面用 **WebRTC H.264**。

作业含义：**广谱端口扫会「什么都没有」≠ 没机器**；要先认「黑洞 + 敲门」指纹，再决定换路（CDN/证书溯源、敲门面、业务入口），别在 22/8888 上空转。  
交付：**控制台 / 终端 / 库** 之一可验证 = L2/L3，证据打码。支付假付不并本链。

## 1. 架构拆解（对照原图）

```text
                    ┌─ 未鉴权扫描 ──► nftables Global DROP（黑洞）
                    │                 22 / 8888 / 直连 8080 → 全灭
外网 ──► CF CDN? ──┤
                    │
                    └─ 已鉴权操作员 ──► 零信任敲门（2 步 API）
                                         Host 校验 + 时间窗 HMAC
                                              │
                                              ▼
                                    动态白名单更新（~10s 窗口）
                                              │
                         ┌────────────────────┼────────────────────┐
                         ▼                    ▼                    ▼
                    SSH :1234            智能防火墙/WAF         Vue C2 控制台
                    （非标口）           白名单隔离 / 防 CC      内存沙箱 + WebRTC
```

| 区块 | 图中要点 | 学什么 |
|------|----------|--------|
| 黑洞模式 | nftables **Global DROP**；无敲门白名单则 8888 不可达；22 默认关；8080 仅允许经 CF Proxy | 默认拒绝在内核层完成，应用层「探测通信」本身也不可见 |
| 零信任敲门 | 终端发起 **两步 API**；经 CF Edge（0-RTT / 缓存）；**Host Header** 校验；**时间请求 → HMAC Token**；协议标注 **SPAKE2** | 敲门面在 CDN 后，密钥协商 + 短时签名，不是经典 UDP 多端口 knock |
| 动态白名单 | 鉴权成功 → 更新 nftables → 操作员 IP 短暂放行（图示约 10s） | 窗口极短：只够建连；超时再扫仍是黑洞 |
| 智能防火墙/WAF | 白名单隔离 + 防 CC | 即使进了白名单，应用层仍有第二道 |
| 内存资产 | Console HTML / `app.js` → **内存沙箱**「无痕执行」 | 磁盘上难找面板静态资源；JS 抓包/备份扫收益下降 |
| Vue C2 控制台 | 实例挂载；**WebRTC + H.264** 桌面流；Terminal / Files / Database；PTY **8889** Web Console API | 管理面是浏览器里的远程桌面+终端，不是传统 WebSSH 单页 |

|------|------|
| 红 ✕ | 防火墙阻断 |

## 2. 端口与路径心智模型（图中示例，非通用常数）

| 端口/面 | 角色 | 未敲门 | 敲门成功后 |
|---------|------|--------|------------|
| 22 | 传统 SSH | DROP | 通常仍关（图示改非标） |
| 1234 | 操作员 SSH | DROP | 白名单窗口内可连 |
| 8888 | 探针/探测通信 | 无敲门白名单 → DROP | 视实现 |
| 8080 | Web 登录 | 直连 DROP；**仅 CF Proxy** | 经 CDN + 鉴权 |
| 8889 | PTY / Web Console API | 默认不可达 | 控制台终端通道 |

记住：**数字可换**；模式是「公网只露 CDN 入口 + 内核黑洞 + 短时 IP 白名单」。

---

## 3. 协议要点（SPAKE2 + HMAC）

不必背实现细节，抓住威胁模型：

1. **SPAKE2**：口令认证密钥交换，防离线撞库式猜敲门密钥（相对裸 Shared Secret）。  
2. **时间窗 + HMAC**：Token 绑定时间与会话，重放窗口窄。  
3. **Host 校验在 CF 边**：伪造 Host / 直连源站 IP 往往进不了合法敲门路径。  
4. **白名单超时短**：即使截到一次成功敲门的源 IP，过窗即失效；要持续访问需重复敲门或维持会话。

## 3.1 立刻跑（本库命令）

```bash
python3 炼蛊房/c2_zt_probe.py drive --base https://授权站 --case <案>
python3 炼蛊房/c2_zt_probe.py drive --base https://授权站 --origin-ip <源IP> --case <案>
python3 炼蛊房/c2_zt_probe.py extract --path bundle.js
python3 炼蛊房/c2_zt_probe.py hmac --key <钥> --method GET --path /api/knock
# 抽出序列后才发；默认不喷 1–65535
python3 炼蛊房/c2_zt_probe.py knock --host <源IP> --seq 7000,8000,9000
```

溯源 / 信任头 / JS 密钥并行：`origin_recon.py` · `space_search.py cert-origin` · `trusted_ip_header_probe.py` · `js_secret_hunter.py hunt`。  
PTY 进线后：`ws_probe.py`。沙箱：`linux-post-exploit` · `container-security-testing` · `瓮中逃.md`。

重点口（探针默认，不是全世界）：`22, 80, 443, 1234, 3000, 6666, 8000, 8080, 8443, 8888, 8889, 9000, 9090`。  
TCP 全通且 HTTP 同码 → **TUN/代理假 OPEN**，禁止报洞。

| 档 | 成立 |
|----|------|
| L1 | CF + 重点口黑洞或假 OPEN；JS 有 knock/HMAC/wss |
| L2 | 敲门序列 / HMAC 钥 / 源站 Host·XFF 出控制台 / 未授权 JSON |
| L3 | 进 Console、PTY 或库查询（截图打码） |

## 4. 授权侦察：怎么认、别怎么浪费子弹

### 4.1 疑似指纹（满足多项再假设）

- 权威 DNS / HTTP 入口在 **Cloudflare**，源站 IP 对常见端口 **全无响应或全丢包**（不像 RST/拒绝服务页）。  
- 业务/登录只经 `*.workers.dev` / 自定义域 CF Proxy；直连解析出的 IP：**超时/黑洞**。  
- 偶发出现 **非标 SSH**（非 22）且仅短时可达，随后又不可达。  
- 浏览器控制台出现 **WebRTC**、H.264 桌面流、PTY/websocket 到高端口。  
- 前端资源极瘦或几乎无磁盘味静态目录；HTML/JS 像「一次性注入」而非常规 SPA 部署树。

### 4.2 侦察分流（授权内）

```text
① scope 已含目标域 / 源 IP（新 IP 先 scope_expand --grant）
② origin_recon + space_search cert-origin + 邮件头 / 历史 DNS
   → 候选源 IP 用 Host / XFF 交给 c2_zt_probe --origin-ip
③ 不要对源 IP 狂扫 1–65535；记录「Global DROP 假设」
④ 攻击面优先：
     · CF 后的合法 Web/API（登录、敲门、keys/apply）
     · 前端 JS / CF Worker：knock、HMAC、wss、ICE、backaddress
     · 同源未加固（CI、备份桶、旧域名）
⑤ 抽出序列才 knock；铸 X-Auth 短窗重放，爆破不超过短字典
⑥ 控制台 / PTY / 库 之一成立再谈 SSH 1234、沙箱 exec
⑦ 找回自有面板：自有密钥重敲门；无密钥按 C 冷冻
```

### 4.3 Triage 口径

| 现象 | 建议分级 | 复工条件示例 |
|------|----------|--------------|
| 仅 CF 入口 + 源站全端口黑洞 + 无密钥/无源码 | **C** | 持有敲门凭据或非 CF 管理入口进 scope |
| 有 Web 业务面可测，主机面黑洞 | 业务 **A/B**，主机旁路 **C** | 主机：源站旁路或运维密钥 |
| 抓到敲门 API 但缺共享密钥 | **B** | 配置/客户端/备份中出现 SPAKE/HMAC 材料 |

## 5. 授权测试时的薄弱点清单（有授权才测）

按优先级，本库命令直接跑，不假设都能打穿：

| # | 面 | 测什么 | 本库命令 | 成功口径 |
|---|----|--------|----------|----------|
| 1 | JS 敲门 / HMAC | bundle 里序列、钥、wss、ICE | `c2_zt_probe extract` / `drive`；`js_secret_hunter hunt` | 抽出序列或钥 = L2 |
| 2 | HMAC 短窗 | `ts\|METHOD\|path` → `X-Auth: ts.sha256` | `c2_zt_probe hmac` 再 drive 重放 | 200 JSON 或可进门 |
| 3 | 源站 Host/XFF | 8080/8888/8889 带正确 Host | `drive --origin-ip`；并行 `trusted_ip_header_probe` | 出 Vue/console，不是 CF 挑战页 |
| 4 | 控制台 API | keys/apply、db/query、sandbox/exec、assets/export | `drive` 默认路径表 | 未授权 JSON = L2 |
| 5 | PTY / WebRTC | `wss://…/pty`；STUN/TURN 泄内网 | `ws_probe.py` | 未敲门进终端 |
| 6 | 敲门后 SSH | 1234 弱口 / 泄露私钥 | 抽出序列后 `knock` 再看 focus-open | 建连成立（改密仍先问） |
| 7 | 沙箱 | `/api/sandbox/exec` 注入 | 交接 `linux-post-exploit` / `container-security-testing` | 逃逸或命令回显 |
| 8 | 弱口 | 控制台 admin/admin 一类 | `auth_brute_probe`（有验证码走 captcha-ocr） | 进 Console |

**不要**：把彩虹易 `return_url` 假相当本链默认洞；未抽出序列就扫 65535；TCP 假 OPEN 报 L2；默认改超管密当持久化。
