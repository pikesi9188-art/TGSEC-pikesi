# Spring 三洞手法：CVE-2025-41243 / 2026-40976 / 2026-22733

## 0. 一句话对照

| CVE | 一句话 | 在本库杀伤链里的位置 |
|-----|--------|----------------------|
| **CVE-2025-41243** | 未鉴权的 Gateway Actuator 上，用 SpEL **改环境属性 / 读敏感配置**（CVSS 10） | Playbook **B2/B4** 加强版：不只 RCE，先做属性篡改与 `@environment` 读 |
| **CVE-2026-40976** | Boot **4.0.0–4.0.5** 在特定依赖组合下，默认安全链**不鉴权几乎所有端点** | 指纹「有 actuator、业务接口也 200」时的**整站未授权**假设 |
| **CVE-2026-22733** | 业务接口挂在 **`/cloudfoundryapplication/**`** 下时可鉴权绕过 | 窄条件旁路；heapdump/云链仍主路径，探针顺手扫 CF 路径 |

共性：**前提几乎都是 Actuator（或同源路径）对攻击者可达且未有效保护。**  
先证「端点裸奔」，再谈洞编号。

## 1. CVE-2025-41243 — Gateway SpEL 属性篡改

### 1.1 官方成立条件（必须同时满足）

1. 使用 **Spring Cloud Gateway Server WebFlux**（**WebMVC 版不受影响**）  
2. 依赖 Spring Boot Actuator  
3. 显式暴露：`management.endpoints.web.exposure.include` 含 **`gateway`**  
4. Actuator **网络可达**  
5. Actuator **未做有效鉴权**

修复：升级 Gateway → **4.3.1 / 4.2.5**（OSS）；4.1.11 / 3.1.11 为企业支持线。  
临时：从 exposure 去掉 `gateway`，或给 `/actuator/**` 上鉴权。

### 1.2 原理（学什么）

Gateway 允许通过 Actuator 动态写路由；路由 predicate/filter 参数里可嵌入 **SpEL**（`#{...}`）。  
校验缺陷时，攻击者可：

1. `POST /actuator/gateway/routes/{id}` 写入含 SpEL 的 filter（常见挂在 RewritePath 等参数）  
2. `POST /actuator/gateway/refresh` 激活  
3. SpEL 求值 → 改 `spring.cloud.gateway.restrictive-property-accessor.enabled` 等 → 放宽属性访问  
4. 再经 SpEL 读 `@environment` / 属性源 → **密钥、DB、云 AK** 等  

与老洞 **CVE-2022-22947**（路由 SpEL → RCE）同族，但 41243 官方描述侧重 **Environment 属性篡改**；实战中读配与 RCE 往往一条链上。

### 1.3 授权作业手法（顺序）

```text
① GET  /actuator/gateway/routes
      /actuator/gateway/routedefinitions   → 200 + JSON？
② 对比：有 Security 时是否 401/403；旁路见 Playbook C1–C4
③ 只读证明：能否 POST routes / refresh（写权限）
④ SpEL 求值证明（低破坏）：写临时路由，表达式只做无害运算或读非敏感属性
⑤ 再考虑：关 restrictive-property-accessor → 读 environment
⑥ 拿明文后：回灌 Jasypt/Redis/Nacos/下游（Playbook F/G）
⑦ 必做：DELETE 临时路由 + refresh；按 IP/HOSTNAME 分桶
```

**成功口径（学习/验证）**

| 级 | 标准 |
|----|------|
| L1 | `gateway/routes` 未授权可读 |
| L2 | 可 `POST routes` + `refresh` 且自建路由出现在列表 |
| L3 | SpEL 求值有回显/副作用（属性被改或可读 env） |
| L4 | 拿到可登录凭据 / 进堆转云链（接 Actuator 堆 Playbook） |

### 1.4 和本库旧手法的关系

- 已有 **B4 SpEL / stale route**：41243 = 官方钉死的「暴露 gateway + 未鉴权」专项。  
- 探针命中 `/actuator/gateway/routes` → **禁止只报 health**，按 Gateway 全链 + 本卡 §1.3。

## 2. CVE-2026-40976 — Boot4 默认安全链失效

### 2.1 官方成立条件（缺一不可）

1. **Servlet** Web 应用（非纯 WebFlux）  
2. **没有**自建 Spring Security 配置，只靠默认 web security filter chain  
3. 依赖 **`spring-boot-actuator-autoconfigure`**  
4. **不**依赖 **`spring-boot-health`**  

影响：**Spring Boot 4.0.0 – 4.0.5**；修至 **4.0.6+**。

### 2.2 原理（学什么）

Boot 4 重构了 actuator/health 模块拆分。默认安全规则在「有 actuator-autoconfigure、无 health」时可能**漏掉授权规则** → 表现为：

- 不只 `/actuator/*`，**业务 Controller 也可能未授权可达**  
- 表面像「忘了配 Security」，根因是框架默认链缺陷  

### 2.3 作业手法

```text
① 指纹 Boot 4：响应头、错误页、/actuator 形态、dependency 泄露
② 抽查：/actuator/env、/actuator/beans 以及 2～3 个业务敏感路径（用户/管理/内部 API）
③ 若「像后台的接口」全部 200 且无登录 → 按 40976 假设扩大枚举（mappings / OpenAPI）
④ 有 heapdump → 直接接堆转云 Playbook（不必死磕洞名）
⑤ 若仅部分 actuator 开、业务仍 401 → 多半不满足「无自定义 Security」条件，降级为普通未授权 actuator
```

**辨析**

| 现象 | 更像 |
|------|------|
| 仅 health 200，env 401 | 正常加固或部分暴露 |
| env/beans/mappings + 业务 API 皆匿名 200 | **重点怀疑 40976（Boot4）或裸奔配置** |
| 只有 gateway routes 200 | 优先 **41243/22947** 族，不是 40976 |

## 3. CVE-2026-22733 — CloudFoundry Actuator 路径鉴权绕过

### 3.1 官方成立条件

1. Web 应用 + classpath 有 **Actuator** + **Spring Security**  
2. 应用把**需要认证的业务接口**映射到 CF Actuator 使用的路径下  
   例：`/cloudfoundryapplication/admin`  
3. Spring 官方也写明：**不推荐**把业务挂在基础设施路径下；预期生产少见  

影响版本线：Boot **4.0.0–4.0.3 / 3.5.0–3.5.11 / 3.4.x / 3.3.x / 2.7.31−**；修至 **4.0.4 / 3.5.12** 等（见官网表）。  
相关但不等价：CVE-2026-22731。

### 3.2 原理（学什么）

Cloud Foundry 平台集成会暴露 **`/cloudfoundryapplication`** 一类基础设施端点；安全规则按「基础设施 vs 业务」划分时，若业务 Controller 挂在同一前缀树下，可能吃到**错误的放行规则** → 认证绕过。

本质是 **路径信任边界画错**，不是通用 RCE。

### 3.3 作业手法

```text
① GET /cloudfoundryapplication
      /cloudfoundryapplication/
      /cloudfoundryapplication/admin
      （以及 mappings 里所有 cloudfoundry* 路径）
② 对比：同接口挂在 /admin 要登录，挂在 /cloudfoundryapplication/admin 却 200
③ 命中后当「未授权业务入口」挖 IDOR/配置/下发令牌；有 actuator 再并堆链
④ 未命中 CF 路径 → 不要在此洞空转
```

## 5. 决策树（背这个）

```text
看到 /actuator 或旁路打到 actuator？
├─ gateway/routes 未授权可写/可读
│    → 按 41243 + 旧 SpEL/RCE 链（B2/B4），再接 dump/Jasypt
├─ Boot4 指纹 + 业务 API 也大面积匿名 200
│    → 按 40976 扩大枚举 + 堆/配置
├─ /cloudfoundryapplication/* 下出现「本该登录」的业务
│    → 按 22733 当未授权入口
└─ 仅 health
     → 继续旁路/heapdump/OpenAPI，勿只结案 health
```

## 6. 常见误区

| 误区 | 纠正 |
|------|------|
| 有 health=有洞 | health 开是常态；要看 **gateway/env/写接口** |
| 41243 一定 RCE | 官方主述是属性篡改；RCE 看表达式能力与版本 |
| 40976 所有 Boot4 都中 | 必须满足「默认链 + actuator-autoconfigure + 无 health」 |
| 22733 优先打 | 条件窄；主链仍是暴露 actuator → dump/云 |

## 7. 练习（实验室 / 授权站）

1. 用 `sgc_probe` 对授权目标出一张「路径 × 状态码」表，标出疑似 CVE。  
2. 对疑似 41243：只做到 **L2（可写路由）** 即停，清理路由；L3+ 需用户确认破坏面。  
3. 把结论写进案卷 `案卷/sgc/CVE_NOTES.md`：命中条件勾选 + 证据路径。
