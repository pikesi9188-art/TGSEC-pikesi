# GIN-VUE-ADMIN 领奖与业务 API 杀伤链

> 参考：（开源包不收个案摘记）（AI 辅助渗透范式）  
> 工具：`炼蛊房/ginvue_admin_probe.py`  
> 结合：CORS Skill · 业务逻辑 · `free_claim_bypass` · JS 挖隐藏 API  
> **管理面静默提权**（注册 `authorityId=888` / 伪造 JWT，默认不改原 admin 密）：见 `锦府·静默.md` · `ginvue_stealth_takeover.py`  
> 授权：仅 `授权范围`。报告里的第三方 IP **禁止**静默扩权。

## 1. 心智（报告 → 可复用）

典型双端口：

| 面 | 指纹 | 优先打点 |
|----|------|----------|
| 管理后台 | `/api/base/captcha` + JWT | **CORS**（`ACA-Origin` 反射 + `Credentials: true`） |
| 领奖中心 | 同框架 `/api/base/*` | **未授权读配置** → 字段探测 → 领奖/逻辑 |

关键洞察（报告已验证）：

1. **验证码在业务/注入之前** → SQLi/IDOR/篡改 payload 全被「验证码错误」挡住；须先过 captcha，再测逻辑。  
2. **未授权 `getConfigs`/`getServers`/`getBConfigs`** 往往比领奖本身更值钱（奖励表 + 服架构）。  
3. **字段名陷阱**：领奖用 `account` 不是 `username`；错字段只回「请认真填写」。  
4. **前端 JS** 常藏 `/breward` `/nreward` `/reward` `/treward` 等未上 UI 的路由。  
5. 与 **免费领付费礼包**分工：Crown 类打「服务端不验 price」；本链打「配置裸奔 + 领奖门禁形态」。

```text
指纹 captcha
  → CORS（后台）+ 未授权 getConfigs/getServers（领奖）
  → JS 挖隐藏 API
  → HPP / 用户枚举（getName）
  → 字段探测（account/configids 类型）
  →（有验证码/会话）再测领取竞态、重复领、configids 篡改
  → 证据 案卷/ginvue/
```

## 2. 命令

```bash
# 指纹 + 未授权泄露 + CORS + JS 隐藏 API（需授权）
python3 炼蛊房/ginvue_admin_probe.py recon \
  --base 'https://授权:端口' --case <案卷> --insecure

# 仅 CORS
python3 炼蛊房/ginvue_admin_probe.py cors \
  --base 'https://授权' --case <案卷> --path /api/user/getUserInfo

# 字段探测（假验证码看错误语义，不真领）
python3 炼蛊房/ginvue_admin_probe.py field-probe \
  --base 'https://授权' --case <案卷> --account test

# 领取矩阵需人工/有效验证码，且 --confirm（耗业务先问）
python3 炼蛊房/ginvue_admin_probe.py claim-probe \
  --base 'https://授权' --case <案卷> \
  --account X --name Y --gid Z --configids 1 \
  --captcha ABCD --captcha-id UUID --confirm
```

## 3. 与引擎内手法对照

| 报告手法 | 本库落点 |
|----------|----------|
| CORS 反射 + credentials | 九阶段 `cors-cross-origin-misconfiguration` + 本工具 `cors` |
| 未授权 getConfigs | 本工具 `recon` / `unauth` |
| HPP `ID=1&ID=50` | 本工具 `hpp`；业务逻辑 Skill「参数污染」 |
| getName 用户枚举 | 本工具 `enum` |
| JS 隐藏 API | 本工具 `js-mine`；web-reverse / recon |
| sendCReward 字段/验证码墙 | 本工具 `field-probe`；过墙后接 `free_claim` / 业务逻辑竞态 |
| OCR 领奖 | **不默认自动化**；人工验证码 + `--confirm` |

## 4. 成功口径

| 级别 | 证据 |
|------|------|
| L1 | 未授权返回奖励/服务器 JSON；或 CORS 对 evil Origin 回显且 credentials=true |
| L2 | JS 挖出隐藏 reward 路由且可触达 |
| L3 | 有效验证码下完成领取 / 重复领 / 越权领（需授权账号范围） |

## 5. 踩坑

- 验证码一次性 + 并发全灭 → 注入矩阵在 captcha 前测会「假阴性」。  
- OCR 30–40% 不稳定，别用自动领奖当结案条件。  
- 管理后台与领奖中心可能不同端口，两个 `--base` 都要扫。  
- 报告目标未授权：只学手法。
