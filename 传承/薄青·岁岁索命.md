# 核心 Web 漏洞面作业手法

> Skill：`杀招/薄青·伤匣`  
> 探针：`炼蛊房/core_web_surface_probe.py`  
> 细卡：SSTI / XSS / LFI / 上传 / CSRF·CORS / PHP 反序列化（本卡只分流）  
> 红线：仅授权。L1/L2 先探；SSTI/XXE/上传 RCE、写马授权内直接做。

---

## 1. 一句话

无专用栈时，**不要只扫目录和 JWT**。侦察后先 `strike_probe`（S1–S8 短字典），再打一遍课程里的核心面：  
XXE · SSTI · 上传/包含 · XSS · CSRF/CORS · 反序列化 · 重置逻辑。  
专卡（假支付 / Actuator / FastAdmin）优先；本卡填「通用 Web」格子。

```bash
python3 炼蛊房/core_web_surface_probe.py -u https://授权站 --case <案卷>
# 套装/广谱用少参数，避免把 kit_run 拖死
python3 炼蛊房/core_web_surface_probe.py -u https://授权站 --case <案卷> --fast
```

落盘：`案卷/core_web/surface.json`

## 2. 指纹 → 档位

| 面 | L1 | L2（探针可做） | 下一跳 |

## 3. 分流（禁止用百科结案）

```text
core_web_surface_probe
  → SSTI L2     → tpl_inject_probe ssti --exec（授权内 RCE/写马直接做）
  → LFI L2      → tpl_inject_probe lfi → .env 回灌假支付
  → XXE L2      → tpl_inject_probe xxe → 切 ssrf_probe 打内网
  → CORS L2     → 带 Cookie 的跨域读；填对象矩阵
  → 上传入口    → 先 marker，再谈解析/.htaccess
  → 重置入口    → ATO 卡（Host 头 / token 可预测）
  → 序列化 Cookie → PHP 反序列化卡（Java 走 Shiro/Fastjson）
  → 全阴        → 业务API未授权 · jwt_gql · 弱口令卡
```

XSS 存储型（客服/IM/备注）探针已有，本卡不重复造：

```bash
python3 炼蛊房/stored_xss_probe.py scan --base https://授权站 --token <用户票> --case <案卷>
```
