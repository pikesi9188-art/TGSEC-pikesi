# 宝黄天·回灌

> 配套 Skill：`杀招/秦百胜·回响`（本卡是假支付严签后的细链，**无独立 Skill**）  
> 挂靠：`秦百胜·假契.md` · `秦百胜·拍卖.md` · Skill `秦百胜·货仓`  
> 学习样本（2026-08-27）：ACG-FAKA **v3.4.8** 主站严签 + 聚合支付后台弱口 → 商户 MD5 key → 合法签出卡

## 0. 一句话

主站 `callback.Epay` 已硬化（`sign:true` / `非法签名`）**不算结案**。  
跟支付页 `submit.php` 到**更弱的聚合支付后台**，短字典进 admin → 列表接口读商户 MD5 key → **合法签**回灌主站 notify → `query` 出卡。

口诀：`weakest_deploy（支付栈）→ bridge（商户 key）→ target_deploy（主站发货）`。

与已有卡的分工：

| 卡 | 打谁 |
|----|------|
| 假支付矩阵 `sign:true` | 主站验签松散（3.4.x **常已修**） |
| 彩虹 submit 回放 | submit 与业务 return **同参数集**（免 KEY） |
| 源码/备份出 KEY | 白盒合法签 |
| **日志/`composer.json`** | PHP 发卡 `storage/logs` 打出 `merchant_pem`/epay key（先于本卡；`sensitive-dir-dump`） |
| **本卡** | 支付栈 **身份**出 KEY，再合法签 |
| ACG 上游库存 | 严签且支付栈也打不开时 |

## 1. 适用指纹

同时出现再套本卡（路径名可换，模式不变）：

| 层 | 信号 |
|----|------|
| 主站 | 异次元 `/user/api/order/callback.Epay`；`pay_matrix` 全变体 `非法签名` / `sign error` |
| 支付页 | 自动提交 form：`pid` / `out_trade_no` / `notify_url` / `sign` / `sign_type=MD5` |
| 支付栈 | 异 host：`/yrpay/epay/submit.php`、标题「聚合支付」、独立 `pay.` / `trade.` |
| 管理面 | `POST /api/admin/login` + Geetest v3/v4；`GET /api/admin/merchants?keyword=` |
| 对照 | 同品牌另一壳（如独立 `pay.`）pid 不存在 → 只打真正 submit 的那台 |

**2026-08 纠正**：ACG **3.4.x** 已拦 `sign:true` / Epusdt `signature:true`；U01 draft 预言机常无。阴性后 **立刻换面支付栈**，勿空转假签、勿先结案去打上游。

## 2. 攻击链（已达成标准）

```text
指纹 ACG 3.4.x + Epay
  → 验证码 OCR 下单 → 支付页泄露 pid + notify + MD5 sign
  → pay_matrix 松散比较 = 非法签名（主站旁路失败）
  → 静默扩权支付栈 host
  → captcha_auto 解 Geetest → POST /api/admin/login 短字典
  → GET /api/admin/merchants?keyword=<pid> → 字段 key 明文
  → 用支付页 submit 参数复算 sign，确认算法 = ksort + key
  → form 合法签 TRADE_SUCCESS → POST 主站 callback.Epay → success
  → POST /user/api/index/query 出 secret
  → 独享 SKU：探针单出卡；num=库存 清空先问
  → 共享交付 URL（非独享卡密）排除交付清单
```

成功口径：**探针单** `query`/`secret` 回明文卡密。仅支付栈 JWT、仅 callback `success` 都不算完成。  
独享 SKU 可用 `num=库存` **验证**控库存能力，**清空先问**。

## 3. 授权作业清单

1. 主站已在 scope；从支付页抽出 `submit` 异 host → `pay_matrix --pay-url` / `scope_expand`（勿再问）。  
2. `pay_matrix` 跑完松散变体；记 `非法签名` 后 **停假签空转**。  
3. 支付栈登录：`python3 炼蛊房/captcha_auto.py solve --url https://支付栈/admin --case <案>`（v4 走 `滑块·破禁.md`）。  
4. 短字典只打 **支付栈** admin（`admin/123456` 等 `auth_brute` 已有表）；主站 `/admin` 未中不要当本卡失败。  
5. 持 JWT：`GET /api/admin/merchants?keyword=<pid>`。响应里 `key` 明文 = VULN。钥只进案卷 `案卷/`，禁止写进可公开同步文档。  
6. 复算支付页 sign，确认与 key 一致后再签 notify（字段集按 Epay：`pid/out_trade_no/money/trade_status/trade_no` + `sign`）。  
7. 主站 `callback.Epay` 回 `success` 后立刻 `query`（订单号或下单邮箱）。  
8. 独享货：探针单出卡即可；`num=库存` 清空先问。共享货 / 跳转交付链不进「出卡」清单。  
9. 测完：STATUS 写 `weakest_deploy / bridge / target_deploy`；轮换建议留给修复段，勿在生产乱改超管密。

## 4. 查单 secret（版本差）

| 形态 | 行为 |
|------|------|
| 旧卡记忆 | `query` 只出订单元数据；卡密在 `/secret` 且先验已付 |
| **3.4.8 实锤** | `POST /user/api/index/query` `keywords=订单号\|邮箱` 可直接带已付单 `secret` |

未付单仍不出卡。邮箱撞库 / 订单号枚举属 **二次窃已购卡**，与假付并行记一笔，不替代本卡主链。

## 5. 复测 / 否定

| 条件 | 含义 |
|------|------|
| 支付栈短字典全失败 | 本卡暂停；转上游库存 / 源码 KEY / 主机 |
| 商户 key 仅掩码 | 试补单 / batch-supplement 是否另泄；否则换面 |
| 旧 key 签 notify 仍 `sign error` | 钥已轮换或算法变体；对照支付页现活 sign |
| 伪造 success 但 query `status=0` 无 secret | 假成功（要二次查单）；转打支付栈补单 API |
| 主站 Entrance 未挖 | 已出卡可收工；未出卡再补 Entrance |
