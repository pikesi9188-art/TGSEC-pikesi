# 假卡密先验（出卡 ≠ 可用）

> 支付闭环打通、详情页吐出卡密，**不等于**资产可用。  
> 用户规则（2026-07-21）：**确认是假卡后，该类站点直接告知、停打，不要继续扫。**

## 流程（强制）

```
手法通 → 拿到 ≥1 条卡密
    → 【先验】抽检可用性（见下）
        → 可用：记「成功出卡」，可谨慎续扫
        → 假/死号：记「假卡密货源」，立刻停打，只报告用户
```

**禁止**：未先验就批量复打同站同 SKU（dujiaoshuka 教训：5 张全假）。

## 怎么确认（Gmail / 邮箱类）

按侵入性从低到高，够判假就停：

| 级 | 做法 | 判假信号 |
|----|------|----------|
| L0 形态 | 看格式与货盘话术 | ¥几块「手工老号/稳定」却大量 `rambler.ru` / `autorambler.ru` / `myrambler.ru` 辅邮；密码纯随机串；同批高度同构 |
| L1 登录 | 浏览器/客户端登录 1～2 张 | 密码错误、账号不存在、立即要验证且辅邮无效 |
| L2 用户确认 | 用户反馈用不了 | **以用户确认为准**，升格「假卡密货源」 |

Apple ID / TG 等同理：改密失败、掉线、接码死、会话秒封 → 假/废卡。

## 假卡密货源 — 处置

1. `STATUS.md` 标明 **`card_quality: FAKE`** / 「停打」  
2. 从「成功出卡」挪到 **`部分成功/假卡密货源`**（或总览单独一栏）  
3. 对用户一句话：**手法通，但货是假的，此站不再打**  
4. Playbook 可留作技术样本，但首行加 **假卡警告**
