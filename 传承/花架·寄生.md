# Laravel 双扩展上传 RCE 手法（CVE-2026-49972）

> 情报：`od_kit.py cvebase lookup --cve CVE-2026-49972`  
> 指纹：`tools/1day-kit/custom-templates/laravel-mediable-upload-rce-cve-2026-49972.yaml`  
> 总览：`新伤·在野.md`  
> 红线：仅 `授权范围`；上传 webshell **先问**

---

## 1. 一句话（两条件同时成立才叫 RCE）

| 条件 | 说明 |
|------|------|
| **A. 包** | 使用 **laravel-mediable &lt; 7.0.0**，上传面可达（描述为未授权可传） |
| **B. Web 服** | Apache/Nginx **误配**：文件名里带 `.php` 就会当 PHP 执行（如 `shell.php.jpg`） |

库用 `PATHINFO_FILENAME` 取基名时**保住内层 `.php`**；MIME/后缀校验以为是图片，落盘后却可被引擎执行。  
修复：`laravel-mediable >= 7.0.0`。别名/相关：`CVE-2026-4809`（同族上传面，以公开 advisory 为准）。

非 KEV · EPSS 偏低 · 本库仍收：发卡/业务站 Laravel 面常见。

---

## 2. 档位与成功口径

| 档 | 动作 | 成功证据 |
|----|------|----------|
| **L1 栈** | `XSRF-TOKEN` / `laravel_session` / `composer` 线索 / mediable 路由 | Laravel + 上传相关路径 |
| **L2 上传** | 授权内传无害双扩展探测文件（非马） | 文件被接受并给出可访问 URL |
| **L3 执行** | 访问 `*.php.jpg`（或同类）出现 PHP 执行特征 | 代码执行回显；**先问再传马** |

```bash
python3 tools/1day-kit/od_kit.py nuclei --url https://授权站 --case <案卷> \
  --template-id laravel-mediable-upload-rce-cve-2026-49972
python3 tools/1day-kit/od_kit.py cvebase lookup --cve CVE-2026-49972
```

只满足 A 或只满足 B → STATUS 写「半条件」，勿报 RCE。

## 3. 旁路：Socialite Facebook 重放 id_token（CVE-2026-73683）

Facebook provider `getUserByOIDCToken()` **不校验 nonce**。签名/`aud`/`iss` 通过后，捕获的未过期 `id_token` 可重放到 `userFromToken()`，登录受害者账号。

L1：站点用 Laravel + Socialite Facebook 登录。  
L2：授权内用**自控 Facebook 测试号**的 token 验证重放；不要打生产用户。

与 mediable 上传不是同一条链。8/15 日报收这条（8/14 Tenable 上架、昨日漏收）。
