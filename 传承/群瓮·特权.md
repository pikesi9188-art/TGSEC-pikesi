# K8s 特权 Pod 手法

> 分流：`瓮中逃.md` · `反客·总诀.md`  
> 检测：`linux_lpe_checker.py` 的 `LOCAL-K8S-SA`  
> 红线：仅授权集群。创建特权 Pod / pods/exec 授权内直接做。删 Namespace、清集群、覆盖生产 DaemonSet 先问。

---

## 1. 一句话

容器内若挂了 **ServiceAccount token**，且 RBAC 能 **建 Pod / 改 Deployment**，可起一个 **privileged + hostPath: /** 的 Pod → 等价宿主机 root。  
这是容器逃逸的 **K8s 控制面** 路径，与 docker.sock 并列，不要和内核逃逸混。

---

## 2. 开场检查（在容器内）

```bash
ls -l /var/run/secrets/kubernetes.io/serviceaccount/
cat /var/run/secrets/kubernetes.io/serviceaccount/namespace
# token 勿完整写入可同步文档
kubectl auth can-i create pods --all-namespaces 2>/dev/null
kubectl auth can-i '*' '*' --all-namespaces 2>/dev/null
env | grep -i kube
```

无 `kubectl` 时：用 SA token 调 `https://kubernetes.default.svc/api/v1/...`（集群内）。

| 信号 | 含义 |
|------|------|
| SA token 可读 | 有身份 |
| `can-i create pods` = yes | **L2 候选** |
| cluster-admin / `*` | 几乎必能特权 Pod |
| 只能 get 自己 namespace | 降权；改收割 ConfigMap/Secret |

---

## 3. 档位

| 档 | 动作 | 成功证据 |
|----|------|----------|
| **L1** | SA/namespace/RBAC 探测 | 权限清单落 `接管/lpe/k8s.json` |
| **L2** | 读 Secret/ConfigMap（只读） | 云 AK、DB 密 |
| **L3** | 建 privileged + hostPath Pod（授权内直接做） | 宿主机根盘或节点 root |

```text
L1 SA 存在
  → 先 L2 读 Secret（常已够支付 KEY）
  → 有 create pods → L3 建特权 Pod
  → 无 RBAC → 退回容器逃逸卡（sock/cap/内核）
```

---

## 4. 交接

| 发现 | 切到 |
|------|------|
| 无 K8s、只有 docker.sock | `瓮中逃.md` L2 |
| 已到节点 root | 隧道 / 横向 |
| 只要业务密钥 | L2 Secret 即可，不必起特权 Pod |
