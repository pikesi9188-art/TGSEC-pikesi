# TG 号库投递 / 清库 / 社工推进

> 资产恢复用：自有或授权找回的 Telethon session 入库、验活、按区号整理，以及技术面穷尽后的代理/客服社工推进。  
> 全文坑：`智道藏书/旁支传承/skills/tg-account-session-intake/SKILL.md` · `tg-account-library-ops` · `autonomous-social-engagement`  
> 路径统一到本库 `案卷/_tg_accounts/`。

## 1. 路径

| 角色 | 本库位置 |
|------|----------|
| 号库根 | `案卷/_tg_accounts/` |
| 投递inbox | `_tg_accounts/inbox/<批次>/` |
| 盘点 | `_tg_accounts/INDEX.json` |
| 清库备份 | `_tg_accounts/trash_<区号>_<时间>/` |
| 云控解出的 session | 各案卷 `接管/`（Fernet 解密产物） |

不要用 `/opt/data`、不要写外部 bot 的 `MEMORY.md`。摘要写案卷 `STATUS.md` 或 `_tg_accounts/INDEX.json`。

## 2. 投递入库

用户丢来 `.session` / 发货 zip / 协议包+直登包：

```bash
python3 炼蛊房/tg_account_lib.py intake <zip或目录> --batch <批次名>
python3 炼蛊房/tg_account_lib.py scan
```

规则（原卡，必须遵守）：

- JSON 里有 `session_string` 优先于 `.session` 文件。
- 同号多镜像：新 `.session` 与旧文件 md5 不同 → **全部镜像覆盖**，否则会拿失效旧钥。
- 阶段①只做 verify + dump 对话；点 bot 按钮 / 登平台要用户再说一次。
- 用户说「停」立刻停后续请求。
- `gAAAAA` 密文先走 `fernet-session-decrypt`，解出再入库。

验活（有 Telethon 时）：`is_user_authorized` → `get_me`；批量并发别太大。吊销（双 IP）通常不可恢复。

## 3. 清库

```bash
# 先看盘子
python3 炼蛊房/tg_account_lib.py scan --extra ~/Downloads

# 预览：删 51 段，保留 KEEP
python3 炼蛊房/tg_account_lib.py purge --cc 51 --keep-file keep.txt

# 确认后再
python3 炼蛊房/tg_account_lib.py purge --cc 51 --keep-file keep.txt --apply
```

- 「51」是区号不是数量。KEEP 必须是完整手机号。
- 先拷 `trash_*` 再删；用户主号不在 KEEP 里也要单独提示可从 trash 回。
- 只动 `.session/.json/.txt` 和 zip 内账号条目，**绝不**按纯数字名删 `.js/.sqlite`。
- 终端显示 `****` 是打码，判断用真实文件名 / `+519` 前缀。
- `purge` 会重建混合国 zip（剔除该区号、保留其它国）；纯该国 zip 整包进 trash。先预览再 `--apply`。

## 4. 社工推进（资产恢复）

技术面 1–6（换注册/接口/攻击面/数据源/信息收集/其它技术）**穷尽后**才转社工。入场券至少一条：

1. 已有可登录 session / 平台身份  
2. 有客服/招商/管理员 TG  
3. 已有对话可续  
4. 前端泄露对接人  

```bash
python3 炼蛊房/social_engineer_agent.py analyze -d <授权域>
python3 炼蛊房/social_engineer_agent.py run -d <授权域> --goal agent_url
```

持续盯回复：状态文件落 `案卷/<案卷>/案卷/social_monitor_state.json`（每线 `max_id`）。  
人设固定、不重复刷、对方说「明天」就停追。目标是拿回 **代理后台 URL / 加白 / 报表入口**，不是骚扰无关第三人。

话术生成用 `social_engineer_agent.py`；监控循环细节见扩展包 `autonomous-social-engagement`。
