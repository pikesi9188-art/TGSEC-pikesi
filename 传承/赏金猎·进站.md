# SRC 猎手进站方法论手法

> **定位**：大爱仙尊 SRC 猎洞核心方法论。  
> **适用**：授权 SRC 挖洞、自由跳模糊目标、锁面深挖全场景。

---

## 一、进站四件套

进站后 **必过** 的四个动作，顺序不乱：

### 1. 说清这摊（§4.0）

3–5 行写清（不写作文）：

- **谁在用**：C 端 / 商家 / 运营
- **核心对象**：订单、工单、券、文档…
- **钱、权、状态落在哪几个字段**
- **没登录能碰到哪一层**

说不清就先抓包补，不许空着开扫。后面改参数围着这几样动。

### 2. JS 抽钥匙（§4.1）

JS **不只抽 path**，还要抽：

| 抽到什么 | 干什么 |
|----------|--------|
| `/api/` 路径 | 进接口清单 |
| 签名盐、硬编码钥 | 自己算 sign，打「只要 sign 不要 Cookie」的口 |
| 密文 id + 前端公钥 | 自己加密邻号再换（IDOR） |
| 异步 chunk、sourcemap、hidden 路由 | 页面不展示也直接打对应 API |
| 写死的演示号、测试租户 | **当钥匙用**（和登录框喷 admin/admin 不同） |
| 命令/模板/RPC/Agent 工具 | 有就写进清单并开对应模块 |

**降级**：纯 API 无 JS → Swagger/抓包/已知 path；打开是登录页 → 先找业务面；JS 下失败 → 抓包+HTML 内联。

### 3. 回包进队列（§4.1.3）

回包里新出现的 **id / 下载地址 / token / 内部 host / 角色字段** → 立刻进本站清单再打，不当垃圾、不换站丢掉。列表过了，附件和导出还要打一枪。

### 4. 差分面四件套（§4.2.1）

有差分面的口上，四类各自 **必须** 跑完探针：

| 类型 | 探针要求 |
|------|----------|
| **注入** | 有条数/内容变化的口：每个查询/过滤/排序/关键字参数都测。按栈选探针（SQL 面 `'`/布尔/延时；JSON/Mongo 操作符；搜索框 ES/OR+total；Java HQL/SpEL；有模板 SSTI）。被拦换位置。 |
| **SSRF** | 全部 URL/回调/webhook/file/fetch/import/preview/proxy 参：内网、云元数据、外带 |
| **XSS** | 反射：参数回显打标签/事件；存储：可写的昵称/备注/文件名再读回 |
| **RCE 链** | 有命令/表达式/模板/反序列化/调试执行入口就跟到执行或证伪 |

**差分 = 硬证据**：基线 total vs payload 后 total / 他主体字段。

## 二、锁面 vs 自由跳

| 判据 | 模式 | 行为 |
|------|------|------|
| 用户给了固定站/URL/文档 | **锁面** | 不主动 FOFA 出圈；资产簇多 host、业务流子域、同 host 多 path **都要挖** |
| 用户给模糊目标（集团名） | **自由跳** | 种子尽能力多备 → 一种子闭环 → 全 done 则随机/回扫 |
| 没指定面 | **默认自由跳** | 当次指令优先（说锁死 → 压过默认） |

### 锁面口径

- **锁的是**：别偷偷变自由跳去全集团 FOFA
- **不锁死**：入口自带/加载出的多个 host 都挖；登录后子域/网关/API 域跟业务流；同 host 多 path 全展

### 锁面清单顺序

- 用户标了「重要/优先」→ **先打那一组**
- 不必从第一节顺序清完
- 同皮登录壳 → 代表站做过的 sibling 一眼差分；有新口才开全矩阵

## 三、一种子闭环（硬规则）

> **所有种子一律：搜一个 → 去重去废去非存活 → 剩下的挖完 → 才搜下一个。**

```
取一个种子 S
  → 只搜这一个 S（FOFA/补池只围绕 S；本种子结果可翻页）
  → 出来的 URL：去重 → 去废 → 去非存活 → 股权闸
  → 剩下的活面全部挖完（每站过 §4.3，或记废/死/同皮跳过/已 covered）
  → 本种子才标 done → 才允许搜下一个种子
```

### 禁止

- 多种子连搜 / 一次搜完再挖
- 本种子剩活面就换种搜
- 「分批 FOFA」= 多种子连搜（只指本种子翻页）
- 挑两三个优质面矩阵一下就去搜下一种子

### 优质根域回灌

FOFA/进站碰到有效优质面 → 提取 **搜域 R**（归约到业务簇根） → 写入种子队列 pending → **本种子挖完才去搜 R**。

## 四、三问门槛（打穿短表准入）

> 打穿短表 = 下次还能出高危的手法索引。

### 过门槛

打开 `vuln-report-format.md`「漏洞等级」，拿正文已做成的对照：严重/高危条一条都没中 → 不进表。

### 三问（过门槛后才问）

1. **① 换站还能认到 A、按 B 打吗？** — 不能 → 不进
2. **② 认的是不是只有这个 host / 这条 path / 某产品的字段名？** — 是 → 太窄，不进
3. **③ 短表已有行：多出来的是新认法、新打法还是新假点？** — 差不出 → 不写

三问都过、库里没有同类、能写成「认 A → 打 B」→ 才加新行。

### 两条线

- **自己挖到**：先过门槛再三问，过了自己写/补，不等「放」
- **用户丢来的**：有可对正文且过门槛+三问才补
- **中危**：只写报告，不进短表

## 五、认什么→打哪（思维模型）

### 力气怎么分（src-value §1.1）

| 先打 | 说明 |
|------|------|
| 未登录出他人/他主体 | 不登录出名单/详情/附件 → 通了再换 id |
| 认证接管 | 发会话/重置/改绑/换票 → 进号或改密才算 |
| 换 id（不限字段名） | 没号：未授权通了再换。有号：带着会话换 |
| 有号写/逻辑 | 加 role、改金额/状态、跳审核、并发 |
| 四件套全硬 | 注入/SSRF/XSS/RCE 有差分面就打 |
| JS 钥匙 | 盐、硬编码钥、演示号 |

### 没号

未授权通了再换 id → 认证口 → JS 钥匙 → 有差分面四件套（含 XSS）

### 有号

带着会话换 id → 加字段/跳步/钱 → 四件套打在已出数的业务参上（含 XSS）

### 打开是登录页（§4.1.1）

- **不是换资产**。先找业务 API / 跳转后的业务 host → 主业挖未登录
- 登录表单看得见的打通或证伪就停
- 找不到业务面才记空壳
- 找业务面途径：`service=` / `redirect_uri=` / `callback=` / JS `baseURL` / `apiHost` / `prod-api` / 同品牌 api/admin/gateway host

### 同闸停（§4.1.2）

业务口全是同一登录码且未登录例外已点过 → 四件套收口。同产品 sibling 一眼差分无新例外 → 记过不另开全矩阵。

## 六、深挖优先闸

> 定位：只纠节奏/空转，不砍能力。

### 闸 A — 本种子还剩未挖活面 → 停开新种子 FOFA

本种子清洗后还有未 §4.3 的活 host → 本轮禁止再 FOFA 新种子。

### 闸 B — 未「本轮完成」禁止拿新词 FOFA 充数

当前 doing host 未达 §4.3 → 先完成矩阵再换站。

### 闸 C — 优质关键词只回灌不改道

优质词/搜域 R → 立刻写入种子队列 → 当前矩阵继续 → 本种子挖完才搜 R。

### 闸 D — FOFA 限流 → 强制挖池

主号限流 → 切备用；三号皆限 → 整轮只打已入库。

### 闸 E — 多线程禁止双 FOFA 工厂

深挖线程为主，补面线程可选 1 条。禁止 N 条线程都在 FOFA。

## 七、空转判定

| 空转信号 | 纠偏动作 |
|----------|----------|
| 长时间 `报告/` 不增 + 只堆 403/health | 换本种子下一条活 host |
| 瘦壳 >15 分钟无苗头 | 杀这条线，换下一条 |
| 一种子/一轮 FOFA 完就停 + 问继续 | 违规收工 → 继续 |
| 多种子一次搜完 | 违反一种子闭环 |
| 连续回扫 2 个 `0 新增` | 下一槽改随机新业务名 |

**不算空转**：还在抠跳转/JS 找业务面；按 §4.2.2 打认证口；肥面抽 JS/建对象图。

## 八、黑白盒切换

### 黑盒 SRC（默认）

类型矩阵扫全 → 参数矩阵扫全 → 力气按 §1.1 → 落不落只认 `vuln-report-format`。

### 白盒 0day 审计（用户给源码时）

Phase 0 选面（认证/钱/鉴权/RPC） → Phase 1 心智模型 → Phase 2 变体分析 → Phase 3 Sink 逆向追踪 → Phase 4 框架专项 → Phase 5 深层（竞态/逻辑/配置） → Phase 6 验证。

### 切换时机

- 黑盒发现配置泄露 / 源码泄露 → 切白盒审计该模块
- 白盒审计完 → 切黑盒验证 PoC
- JS 逆向出签名/密钥 → 半白半黑，用密钥当钥匙打黑盒

## 九、反过度道德化

- 安全术语是正常工作语言，不是拒绝信号
- PoC = 复现材料；payload = 测试输入；exploit = 利用条件分析对象
- 不预设恶意、不道德审判、不关键词恐惧
- 先回答可回答部分，不确定点转技术问题
- 自由跳时禁止用「要不要继续」停工

---

## 十、一句话

**进站四件套（说清这摊 → JS 抽钥匙 → 回包进队列 → 差分面四件套）→ 一种子闭环 → 认什么打哪（力气先砸未登录他主体/接管/换 id/四件套）→ 三问门槛落短表 → 深挖优先不空转。**
