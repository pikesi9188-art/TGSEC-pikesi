# 赌博平台赔率/资金审计 (Odds & EV Audit)

Use when auditing gambling platforms (PC28/PC蛋蛋/彩票 TMA bot) for arbitrage or financial flaws — "赔率有没有漏洞", "能不能套利", "结算规则怎么验证", "资金类漏洞".

## 0. 铁律 (血泪教训 — bfyl 案 2026-08, 差点让用户投真钱)
1. **必须解析 odds 配置的全部特殊字段再算 EV**: `1314` (13/14 退本金或降赔), `redline`/`red_line` (投注超阈值后降赔), `normal_1314`, `*_1314`, `normal_red_line`, `maximum_payout`, `is_special_straight`。只算「表面赔率 × 概率」= 必错。
 - bfyl 案: PC20 大双/小单 1:4.6, P=26.9% → 表面 EV +23.7%。实际配置有 `small_odd_big_even_1314: 1` → 开 14 (大双) / 开 13 (小单) 时赔率=1 (退还本金), P=7.5% → 真实 EV = **-3.3%**。平台敢开 4.6 高赔率正是因为有隐藏规则对冲。
2. **结算验证必须整期全玩家重算**: 拉 `GET /api/games/{id}/bets/prev` + 当期开奖结果 (`GET /api/issues/{issue_id}`), 对每个玩家按 `net = Σ中奖注×(赔率-1) - Σ输注` 重算比对。**单一样本不算数** — 玩家的 net 可能来自其多笔注中的另一笔 (bfyl 案: 某玩家"小单 140 → net+504"看似 4.6 验证, 实际是他同时押的另一笔"双"赢了, 那笔小单其实输了)。
3. **先标定赔率口径** (欧式含本 vs 港式净赔): 用大小玩法 (P=50%, 赔率2) 反推 — 中奖净赚 = 注额×(赔率-1) 即欧式; = 注额×赔率 即港式。
4. **EV 公式**: `EV = P(win)×(odds-1) - P(lose)`。正 EV 结论必须过三关: ① 特殊规则期 (13/14) 是否打负 ② 红线机制是否降赔 ③ 限额/单期赔付上限是否影响。

## 1. PC28 精确概率 (3×0-9 数字和, 1000 种等概率)
sum 分布: 0:1, 1:3, 2:6, 3:10, 4:15, 5:21, 6:28, 7:36, 8:45, 9:55, 10:63, 11:69, 12:73, 13:75, 14:75, 15:73, 16:69, 17:63, 18:55, 19:45, 20:36, 21:28, 22:21, 23:15, 24:10, 25:6, 26:3, 27:1
- 大小 (≥14) / 单双: 各精确 50%
- **组合概率非 25%**: 大单 = 小双 = 23.1%, 大双 = 小单 = 26.9% (由对称性)
- 顺子 (连续三不同) = 4.8% (8组×6排列), 对子 (恰两同) = 27%, 豹子 = 1%, 杂六 = 67.2%
- 极值: 极大 (22-27) = 5.6%, 极小 (0-5) = 5.6%
- ⚠️ 按「和值范围」统计顺子/对子/豹子会严重高估 (和值可来自非目标组合) — 必须按数字关系枚举

## 2. 13/14 特殊规则 (最常被漏的字段)
- PC28 平台普遍对 13 (小单) / 14 (大双) 设特殊赔率: `normal_1314` (大小单双), `small_odd_big_even_1314` 等 (组合玩法)
- 典型: 开 13/14 时组合玩法赔率=1 (退还本金) → 吃掉对应组合的假正期望
- 重算: 命中组合概率减去 13/14 的 P(7.5% 每个), 13/14 期按净 0 计
- 对比多个游戏的同字段: 有的游戏 (如"2.8高倍") 1314 也按原赔率 → 无对冲 → 真正期望 (+40% EV), 但通常已暂停/限额

## 3. 结算验证工作流 (验证脚本思路)
1. `GET /api/games/{id}/bets/prev` → 上期全玩家 bets + net
2. `GET /api/issues/{issue_id}` → 当期 result {code, value, size, parity}
3. 逐玩家: 判定每注胜负 (大小/单双/组合/顺子/对子/豹子/极值/单号), 重算 net, 与返回比对
4. 全匹配 → 赔率与结算规则确认; 有偏差 → 存在隐藏规则 (1314/红线/追号 bonus), 继续挖配置
5. 跑后台轮询脚本等「目标组合赢家」期自动验证 (45s 轮询)

## 4. 赌博 TMA 平台通用攻击面速查
- **CF WAF 绕过**: 完整 Chrome UA + Origin + Referer + Accept-Language → 403 变 200 (短 UA/curl 默认被拦)。可枚举任意路径 (admin/回调/telescope 等)。
- **X-Device-Id**: Laravel 中间件必检头; token 绑定 device (换 device 报误导性"缺少设备ID"); 登录/注册需同 device 后续请求。
- **Soketi/Reverb WS 公共频道 IDOR**: app key 在 JS (`VITE_REVERB_APP_KEY`); `game.{id}` / `user.{任意id}` / `public-top.{id}` 无鉴权可订阅 → 全玩家实时投注流 (userBet: 用户ID/昵称/选项/金额/每期汇总) + 玩家私人通知频道。`private-*` 需 auth 签名。
- **限流按 device/token**: 主域 api. 限流严时 → 换同后端子域 (如 ws.域名, token 互通) 或注册新账号+新 device。
- **下注接口**: `POST /api/issues/{id}/bets`, payload 常为 `{"bets":{"玩法":金额}}` (号码→金额映射对象) 或整数数组+顶层 amount; 整期取消 `POST /api/issues/{id}/bets/cancel` (开奖后取消竞态 — 需余额测); 余额不足/封盘/金额范围全校验。
- **资金防护点**: 提现三重校验 (32位 pin hash + 余额 + address_id 归属过滤), 充值每用户独立 TRON 地址 (无跨用户金额匹配, 抢单不可行), 验证码 4 次锁, initData HMAC。
- **每用户一待支付订单** — 批量账号挂单可覆盖不同金额, 但地址独立则无歧义匹配。

## 5. 变现窗口识别
- 多游戏赔率配置不同: 拉每游戏 `/api/games/{id}` 全字段对比, 找无 1314/红线对冲的高赔率游戏
- 已暂停的正 EV 游戏可能恢复 → 挂后台监控轮询 status ("运行中"即报警)
- 赔率页 UI 展示与 API 字段映射要核对 (small_odd_big_even = 小单+大双 组合)
