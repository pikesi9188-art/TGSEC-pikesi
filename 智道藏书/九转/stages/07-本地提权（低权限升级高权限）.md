# 07. 本地提权（低权限升级高权限）

> 写作原则：本章按图中第 7 个板块整理，面向授权靶场、本地样本、企业加固和应急排查。本章重点讲权限模型、提权证据、漏洞事实来源和防守检查，不输出真实系统提权利用代码。

## 1. 这个板块到底在干什么？

大白话：你已经进了一个房间，但只是普通访客。提权就是看能不能变成管理员、root、SYSTEM，或者拿到更高权限的数据访问能力。

提权通常分两类：

```text
漏洞提权：系统/内核/服务有已知漏洞，低权限用户能升高权限。
配置提权：权限、服务、计划任务、sudo、文件 ACL、凭证泄露配置错误。
```

事实依据：

- MITRE ATT&CK 的 Privilege Escalation 战术描述了攻击者尝试获得更高权限的技术集合。[^mitre-privesc]
- MITRE T1068 “Exploitation for Privilege Escalation” 描述了通过软件漏洞提升权限。[^mitre-t1068]
- NIST SP 800-115 把渗透测试看作在授权范围内验证安全弱点影响的活动。[^nist-800-115]

## 3. 先理解权限模型

### 3.1 Windows 常见权限层级

| 身份 | 大白话 |
|---|---|
| 普通用户 | 只能操作自己的文件和被授权资源。 |
| 本地管理员 | 可安装服务、改系统配置、访问更多本地资源。 |
| SYSTEM | 本机最高本地服务身份之一，很多系统服务运行在该上下文。 |
| 域用户/域管理员 | Active Directory 域环境下的身份，影响范围可能跨机器。 |

Windows 提权常看：

- 服务权限；
- 计划任务；
- 注册表启动项；
- 可写目录；
- UAC 配置；
- 补丁缺失；
- 凭证缓存；
- SeImpersonatePrivilege 等特权。

### 3.2 Linux 常见权限层级

| 身份 | 大白话 |
|---|---|
| 普通用户 | 普通 shell 权限。 |
| sudo 用户 | 可按 sudoers 规则以更高权限执行命令。 |
| root | 系统最高权限。 |
| 服务用户 | `www-data`、`nginx`、`mysql` 等，权限通常受限但能访问业务文件。 |

Linux 提权常看：

- sudoers 规则；
- SUID/SGID 文件；
- cron 计划任务；
- 可写脚本/服务文件；
- 内核版本；
- Docker 组权限；
- 环境变量和 PATH 劫持；
- 敏感文件权限。

## 4. 漏洞提权：必须绑定 CVE 和版本

### 4.1 Sudo Baron Samedit（CVE-2021-3156）

Qualys 披露了 Sudo 堆溢出漏洞 CVE-2021-3156，又名 Baron Samedit，影响多个类 Unix 系统上的 sudo 版本。[^qualys-baron]

学习点：

- 不是“有 sudo 就能提权”；
- 要看 sudo 版本、系统发行版补丁、编译选项；
- 报告要写清楚本机版本和补丁状态。

### 4.2 Dirty COW（CVE-2016-5195）

NVD 记录 CVE-2016-5195 是 Linux kernel 内存子系统 copy-on-write 竞争条件漏洞。[^nvd-dirtycow]

学习点：

- 内核漏洞通常影响面广，但补丁状态差异很大；
- 靶场复现不等于生产可利用；
- 生产环境验证要格外谨慎，因为内核级行为可能导致系统不稳定。

### 4.3 PrintNightmare（CVE-2021-34527）

Microsoft 官方记录 CVE-2021-34527 与 Windows Print Spooler 远程代码执行漏洞相关。[^ms-printnightmare]

学习点：

- Windows 服务配置和域环境权限会影响漏洞风险；
- 关闭或限制不必要服务是重要加固手段；
- 提权类漏洞要看补丁、服务状态和权限条件。

## 5. 配置提权：比 CVE 更常见

### 5.1 Windows 配置提权检查

| 检查项 | 大白话解释 | 证据 |
|---|---|---|
| 服务路径未加引号 | 路径含空格时可能被错误解析 | 服务配置截图/命令输出。 |
| 服务可写 | 低权限用户可改服务二进制或配置 | ACL 输出。 |
| 计划任务可写 | 可替换任务执行脚本 | 任务配置与文件权限。 |
| 启动目录可写 | 登录时自动执行恶意文件 | 目录 ACL。 |
| AlwaysInstallElevated | MSI 安装策略错误 | 注册表键值。 |
| 凭证文件 | 明文配置、脚本、备份 | 文件路径和权限。 |

### 5.2 Linux 配置提权检查

| 检查项 | 大白话解释 | 证据 |
|---|---|---|
| `sudo -l` 规则过宽 | 某命令可 root 执行 | sudo 规则输出。 |
| SUID 文件异常 | 普通用户能以文件属主权限执行 | 文件列表和 hash。 |
| cron 脚本可写 | root 定时执行可写脚本 | cron 配置和权限。 |
| PATH 劫持 | 高权限脚本调用相对命令 | 脚本内容和环境。 |
| Docker 组 | Docker 权限常接近 root 风险 | 用户组与 Docker socket 权限。 |
| 明文凭证 | 配置文件、history、env | 文件路径、权限、脱敏片段。 |

## 6. 进程内存与 heapdump：取证不是“随便翻秘密”

### 6.1 heapdump 是什么

大白话：heapdump 是 Java 进程某一时刻的内存快照。里面可能有对象、字符串、配置、Token、连接池信息等。Spring Boot Actuator 文档中列出 heapdump endpoint，可返回应用 heap dump 文件；生产环境是否暴露该端点需要严格控制。[^spring-actuator]

风险：

- 可能包含访问令牌；
- 可能包含数据库连接串；
- 可能包含用户数据片段；
- 文件很大，容易泄露隐私；
- 下载 heapdump 可能给服务带来压力。

### 6.2 取证原则

```text
1. 只在授权窗口和本地/隔离环境操作。
2. 优先确认端点是否暴露，不直接下载大文件。
3. 如需下载，记录大小、时间、哈希、保存位置。
4. 分析时只提取必要证据，敏感值脱敏。
5. 复盘后按数据保留策略加密保存或删除。
```

### 6.3 进程内存凭证风险

MITRE T1003 “OS Credential Dumping” 描述了攻击者从操作系统或软件中获取凭证的技术，包括 LSASS memory 等子技术。[^mitre-t1003]

防守角度：

- 限制调试权限；
- 启用 Credential Guard 等保护；
- 监控异常读取敏感进程内存；
- 对 dump 文件进行敏感数据管控；
- 生产环境关闭不必要的诊断端点。

## 7. 提权证明分级

| 级别 | 说明 | 示例 |
|---|---|---|
| hypothesis | 只是怀疑 | 系统版本可能受 CVE 影响。 |
| observed | 有证据 | 版本号和补丁缺失已确认。 |
| primitive | 基础原语成立 | 低权限用户可写服务文件。 |
| local_proof | 本地靶场复现 | 同版本虚拟机复现提权。 |
| remote_proof | 授权目标验证 | 授权窗口内证明权限边界被突破。 |

报告要避免夸大：

```text
发现 kernel 版本老 ≠ 一定能 root
发现 sudo 规则异常 ≠ 已拿 root
下载 heapdump ≠ 已经掌握全部凭证
```

## 8. 真实案例

### 案例 1：Baron Samedit

Qualys 披露的 CVE-2021-3156 说明，一个广泛部署的本地工具 sudo 也可能成为本地提权入口。这个案例提醒：**补丁管理不只看 Web 服务，也要看系统基础组件。**[^qualys-baron]

### 案例 2：Dirty COW

Dirty COW 是 Linux 内核 copy-on-write 竞争条件漏洞，NVD 记录其影响 Linux kernel。这个案例提醒：**内核版本和发行版补丁状态是本地提权排查的关键字段。**[^nvd-dirtycow]

### 案例 3：Actuator heapdump 暴露

Spring Boot Actuator 的 heapdump endpoint 是官方存在的诊断能力；如果生产环境暴露且访问控制不足，可能泄露内存中的敏感信息。这个案例提醒：**诊断接口不是漏洞本身，错误暴露和缺少访问控制才是风险。**[^spring-actuator]

## 9. 入门练习：本地提权检查报告

在本地 Linux/Windows 靶机上做一次只读检查，输出：

```text
1. system-info.md：系统版本、内核/补丁、用户身份。
2. privilege-map.md：当前用户权限、组、sudo/特权。
3. writable-paths.md：可写服务、任务、脚本、目录。
4. cve-candidates.md：只列和版本匹配的 CVE。
5. secrets-evidence.md：只记录脱敏后的凭证线索。
6. conclusion.md：哪些路径成立，哪些被否定。
```

`cve-candidates.md` 模板：

```markdown
## CVE-XXXX-YYYY

- 组件：COMPONENT
- 当前版本：VERSION
- 影响版本：从 NVD/厂商公告摘录
- 补丁状态：installed / missing / unknown
- 本地证据：COMMAND_OUTPUT_PATH
- 风险：local privilege escalation / information disclosure
- 结论：observed / negated / needs-lab-proof
```

## 10. 防护检查清单

| 防护 | 说明 |
|---|---|
| 补丁管理 | 系统、内核、sudo、打印服务、Java 运行时都要纳入。 |
| 最小权限 | 服务账号不要给管理员/root。 |
| 文件 ACL | 服务文件、脚本、计划任务不可被普通用户写。 |
| 诊断端点访问控制 | heapdump、env、metrics 等生产环境严格限制。 |
| 凭证管理 | 不把密码写入脚本、history、配置明文。 |
| 日志审计 | 记录权限变更、sudo、服务修改、进程注入。 |
| EDR/基线 | 监控异常 dump、异常服务创建、敏感进程访问。 |

## 11. 常见误区

| 误区 | 为什么错 | 正确做法 |
|---|---|---|
| 看到老版本就说可提权 | 补丁可能已 backport | 看发行版补丁和厂商公告。 |
| 只找 CVE | 配置错误更常见 | CVE + 配置 + 凭证三条线并行。 |
| 生产上直接跑提权 EXP | 可能蓝屏、崩溃、破坏数据 | 先本地同版本复现，再申请窗口。 |
| heapdump 直接下载分析 | 文件大且含敏感数据 | 先确认暴露，必要时脱敏取证。 |
| 不记录当前权限 | 无法证明“提升” | 复现前后都记录身份和权限。 |
