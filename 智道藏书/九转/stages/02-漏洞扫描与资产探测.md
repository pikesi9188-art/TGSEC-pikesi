# 02. 漏洞扫描 & 资产探测

> 写作原则：本章按图中第 2 个板块整理。工具名来自图片；工具功能只采用官方文档、GitHub README、CVE/NVD、CISA、厂商公告等可核验来源。没有可靠来源的工具不硬编，只标“待核验”。本章用于授权靶场、CTF、本地样本与企业自查。

## 1. 这个板块到底在干什么？

大白话：第 1 章“信息收集”解决的是“目标有哪些门”；第 2 章“漏洞扫描 & 资产探测”解决的是：**这些门后面用的是什么锁？锁是不是旧型号？有没有公开已知问题？**

漏洞扫描不是“点一下就等于漏洞成立”。更准确的流程是：

```text
资产确认 → 指纹识别 → 版本/配置判断 → 漏洞假设 → 低风险验证 → 人工复核 → 证据归档
```

事实依据：

- NIST SP 800-115 把端口扫描、漏洞扫描、渗透测试都放在技术安全测试方法中，并强调扫描结果需要分析与验证。[^nist-800-115]
- OWASP WSTG 强调信息收集后要识别应用入口点、框架、配置和攻击面，不能只依赖单一自动化工具。[^owasp-wstg-info]
- CISA Known Exploited Vulnerabilities Catalog 是公开已被利用漏洞目录，适合用来给扫描结果排序：KEV 里的漏洞通常比普通 CVE 更需要优先处理。[^cisa-kev]

## 3. 综合通用扫描器：先做“体检”，不要把体检当诊断书

### 3.1 可核验工具事实

| 工具 | 可核验事实 | 来源 |
|---|---|---|
| xray | 长亭科技 xray 项目定位为 Web 漏洞扫描器，支持被动代理、主动扫描、插件等能力。 | [chaitin/xray](https://github.com/chaitin/xray) |
| afrog | afrog 是 Go 语言编写的安全工具，项目说明其用于漏洞扫描，基于 POC 模板。 | [zan8in/afrog](https://github.com/zan8in/afrog) |
| kscan | kscan 项目说明其可进行资产测绘、端口扫描、服务识别等。 | [lcvvvv/kscan](https://github.com/lcvvvv/kscan) |
| fscan | fscan 项目说明其是内网综合扫描工具，包含主机存活、端口扫描、常见服务爆破、漏洞检测等。 | [shadow1ng/fscan](https://github.com/shadow1ng/fscan) |
| tscanplus | GitHub 上存在 tscanplus 相关项目，常见描述为综合性网络安全检测工具；不同分发源版本较多，使用前要核对来源和哈希。 | [TideSec/TscanPlus](https://github.com/TideSec/TscanPlus) |
| Rscan | 同名工具较多，本轮没有找到能唯一对应图片名称的稳定官方来源。 | 待核验 |
| ppsscan | 同名/近名项目分散，本轮没有找到稳定官方来源。 | 待核验 |
| Xscan | X-Scan 是较早期的综合扫描器名称，现代环境中版本来源复杂；本章不对具体版本功能做断言。 | 待核验 |

### 3.2 大白话理解

综合扫描器像“体检套餐”：

- 能快速发现哪些端口开着；
- 能猜测服务和框架；
- 能匹配一批已知漏洞模板；
- 能给后续人工验证排优先级。

但它也有明显局限：

- **误报**：指纹像，并不代表漏洞真的存在。
- **漏报**：模板没有覆盖，或者目标环境有 WAF/CDN/自定义改造。
- **风险**：某些 POC 会触发写文件、命令执行、反连或业务异常。

### 3.3 新手建议流程

```text
1. 输入资产表：只放已授权、已验证存活的 HOST/IP。
2. 先跑低风险模式：端口、标题、指纹、版本，不跑破坏性 POC。
3. 对命中的 CVE 做人工核验：版本、组件、配置、补丁状态。
4. 高危漏洞先查 CISA KEV/NVD/厂商公告。
5. 每个结论保留：扫描命令、工具版本、模板版本、原始输出、人工复核证据。
```

资产扫描记录模板：

| 资产 | 工具 | 版本/模板 | 发现 | 置信度 | 复核证据 | 结论 |
|---|---|---|---|---|---|---|
| `https://HOST` | xray | `VERSION` | `CVE-XXXX-YYYY` | medium | `raw/xray-HOST.json` | 待人工确认 |

## 4. 专项漏洞探测：一次只证明一个问题

### 4.1 Seay-Svn：SVN 泄露

大白话：有些网站历史上会把 `.svn/` 目录误部署到 Web 根目录。`.svn` 是 Subversion 的工作副本元数据目录，可能暴露源代码路径、历史文件和敏感配置。Subversion 官方文档说明工作副本会包含管理目录，用于记录版本控制元数据。[^svn-book]

入门判断：

```text
发现 /.svn/entries、/.svn/wc.db、/.svn/pristine/ 这类路径 → 怀疑 SVN 泄露
```

记录方式：

```text
URL: https://HOST/.svn/entries
状态码: STATUS
证据: artifacts/02-scan/svn-HOST.txt
风险: 可能泄露源码、数据库配置、接口路径、历史文件名
```

图中 `Seay-Svn`：该名称常见于 SVN 源码泄露检查/利用辅助工具，但本轮没有找到稳定官方源；本章只讲 SVN 泄露原理，不编具体工具功能。

### 4.2 supersql：SQL 注入专项

SQL 注入的事实基础来自 OWASP：SQL Injection 是把不受信任输入拼进 SQL 查询，导致攻击者影响数据库查询逻辑。[^owasp-sqli]

新手大白话：如果网站把用户输入直接拼进 SQL，就像把访客写的纸条直接塞给数据库执行。

图中 `supersql`：同名项目较多，本轮没有找到能唯一对应图片名称的稳定官方来源；本章不写具体工具断言。

学习重点：

| 看点 | 解释 |
|---|---|
| 参数位置 | GET、POST、JSON、Header、Cookie 都可能是输入点。 |
| 响应差异 | 报错、长度、状态码、时间延迟、排序变化。 |
| 数据库类型 | MySQL、PostgreSQL、Oracle、SQL Server 语法不同。 |
| 证据等级 | 报错回显 < 布尔差异 < 时间差异 < 授权环境下的数据验证。 |

### 4.3 PcapDecrypt：流量包解密/探测

大白话：抓包文件 `.pcap/.pcapng` 里是网络流量。如果有 TLS 密钥日志、会话密钥、私钥或弱加密协议材料，就可能还原请求内容。Wireshark 官方文档说明可以使用 TLS key log file 解密 TLS 流量。[^wireshark-tls]

图中 `PcapDecrypt`：本轮未找到稳定官方来源；本章只讲“流量包解密需要密钥材料或协议条件”，不编工具功能。

新手注意：

- HTTPS 不是“永远不可看”，有合法密钥日志时可在本地还原。
- 没有密钥材料时，不要把“看不到内容”误判为“没有敏感数据”。
- 保存 pcap 时要注意隐私和 Token，放到 `secrets/` 或受控目录。

## 5. Java 反序列化与框架漏洞

### 5.1 先理解“反序列化”

大白话：序列化就是把对象打包成一串字节；反序列化就是把字节恢复成对象。危险点在于：**如果应用反序列化了攻击者可控的数据，并且类路径里存在危险 gadget，就可能触发非预期代码路径。**

OWASP 对反序列化风险有专门说明：不可信数据反序列化可能导致远程代码执行、认证绕过或权限提升。[^owasp-deserialization]

### 5.2 图中关键词事实表

| 关键词 | 事实依据 | 入门者理解 |
|---|---|---|
| FastJson | Fastjson 历史上多次出现反序列化/AutoType 相关安全问题；以具体 CVE/版本为准。 | 看到 Fastjson 不能直接判漏洞，要看版本、AutoType、黑白名单配置。 |
| Jackson | Jackson databind 历史上有多态反序列化相关 CVE；NVD 中有多个 jackson-databind CVE。 | 关键看是否启用危险多态类型处理、版本是否老旧。 |
| jndi | Log4Shell（CVE-2021-44228）与 Log4j JNDI lookup 相关；CISA 有专题说明。 | JNDI 本身是 Java 命名目录服务机制，漏洞来自危险调用链和配置。 |
| shiro | Apache Shiro CVE-2016-4437 与 rememberMe cookie 加密密钥相关。 | 固定/弱密钥会让 rememberMe 反序列化风险变高。 |
| struts2 | Apache Struts2 S2-045 / CVE-2017-5638 曾造成严重 RCE，Equifax 事件中未及时修补 Struts 漏洞是关键原因之一。 | 框架漏洞要看版本、插件、上传解析链路。 |
| yso | ysoserial 是公开的 Java 反序列化 payload 研究工具。 | 学习 gadget 链原理，不要把 payload 命中当作唯一证据。 |
| Gr33k | 本轮没有找到能唯一对应图片名称的稳定官方来源。 | 待核验。 |

相关来源：CISA Log4Shell 页面、NVD Shiro CVE-2016-4437、NVD Struts CVE-2017-5638、FTC Equifax 投诉、ysoserial GitHub。[^cisa-log4shell][^nvd-shiro-4437][^nvd-struts-5638][^ftc-equifax][^ysoserial]

### 5.3 Java 漏洞扫描怎么做才靠谱

```text
1. 指纹：确认 Java、框架、中间件、版本或错误页。
2. 配置：确认是否开启危险功能，例如 Shiro rememberMe、Struts 上传解析、Log4j 版本。
3. 条件：确认是否存在可控输入点进入对应代码路径。
4. 低风险验证：优先用无破坏的 DNS/log 证据或版本证据。
5. 人工复核：把工具输出和厂商公告条件逐条对照。
```

不要这样写报告：

```text
工具显示存在 Struts2，已确认漏洞。
```

应该这样写：

```text
目标 /upload.action 响应头和错误页符合 Struts2；版本线索指向受影响范围；
低风险验证请求触发可控错误差异；仍需在授权窗口进一步确认补丁状态。
```

## 6. CMS / 框架扫描

### 6.1 ThinkPHP

ThinkPHP 是 PHP 框架。NVD 记录过 ThinkPHP/相关项目的远程代码执行 CVE，例如 CVE-2018-20062；Akamai 也公开分析过攻击者继续利用老 ThinkPHP CVE 投放 WebShell 的活动。[^nvd-thinkphp-20062][^akamai-thinkphp]

新手判断：

- URL 路由、报错信息、静态资源路径可能暴露 ThinkPHP 特征；
- 不能只凭 `X-Powered-By` 或页面标题就下结论；
- 扫描结果要回到具体版本、具体 CVE、具体请求路径。

### 6.2 RuoYi / 若依

若依（RuoYi）是公开的后台管理系统/快速开发平台，官方仓库和文档可查。图中写的是 `RuoYi-All-master`，更像工具包/POC 集合名称；本轮不对这个具体包做功能断言。[^ruoyi]

新手关注点：

| 看点 | 解释 |
|---|---|
| 登录页版权/静态路径 | 可能识别 RuoYi，但可被修改。 |
| 后端框架 | 常见 Java/Spring Boot 生态，需要看依赖版本。 |
| 管理后台 | 重点检查认证、权限、默认配置、历史漏洞。 |
| 代码分支 | 开源项目被二开后，漏洞条件可能改变。 |

## 7. 中间件服务扫描

### 7.1 JBoss

Red Hat CVE 页面记录了 CVE-2017-12149：JBoss HTTP Invoker 的 ReadOnlyAccessFilter 对可反序列化类限制不足，可能导致远程代码执行。[^redhat-jboss-12149]

### 7.2 Jenkins

Jenkins 官方安全公告记录过严重远程代码执行漏洞，例如 SECURITY-218 / CVE-2017-1000353。[^jenkins-2017-1000353]

### 7.3 WebLogic

Oracle WebLogic 历史上多次出现反序列化/RCE 类漏洞；CISA 和 Oracle 官方公告可作为优先事实源。[^oracle-cpu][^cisa-weblogic]

### 7.4 XXL-JOB

XXL-JOB 是开源分布式任务调度平台。GitHub Issues 和公开模板中能看到与默认 token、SSRF、命令执行风险相关的讨论；具体结论必须绑定版本、配置和补丁状态。[^xxljob][^xxljob-default-token]

### 7.5 Docker

Docker 官方文档强调 Docker daemon socket/远程 API 等同高权限控制面，需要保护访问权限。暴露未授权 Docker API 可能导致容器、镜像、主机挂载等严重风险。[^docker-daemon]

中间件扫描最小记录：

```text
service: Jenkins
url: https://HOST:PORT/
version_evidence: 页面 footer / header / error page / authenticated about page
cve_candidate: CVE-XXXX-YYYY
vendor_advisory: LINK
scanner_output: artifacts/02-scan/jenkins-HOST.json
manual_result: observed / negated / needs-auth
```

## 8. 设备与虚拟化平台

### 8.1 vCenter

VMware 官方公告 VMSA-2021-0002 记录了 vCenter Server 插件相关漏洞 CVE-2021-21972，属于严重漏洞。[^vmware-21972]

### 8.2 Hikvision

海康威视官方安全公告和 NVD 都记录了 CVE-2021-36260：部分 Hikvision 产品 Web server 中的命令注入问题。[^hikvision-36260][^nvd-hikvision-36260]

### 8.3 hvvoaexploit

图中 `hvvoaexploit` 更像某 OA 漏洞利用集合/工具名，本轮没有找到稳定官方来源；本章不对其功能做断言。OA 类系统扫描应以厂商公告、CVE、版本号和补丁说明为准。

设备/虚拟化平台的入门注意点：

- 设备类漏洞常常影响摄像头、NVR、网关、虚拟化控制面，权限很高；
- 不能只扫 Web 标题，要确认型号、固件版本、暴露接口；
- 优先引用厂商公告和 NVD；
- 检测动作必须低风险，避免重启设备或影响生产。

## 9. 真实案例

### 案例 1：Equifax 与 Apache Struts

FTC 对 Equifax 的材料说明，Equifax 未及时修补 Apache Struts 漏洞，攻击者随后利用该漏洞获取敏感数据。这个案例说明：**漏洞扫描发现高危 CVE 后，最重要的是补丁闭环，不是只把报告发出去。**[^ftc-equifax]

### 案例 2：Log4Shell

CISA 为 Log4Shell（CVE-2021-44228）建立专题页面并持续更新建议。这个案例说明：**Java 生态漏洞经常不只看一个应用，还要排查依赖、间接依赖、打包组件和历史服务。**[^cisa-log4shell]

### 案例 3：Hikvision CVE-2021-36260

NVD 和海康威视公告记录了部分产品 Web server 命令注入漏洞。这个案例说明：**设备类资产也属于攻击面，固件版本、补丁状态和暴露面同样要进资产表。**[^hikvision-36260][^nvd-hikvision-36260]

### 案例 4：Docker daemon socket 风险

Docker 官方明确要求保护 daemon socket，因为它控制容器与主机相关高权限能力。这个案例说明：**中间件和管理 API 的“暴露”本身就可能是高危配置问题。**[^docker-daemon]

## 10. 入门练习：把扫描结果变成证据

对本地靶场 `HOST` 做一轮不破坏业务的漏洞扫描整理：

```text
1. assets.csv：从第 1 章继承资产表。
2. fingerprints.csv：记录服务、版本、标题、框架证据。
3. scanner-raw/：保存 xray/afrog/kscan/fscan 等原始输出。
4. cve-candidates.md：只记录能匹配到厂商公告/NVD/CISA 的候选漏洞。
5. manual-review.md：逐条写“为什么认为存在/为什么否定”。
```

`manual-review.md` 模板：

```markdown
## CVE-XXXX-YYYY on https://HOST

- 来源：TOOL 输出 / 手工发现
- 组件：COMPONENT VERSION
- 厂商公告：LINK
- 影响条件：官方公告中的条件列表
- 本地证据：raw/xxx.txt、img/xxx.png
- 低风险验证：REQUEST_SUMMARY
- 结论：observed / negated / needs-auth / out-of-scope
- 下一步：PATCH / further-test / monitor
```

## 11. 常见误区

| 误区 | 为什么错 | 正确做法 |
|---|---|---|
| 扫描器报高危就直接算漏洞 | 模板可能误报，条件可能不满足 | 对照 CVE、版本、配置、请求路径人工复核。 |
| 一上来跑所有 POC | 可能影响业务或产生脏数据 | 先指纹和低风险探测，再申请验证窗口。 |
| 只看 CVSS 分数 | CVSS 高不等于当前资产可利用 | 结合 CISA KEV、暴露面、是否有补丁、业务重要性。 |
| 不记录工具版本 | 复现不了，也解释不了误报 | 保存工具版本、模板版本、命令和原始输出。 |
| 只扫 Web | 中间件、CI/CD、Docker、vCenter、设备也可能是入口 | 资产表按 Web、服务、设备、云资源分组。 |
